**Goal.** When an unranked match is over, each watcher on `/ws/watch` is still sent every delayed view it is owed, oldest first, through the view that shows the result. **Steps.**

1. **Why the close happens outside the lock (read this first).** `spectate_flush` runs while the actor's lock is held (`&mut Core`). `Socket::close` (`ws_server.rs:189`) runs the socket's close handler right away, and a watcher's handler calls `detach_watcher`, which takes the same lock. Closing a socket inside `spectate_flush` would deadlock. So, as `revoke_watchers` and `spectate_close` already do: under the lock, take the watchers out of the list and push the count; after the lock is released, close their sockets. Their close handlers then find nothing to remove.

   /// caller to close with `close_finished_watchers` once it has let go of the lock. Called after each
   /// `spectate_flush` that can send that view: the wait's and an attach's. `spectate_record_in`'s

   #[must_use]
   fn spectate_let_go_finished(&self, core: &mut Core) -> Vec<Watcher> {
       if !core.finished || core.spectate.closed {
           return Vec::new();
       }
       let records = &core.spectate.records;
       let (done, kept): (Vec<Watcher>, Vec<Watcher>) = std::mem::take(&mut core.spectate.watchers)
           .into_iter()
           .partition(|watcher| {
               records[watcher.home]
                   .back()
                   .is_some_and(|last| watcher.sent == Some(last.seq))
           });
       core.spectate.watchers = kept;
       if !done.is_empty() && !core.stopped {
           tracing::info!(event = "match.watcher.finished", matchId = %self.match_id_str(), finished = done.len(), watchers = core.spectate.watchers.len());

       }
       done
   }
