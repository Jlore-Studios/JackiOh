## Risks

- **The submit flow.** Only the form's `onKeyDown` is removed and `onSubmit` is untouched. Test 4 sends a challenge end to end, and e2e `42-together.cy.ts` uses the same testids.
- **The opener can vanish.** If the friend goes in-game or offline while the dialog is open, polling unmounts their Challenge button, and the `isConnected` check then leaves the focus alone. `closeChallenge` clears the ref, so a send that resolves after an Escape doesn't pull the focus back later.
- **The key listener re-subscribes.** It is window-capture and its deps are `[onClose]`, which is a new function on every `TogetherRoute` render. Re-subscribing is harmless. Do not move the focus-on-open into that effect, or it would refocus on every poll. Escape's `stopPropagation` keeps an open `ChatPanel` from also closing.
- **Hidden information and determinism.** Neither is touched: this is the client only, with no engine change.

Decisions this plan made that the issue left open, with the rejected alternatives:

The plan copies `ConfirmConcede.tsx`'s window handler instead.
