## Risks

- **Thread-local test state.** `register_shipped` sets a thread-local override, so every test that calls `carry_played_on` ends with `clear_overrides()`, as `game_records.rs` does. Call `carry_played_on()` after `test_app()` and before `finished_match`.
- **Check order (a decision).** The guard runs after the double, finished and series checks, so a live match still answers `match_not_finished` and a series game still answers `series_game`. Rejected alternative: putting the guard first, which would answer a series game on an old catalog with `update_required` instead of the series screen's message.
- **Status route (a decision).** `GET /api/matches/:matchId/rematch` stays 200, so the panel still renders and the offer's refusal shows the message. Rejected alternative: refusing the status too, which would leave the panel nothing to show.
- **A refused offer leaves no trace (a decision).**
  - The guard returns before `note_rematch` (the R1442 signals) and before `on_rematch_offer`, as the other refusals do. So a ladder bot is never told about a refused offer.
  - A bot's own planned offer after a deploy logs `bot.rematch.failed` at warn level (`match_actor.rs:1310`). The issue already names this cost.
- **Replay, determinism and hidden information.** None of them is touched. The refusal comes before anything is written, and the details name only catalog versions, which `GET /api/catalog` already serves.
- **No patch fragment.** No card plays differently, so `crates/cards/patches/pending/` gets nothing, and `rust (classify)` should label the PR `kind:app`. If `origin/main` can be fetched, `cargo jackioh classify --base origin/main --claims` confirms it.
- **Formatting.** The test names are long: let `cargo fmt` place the `{` (the file already has `()\n     {` cases). Do not reformat other code.
