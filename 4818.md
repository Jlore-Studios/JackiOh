## Risks

- **Double read on Try again.** After a failed reread with no kept answer, the error view replaces the list and Try again remounts `QuestsList`. The old due time is still in the past, so `onArrived` fires once more on mount and supersedes the first read (the first is cancelled by the hook's `canceled` flag). It is not a loop: a second failure shows the alert again and nothing re-triggers. The landing bookmark already behaves this way. The issue says to keep `reread` and the effect's guard, so do not "fix" it here, and do not assert an exact count after Try again.
- **Clock skew.** If the client's clock is ahead and the server still answers the same `nextDueAt`, the effect's deps are unchanged, so no second read fires and the page shows no sentence. This matches the landing, and the server still decides when a quest arrives (rule 7).
- **Fake-timer hangs.** `waitFor` and `findBy*` poll with `setInterval`, which these tests fake. Use only `await act(async () => {})` for reads, as the landing test does.

- **Stale-cache leakage.** Test 3 calls `rememberRead`, and the suite's setup empties the cache after each test. Do not reuse its `held` object in the other tests.
