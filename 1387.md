## Goal

Every fuzzed game — the 1v1 gate (`crates/tools/src/fuzz.rs`), the handicapped wave (same file), and Duos (`crates/tools/src/duos_fuzz.rs`) — crosses exactly one deterministic serialization checkpoint per game, preferring a state with paused work (open `pending`, non-empty `work`, or an owed mulligan). The checkpoint serializes the mid-game state to JSON, parses it back, requires identical hashes, then continues play from the restored state so the existing invariant, termination, growth, and final replay checks cover the restored game. A focused engine test proves a tampered round trip is detected, and checkpoint cost is timed, bounded, and reported.
