# Plan (opus, strong)

## Goal

The seven spend routes take an optional `Idempotency-Key` header holding a UUID. They are `POST /api/packs/buy`, `/api/packs/open`, `/api/tokens/redeem-card`, `/api/tokens/redeem-cosmetic`, `/api/cosmetic-packs/open` and `/api/cosmetic-packs/chase` (every spending POST under `economy/`), plus `/api/codes/redeem`.

- **Under the account's economy lock:** a known (account, key) with the same route and body hash replays the stored status and body. A known key with another route or body is refused with 422 `idempotency_key_reused`. An unknown key runs the spend and stores its answer in the spend's own transaction.
- **No key:** the request behaves as today.
- **Retention:** keys are kept `IDEMPOTENCY_KEY_TTL_HOURS` = 24, then swept.
- **Store:** migration 0065 with RLS for the server only, the fake store, a contract case and SQL cases.
- **Ruling:** R2124000.
- **Client:** `net/api.ts` reuses a press's key on its retries, and a new press gets a new key.
