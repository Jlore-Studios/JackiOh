# Plan (sonnet, medium)

## Goal

A redeploy of the same commit with changed settings (a secret, a var) restarts a running game server. The Worker keeps a SHA-256 fingerprint of `containerEnv(settings)` in the `Server` object's storage. On the first request after a deploy, a server on the deployed commit whose stored fingerprint differs or is absent is retired on the existing path (SIGTERM, `RETIRE_WAIT_MS`, then destroy), and the request starts the new one. A server with the same fingerprint is left alone. A storage fault never restarts a live site. The edge README and `docs/architecture.md` say so, and "or wait for the next sleep" is removed. No ruling and no spec change: the Worker's operation is operational, not a spec matter.
