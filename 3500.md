## Risks

- **Permit lifetime.** The permit must move into the blocking closure, not the async fn. Otherwise a dropped request frees the permit while the fold still runs.
- **Dropped first request.** If the first request of a match is dropped mid-fold, its result is lost and the next open folds again. It still waits for the permit, so it is bounded. Note this in R3500000.
- **Flight cleanup.** `strong_count <= 2` is only valid because clones are taken under the `flights` lock. Keep that lock's scope tight, with no `.await` while it is held. Clippy's `await_holding_lock` would flag it.
- **Unavoidable behaviour change.** A claim in flight now holds a seed slot. A deliberate burst is refused as 409 (the message is unchanged), and an honest player's single claim is unaffected.
- **Postgres.** The count is an edit to a query, so the Docker suite proves it. The fake and Postgres definitions must match: `claim is not null and settled_at is null`.
- **Sweep skip.** The skip is per process. During a deploy handover two processes could still both settle a claim, and `economy_practice_seed_settle`'s "only where unmarked" already makes the pay land once.
- **Duos wiring.** The Duos permit use is covered by the shared `open` tests and the existing Duos replay tests. Review it by reading the diff.
- **Contracts.** The server README's route table is the contract and must change with the behaviour. Cached pages, the per-account `REPLAY_REQUESTS_PER_MINUTE` limit and seat filtering (CLAUDE.md rule 7) are untouched.
