## Risks

- **Spurious memory errors.** The cap counts the VM's live bytes, garbage included. 64 MiB is about 25 times the peak measured with 370 cached chunks, and the collection threshold (32 MiB) is never reached in normal play. Do not lower either value.
- **Determinism (L8).** A collection is invisible to scripts except through weak tables, a hole the README already lists. A hook near the cap that catches the error with `pcall` hangs on thread history; step 10 documents this. Cards never come near the cap, and the fuzz and replay gates are not affected: nothing depends on `crates/luau` yet.
- **Purity (rule 4).** `set_memory_limit`, `used_memory` and `gc_collect` are mlua methods on the VM. There is no new dependency, clock or static.
- **Cost.** `used_memory()` is a field read on every outermost call. `gc_collect()` runs only above 32 MiB and takes about 8 ms with 64 MiB of garbage.
- **Merge with `bot/issue-442`.** That branch leaves `sandbox.rs` and `BudgetGuard::run` as on main and appends to `config.rs` after `LUAU_VALUE_NODES`, which is why the constants go after `LUAU_HOOK_DEPTH`. Its `host.rs` additions sit near line 608, below these tests. Don't touch `lib.rs` or the README's Tests paragraph, both of which it edits.

## Open questions

Nothing blocks the build. Decisions made, with the alternative rejected for each:

- **A per-VM cap, not per call.** As the issue proposes. Per-call accounting would need allocator hooks that mlua 0.12.2 does not expose.
- **64 MiB.** Generous against the measured 2.5 MB peak. On Render's free 512 MB instance, several AI threads (`crates/server/src/bots/seat.rs` uses `spawn_blocking`) each hold a VM, so the cap was not set higher. A person may tune it.
- **Collect at the start of an outermost call, above half the cap.** Rejected: collecting only after a memory error (it misses a nested hook's panic and a fill caught with `pcall`), and collecting before every call (cost on every hook).
- **`pcall` still catches a memory error.** Documented, not closed. Rejected: wrapping `pcall` in Rust to re-raise memory errors, which would change the nested-panic behaviour that `pcall_does_not_catch_a_nested_hooks_failure` pins.
- **The error ends "(L5)".** This matches the sandbox's other caps; the constants' docs cite #843.
