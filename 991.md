**Decisions to record**, each with the alternative rejected:
- **The ring is an `outline`.** A third box-shadow colour was rejected: the first box-shadow layer is the glow contract, and selection and the breathing keyframes own box-shadow too.
- **The ring marks the union of every preview value's `ids`.** Radiant #44's "all permanents" already contains "only your opponent's". A ring per value was rejected because there is no control to choose a value.

## Risks

- **Hidden information:** the ring can only match `card-<id>` testids, which backs never have. The engine strips unreadable ids (R1447). Test 4 pins both.
- **A stale hover:** a hand card that leaves under the pointer may get no `pointerleave`. `countedTestids` ignores an id no longer in the hand, so nothing rings. Only that same instance coming back to the hand would ring until the next hover. This is acceptable; don't add an effect for it.
- **The glow contract:** never touch the box-shadow rules. `.card[data-unrevealed]`'s dashed outline (facedown.css) is replaced by the ring while the ring shows, by import order. That is intended.
