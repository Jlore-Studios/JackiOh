## Goal

A `#[unsafe(no_mangle)]` export in `crates/wasm/c/src/lib.rs` named like a libm or host function (`log`, `round`) must fail the C module's build, and the error must name the function. #4273's `grep signature_mismatch:` reads a name that #4283's `strip=symbols` removed, so it can no longer fire. It is replaced by two parts:
1. `deny(linker_messages)` in `lib.rs`, which turns rust-lld's `function signature mismatch: <name>` warning into a failed link.
2. A self-test in `scripts/build-wasm.sh` that builds a throwaway fixture under the module's profile and fails the script unless that fixture fails to link with `signature mismatch`.

I checked three things on the pinned toolchain (rustc 1.97.0):
- **Real module with the attribute:** it builds clean, with no linker message (cold, 2m26s here).
- **Real module with an extra export named `log`:** the link fails with `error: linker stderr: rust-lld: function signature mismatch: log`, exit 101, and the lint note points at the attribute.
- **The self-test shell block:** it passes with the `deny` line. It fails with a `warn` line, because that fixture links clean.

**The fixture needs two crates.** A single crate that defines `log` and calls `.ln()` itself links clean, because the call and the definition share a compilation unit. The mismatch needs a dependency crate calling `f64::ln` plus a cdylib exporting `log`. The fixture is therefore about 25 lines across two crates, not ten.
