     pub fn gate_needed_with_rate(matchup: Matchup, games: i32, rate: f64) -> i32 {

## Risks

- **Flaky or red gate after raising floors:** Higher `measured_rate` raises `gate_needed` floors for daily runs and smoke checks. Avoided by: only raising rates that are statistically demonstrated on 300+ fresh deals, capping at brief rates, and verifying `cargo jackioh gate` smoke passes with head commit.
- **Lower measured rate without sign-off:** §9.9 explicitly prohibits lowering `measured_rate` without user sign-off. Avoided by: retaining current `measured_rate` for any matchup where the new measurement is lower, and explicitly documenting this in the ruling and PR notes.
- **Seed contamination:** Tuning measurements must never reuse gate seeds, which would invalidate future test independence. Avoided by: strictly using `AI_TUNING_SERIES` (`"tune"`) and asserting `!seed.contains("gate:v3")`.
- **Determinism under multithreading:** Parallel game execution across Rayon threads could theoretically sort games non-deterministically if not indexed. Avoided by: mapping indexed game numbers with `par_iter()` and flattening back into original order, identical to `play_gate_with`.
