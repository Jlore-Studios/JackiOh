## Risks

- **`popstate` listener order.** The guard check must live in each `subscribe` wrapper and run before `onChange`. Browsers run microtasks between listeners, so a separate listener could let React render the next screen, unmounting the creator, before the guard runs. Later subscribers see the restored address and change nothing.
- **Held loop.** The `popstate` leave must clear `leaveGuard` before calling `history.back()`. Otherwise the next `popstate` is held again.
- **`navigate` now returns `boolean`.** Never return it from a `useEffect` or `act` callback. The tests that mock it with `vi.fn()` (`play.test.tsx`, `qa-v020.test.tsx`) never click the toast's Accept, so they are unaffected.
- **The gate's redirect** (`Gated`, `main.tsx`) unmounts the creator before its effect navigates, so the guard is already released by then.
- **Decisions to record in the PR:**
  - Back goes through `navigate`: one path, so the note is never raised twice.
  - When several moves are held, the latest one is what Discard makes.
  - A held `popstate` restores the address with `pushState`, and Discard uses `history.back()`. Rejected: `navigate(left, { replace: true })`, which leaves a duplicate history entry.
  - A match the player kept away from is offered again by the menus' `LiveGameBanner`, not by a new banner on the creator.
  - Accept marks a challenge answered only once the move went. Rejected: marking it at once, which loses the challenge in this tab, because no other screen lists incoming challenges.
  - After Discard on a held Accept, the toast still lists the challenge on `/play` until the join closes it.
