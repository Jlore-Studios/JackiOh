## 6. Risks
- **Test execution order / synchronous assumptions:** Many existing audio tests assume tables are immediately available. Mitigated by exporting `seedSoundTables(tables?: SoundTables)` in `fakeAudio.ts` and awaiting `loadSoundTables()` in test file setup blocks (`ui.test.tsx`, `CardDetail.test.tsx`, `NotFoundPlay.test.tsx`).
- **Memory during typecheck:** `tsc` can hit Node's default heap limit; running with `NODE_OPTIONS="--max-old-space-size=4096"` prevents OOM.
- **Accidental static imports of `json5`:** If `parseCardAudioText` remained in `voiceData.ts`, importing pure functions like `voiceKey` would pull `json5` into the entry bundle. Moving parser functions into `soundTables.ts` guarantees `voiceData.ts` and `engine.ts` stay completely clean of `json5`.
- **Hidden information & client purity:** Audio continues to read only `PlayerView` and public catalog facts; no rules or engine state are altered.
