````markdown
// Every `@keyframes` block of a stylesheet, from its name to its closing brace.
function keyframes(css: string): string[] {
  const blocks: string[] = [];
  for (let at = css.indexOf("@keyframes"); at !== -1; at = css.indexOf("@keyframes", at + 1)) {
    let depth = 0;
    let end = css.indexOf("{", at);
    for (; end < css.length; end += 1) {
      if (css[end] === "{") depth += 1;
      if (css[end] === "}") depth -= 1;
      if (depth === 0) break;
    }
    blocks.push(css.slice(at, end + 1));
  }
  return blocks;
}
```
````

````markdown
## Risks

- **Whole-page restyle on each press and release.** Changing a custom property on the root makes the browser recompute every element's style on mousedown and mouseup. That is one recalculation each, a few milliseconds on the board. Accept it, and do not scope the swap per element.
- **Drag and disabled controls.** The drag cursor (`drag.css:60`, `!important` grab) and every `not-allowed` or `default` rule never read `--cursor-glove-point`, so they are unaffected.
- **Every pressed state, not only the clicked element.** While the button is held, other pointer elements under the mouse also show the press, as the issue's "shown while the button is held" describes. Chrome also matches `:active` for the right button, and for Space held on a focused button while the mouse rests on a pointer element. All of these are harmless.
- **Firefox can skip the swap.** Firefox does not apply `:active` when a `mousedown`'s default is prevented. Where drag code prevents it, Firefox shows the pointing glove throughout, which is no worse than today.
- **First press on a first visit.** The press SVG loads on its first use, so that press may briefly show the system hand.
- **The SVG test strings are exact.** Step 7's hotspot test matches Step 1's SVG text and Step 2's indentation character for character. Copy both verbatim. Do not reformat the CSS block or the SVG.
- **No engine, replay, hidden information or wire change.**

## Open questions

- **The drawing is a judgment call.** It is an 8% shrink toward the tip, a 2.5-unit shorter finger and a crease. A person may retune it in `glove-press.svg`, keeping the tip at (14.4, 1.6) under the same turn, and update the hotspot test's two strings to match.
- **"Tap downward" is read as tapping into the table.** The hand shrinks toward the pinned fingertip, as if moving away from the viewer. Moving the hand lower on screen with the tip pinned is impossible without moving the hotspot.
- **The issue allows "one or more" press frames; this delivers one.** A multi-frame tap would be a separate polish issue.
- **Difficulty:** medium stands. The change is visual polish judged partly by eye, though only three files in one app change.
````
