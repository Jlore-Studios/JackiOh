**[[R4403000]] A settings write keeps out a cosmetic pick the account does not own instead of refusing the whole write (issue #4403, 2026-11-21)**: a shared device could strand an account's settings saves for good: the device's stores are not per account, so by [[R634]] the first account's picks go up with the second account's first save, and every later save resent the same unowned pick and met the same 400 [[R1834001]]. `PUT /api/settings` now leaves out a `cosmetics` pick refused as `NotOwned`, keeping the stored pick for that key when the account's held group has one, and merges everything else as [[R634]] says; the answer is the account's copy, and the server logs `settings.pick_refused` with the profile and the keys. A pick of another kind, one not offered, and a value that is not text still refuse the whole write with 400 and write nothing. It amends [[R1834001]] and edits [[§9.1]].
