**[[R3507000]] The account screen names the linked Roblox account: its username, its display name when that differs and its headshot, from the identity's `identity_data` (issue #3507, 2026-11-09)**: `/account`'s Roblox row said only that Roblox was linked, never which account. The identity list the screen already reads (`GET /auth/v1/user`) holds Roblox's `profile`-scope claims in each identity's `identity_data`, so the row now reads `preferred_username` as `@username` (with `name`, else `nickname`, before it when it differs) and `picture` as a small headshot, each only when a non-empty string and the picture only as an `https:` URL on Roblox's image host `tr.rbxcdn.com`: display only, deciding nothing, and for Roblox's identity alone, so no other provider's row changes. A row with no username stays as it was, a row with a username but no usable picture shows the username alone, and an image that fails to load is removed instead of leaving a broken one. The CSP's `img-src` gains that one host, no wildcard, the only way the image can load; the host is the one Roblox's documentation gives for the claim and was not checked against a staging account's `identity_data`, so a different one shows the username alone until `ROBLOX_AVATAR_IMAGE_HOST`, `_headers` and the tests are changed together.
