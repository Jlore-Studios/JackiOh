**[[R2630000]] and [[R2630001]] open a gated screen without waiting on what the page already knows (issue #2630, 2026-10-31)**: a launch-speed pass after a developer's write-up of cutting an app's cold start with three fixes (trust what the device has, show a saved snapshot at once, make requests in parallel) found two waits on every gated screen. Each screen's gate read `/api/auth/me` before showing anything, even a moment after the last screen read it, and a screen that calls the engine asked for the engine's module and its own code only once that read answered. [[R2630000]] opens a screen at once on the page's last answer, kept with the menus' ([[R2125000]]), for an active account that owes nothing, reads again behind it, and drops it on `announceAccountChange()`, so no redirect or prompt rests on it. [[R2630001]] starts the screen's code, and the engine's module for a screen that calls it, as the gate mounts, beside the account read. They edit [[§10.10]].
