**[[R3206000]] A kept answer inside READ_CACHE_FRESH_MS needs no read behind it, and a GET already out is shared (issue #3206, 2026-11-05)**: tracker #3201 asks for less compute and faster traffic, and R2125000 kept a menu's last answer only to draw it sooner: every screen, the gate (R2630000), the wallet and the landing still read again behind it on each move, and a read already out was sent again by the next screen that asked. Each kept answer now carries the time its read finished, and one younger than `READ_CACHE_FRESH_MS` (45 s, midway in the 30 to 60 s the issue allowed) is used with no read behind it; an older one behaves as R2125000 has it. A `GET` of one path and token asked while one is out shares it, on its own controller, so one caller's abort never aborts another's. A write epoch counts every spend that settles and every fold, drop or remembered answer (a read asked after it never joins an earlier one, and one that finished after it is not kept), a write that changes a kept read without carrying it drops it, a game's paid result drops the wallet, quests, tracks, packs, tokens and both ladders, a dev tool empties the cache and a quest falling due expires its answer. The gate skips its `/api/auth/me` read for a fresh answer of an active account that owes nothing, and the wallet pill reads through the same window; the server still enforces every gate (CLAUDE.md rule 7). A per-path window, `localStorage`, keeping the news or the friends list, a window a fold or a gate mount makes fresh again, sharing only inside `keptGet` and an epoch per path were rejected. It takes R3206000, the first number of issue #3206's block, amends [[R2125000]] and [[R2630000]], and edits [[§10.10]].
