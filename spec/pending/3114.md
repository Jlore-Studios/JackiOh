**[[R3114000]] A set is one row of the set table (issue #3114, 2026-11-05)**: at hundreds of cards a month a set lands every month or two, and each one was written into many places: `SetName`, the fixed-size `SHIPPED_SETS` and `CATALOG_SETS`, the cards build's folder list, the deck codes' offsets, `spec check`'s set names, the client's own `SetName` and `SHIPPED_SETS`, and the shadow ban's sets and ceilings. One table in `catalog_types.rs` now holds a row per set, its stage, id segment, abbreviation and shadow-ban share, and every one of those reads it, `SetName` generated from it so the wire and the client's type are unchanged. Rows are only appended, so every set keeps its place in the catalog order and the deck codes, and the table sits in the range the sweep workflow compares. Adding a set touches its row, its census entry and its scripts folder.

**[[R3114001]] A set's shadow-ban ceiling is its share of its cards (issue #3114, 2026-11-05)**: Stinkyscape's ceiling was `STINKYSCAPE_BAN_CEILING = 35`, 20% of the set's 175 non-token cards worked out by hand, which went stale as the set grew to 178. A ceiling is now the set's share in the set table times its non-token cards, rounded down: half for the Meditative sets and Training Grounds, a fifth for Stinkyscape, still 35. No ceiling changes.
