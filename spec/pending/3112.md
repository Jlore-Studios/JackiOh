**[[R3112000]] The learned evaluation reads what each card the seat can name is, beside its id, so a card the network never saw still counts (FEATURES_VERSION 3, issue #3112, 2026-11-05)**: the owner expects hundreds of new cards a month, and the network's sparse features named a card by its id alone, so a card it was not fitted on added nothing until the next refit. Each card the features name by id now also has keys for its type, printed cost, tags, keywords, printed attack and health (clamped at 10) and Radiant face, only where it already had an id key ([[R185]]). Printed numbers were taken over the current ones, which the dense features already hold; rarity and set were left out, since the issue did not list them; one key per stat was taken over one key for attack and health together, which would share less between cards.

**[[R3112001]] A network fitted on an older feature layout, to which this one only added sparse keys, reads it as it was fitted (FEATURES_READ_SINCE, issue #3112, 2026-11-05)**: a refit needs the learn lane's 100,000-game export, about 40 hours on the owner's PC, so the pull request that bumped `FEATURES_VERSION` to 3 shipped no new network. Generation 13, fitted on version 2, has no row for any key version 3 added, so it reads version 3 exactly as it was fitted and the AI plays as before; [[R1010000]]'s test now takes any version from `FEATURES_READ_SINCE` (2) on. Relabeling the shipped weights as version 3 was rejected, since it would misstate what they were fitted on; keeping version 2 was rejected, since the lane would then fold the new keys under the old version and its loader's guard against mixing versions would be lost.
