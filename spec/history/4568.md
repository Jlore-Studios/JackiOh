**[[R4568000]] A screen drawing the kept deck list redraws when this device's own deck write folds into it (issue #4568, 2026-11-23)**: the Decks tab read once, when it mounted, through a kept read that sends nothing while its answer is under `READ_CACHE_FRESH_MS` old ([[R3206000]]), and the read cache had no listener, so `syncDecks` folding a landed deletion or save into the kept decks never reached the tab: a deck deleted just before Back stayed on the tab, and a deck saved complete kept its short tile. The cache now holds one listener set per kept path (`subscribeKept`), heard once after every change to that path's answer, and the tab's decks read follows the kept decks while mounted, drawing each fold as its ready value with no remount and no new read; a forgotten answer leaves what is drawn alone, and the Cards and Progress tabs follow nothing. This amends [[R3206000]], whose window still stands: a screen may show what the server changed elsewhere for up to the window, but this device's own folded write is already in the tab's memory. Presentation only (CLAUDE.md rule 7): the kept answer stays the server's, a refused deletion coming back in its words ([[R2119000]]), at the cost of the deleted tile showing for one round trip ([[§10.10]]).
