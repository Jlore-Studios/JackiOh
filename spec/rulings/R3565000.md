S+ #129, #130 and #131 add a card "it has no Tribute condition", and S+ #138 and #139 add cards that, embiggened, "have Tribute 1 (2)". The spec has no way for an effect to change the Tribute X a card asks, so it is read as follows.

- **The rider.** `addRandomFromCatalog` takes a `tribute`: the Tribute X each card it adds has while it is in a hand or a deck, set in place of the printed X ([[§6.3]] Tribute X). "No Tribute condition" sets 0; "they have Tribute N" sets N. It goes on with the other hand prices once the card has reached the hand, so a card a full hand burns takes none ([[R78]]).
- **Where it is read.** `play_choices::tribute_cost_of` starts from the set X in place of the printed one, and a Nerf or a Buff ([[R386]]) and the card's Floats ([[R1841003]]) still move it from there. A set 0 is no number a Nerf can draw: a Tribute that is 0 is no numbered keyword on the card. The numbered keywords on the card list the set X as its printed one.
- **Where it ends.** It is kept in the card's `memory` in hand and deck, as a Float's reduction is, and a graveyard, an exile or the field's reset takes it ([[R78]], [[R215]]): played and bounced, the card asks its printed Tribute again.

Rejected: a `tuning.set` entry, which floors at 1 (R386) and is kept in every zone; and a new field on `CardInstance`, a change to the state's shape that a `memory` key does without.
