[[R835001]] absorbs a `hello` while one for the same seat and socket generation is still queued, and nothing else: the flag is cleared as the hello's task starts, so a client that sends again as soon as each answer arrives keeps one hello queued for ever. Each run resends the loadouts, the view with its legal actions, the clock, the portraits and every card's picks (a co-op seat's view, clock and teammate) under the lock both players' actions wait on, and `WS_OUTBOX_MAX_FRAMES` ([[R1441]]) bounds only a reader that falls behind. [[R2609000]] closed this for a watcher's socket; a seat's socket, on `/ws/match` and on `/ws/duos`, now stands behind the same interval ([[§9.8]]):

- **A later hello of one socket is answered at most once per `WATCH_HELLO_INTERVAL_MS` (1 s).** A hello that finds none queued but comes sooner than the interval after the last one answered for the same socket is dropped unanswered, with no error and the socket left open. One that comes at or after the interval is answered and starts the next. A hello absorbed by a queued one is not an answer and moves nothing, so the interval runs from the hello that was queued, not from one that was absorbed.
- **The first hello of a new socket generation is always answered, and starts its own interval.** A reattach is a new generation ([[R835001]]), so a real reconnect, which begins with a fresh hello, is answered at once however recent the old socket's last answer. The guard keeps the generation with the time, so no other part of the seat's guard is reset by an attach: its action window, its refusals and its malformed frames are the seat's across sockets as before ([[R137]], [[R835000]], [[R835002]]).
- **An action is never delayed or refused by it.** Only the hello arm asks the interval; the action, emote, aim, ping and malformed-frame arms and their own limits are untouched.

A page probes only once its socket has been quiet past `WS_PING_INTERVAL_SECONDS`, and any answer ends the quiet ([[R1441]]), so a real page never sends two hellos inside the interval; a client that lost a view and asks again sooner waits at most one interval for the next answer.

Rejected: closing the socket on a hello flood, as [[R835002]] does for malformed frames, since a reconnect storm of an honest page (a flaky network, a woken device) would end its game while a script loses only the answers it never needed; answering a dropped hello with an error, which would spend a frame on the flood; keying the interval to the seat so a reattach waits it out, which would delay the one hello a real reconnect sends; and a second constant, since the value and the reason are a watcher's (the page's probe never falls inside it) and the client reads neither.
