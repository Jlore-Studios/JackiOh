# R1101: the win-rate table is compiled in and refreshed only with a card patch

- Date: 2026-10-09
- Status: accepted
- Decides: MD-D2 (docs/meditative-set.md M5)
- Spec: §7, §10.1
- Proven in: `r1101_engine_reads_compiled_table` (M #50), `table_from_report_reads_in_deck`, `table_from_records_counts_every_seat`, `rows_sorted_zero_games_dropped` (tools)

The table CN Tech reads is `crates/cards/data/win_rates.json`, validated by `crates/cards/build.rs`
(a string `patch`, a `source` of `live` or `provisional`, unique row ids, `0 <= wins <= games` on
every row) and compiled in beside the catalog, so the pure crates keep their two statics and the one
table serves the server and WASM alike. It changes only with a card patch: a game's seed and log
replay on the build that played it. `cargo jackioh winrates` writes it from a `stats report --json`
export or from JSONL game record files, never both; rows with 0 games are dropped and rows are
sorted by id. The command does not apply R654's gate — the threshold lives in the server, and the
exporter picks `--source` there. The table ships empty (provisional, no live figures offline), so a
fresh patch plays the fallback until someone runs the command.
