The `improve` lane measures a change on two fixed sets of deals, each deal played twice with the seats swapped ([[R850000]]).

- **The dev set** is for screens: `cargo jackioh arena --set improve-dev`, whose deal `d` is `improve-dev:<d>`, the same deals in every session. A screen plays at least 400 games (200 deals; `SCREEN_GAMES`, the default, and the fewest the arena plays on a seed set) of the change against a control, the AI without it, and the change is kept only when the lower bound of the paired edge's 95% interval (`edgeLow`) is above zero. A change is screened once: a second read of the same deals is not a better one, and picking the best of several reads, or of several arms of a knob, is the selection the lane's sessions mistook for gains. Before the gate, the whole stack is screened against the parent on the dev set the same way.
- **The hold-out set** is the gate's own deals, `improve:<tree>:<d>`, named for each committed AI by its source tree (`git rev-parse HEAD:crates/ai/src`). Only the AI they are named for reads them: the promotion, CI's `--verify`, and a dry run of the gate on a committed `crates/ai/src`, which plays the very games the promotion would. A dry run refuses uncommitted changes in `crates/ai/src`, which would read them with another AI (`promote`'s `dirty_refusal`), and no screen plays them: `arena` refuses a seed base that is a lane's name, `improve` or `unban`, alone or followed by `:`, the gate's seeds. A stack is promoted on its hold-out read alone, so a change that won by fitting the dev set's deals shows no gain there.

The unban lane's gate is unpaired and unchanged, and its dry run still measures uncommitted changes on HEAD's seeds.

Rejected: one fixed hold-out list, the same in every session. Every read of it and every loss traced on it would tune the AI to it, until it was a second dev set, and a dry run on it would be the gate itself, played as often as a session liked. Named for the committed AI, the hold-out deals change with every change committed, and the games are a function of their seeds and the two AIs, so running the gate twice on one tree reads the same result. A commit that changes nothing measured, to draw new deals, is still fishing, which `training/improve.md` forbids.
