Hearthstone prints its expansion's symbol, large and faint, behind a card's text, so a card says
which set it is from before anyone reads it. The spec decided nothing about it: [[R503]] gave a card
a small set mark on its frame and no more, so this follows Hearthstone.

**What a face prints.** Every face that prints a rules box carries its set's watermark behind the
words: the set's mark ([[R503]]) drawn large and faint, centred in the box, as one flat silhouette
in one ink, a darker shade of the box's own colour, so it reads as an engraving and not a sticker.
It sits under the words and over the box's parchment, on every card type, a Radiant face
([[R277]]) and a Chinese face ([[R1301]]) included, and in a box with no words at all, a Vanilla
Unit's. Its size and its ink and opacity are named constants (`WATERMARK_SIZE_PCT`,
`WATERMARK_INK`, `WATERMARK_OPACITY`, and the `_ON_DARK` pair), and it never moves, so reduced
motion needs nothing. It takes no pointer, so the box's tooltip and the face's hit target are as
before.

**It never costs the words their contrast.** The ink and opacity are held, by the tests, so that
each ink the box prints in reads over the watermark as well as over the box's own edge, the
darkest part of its parchment, and the Radiant box's gold ([[R277]]) keeps its 5:1 where the text
sits. Keywords, marks, tuned numbers and Chinese faces read as they did.

**A set for each, and Meditative+'s mark.** Each set of the catalog has a watermark of its own:
Core's ringed orb, Classic's columned temple, Classic+'s temple with a plus, Meditative's ensō with
its seal, Stinkyscape's ringed planet with its stink lines and Training Grounds' target over
crossed swords. Meditative+ had no set mark, so its cards wore the fallback diamond; it now has
the ensō with the plus (Classic+'s plus over Meditative's ensō, as Classic+ is Classic's temple
with a plus), as its set mark and so as its watermark. A watermark is cut from its set's mark by
a filter, so a set that ships later needs only its mark; a test holds every set the client ships
and every set the catalog holds to a mark and a watermark of their own, all distinct. A set this
client has no symbol for (Boss, Boss-X, Custom's custom cards, or a set newer than the build)
prints no watermark, not the diamond.

**Where it does not show.** On a Glitch face, which is blank and hides its set mark too
([[R674]]); on a face with no rules box (a face-up backrow card's compact layout, a full-art face,
a face-down card); and on a face too small for its rules box, which hides the watermark with the
box (`FACE_TEXT_MIN_HEIGHT_PX`).

**Full art.** A full-art face ([[R1017001]]) prints no rules box, so its watermark shows behind the
text where its words move to: the hover preview's and touch sheet's Full text and the detail
view's rules, which are on a dark panel, so there it is the lighter ink at the lower opacity. A
card whose face holds its own box wears its watermark there and not on the panel beside it.

**Set watermarks.** A switch of the display settings' Visuals section, on by default. It is the
viewer's own and stays on the device: the `cards` settings group the account keeps ([[R633]])
leaves it out both ways, so the account's copy never sets it and changing it sends nothing. With
it off every face prints as it did before.

**Presentation only.** The set is public catalog data ([[§5.1]]) and no rule reads it. Nothing
enters `PlayerView`, an action, the log or a replay hash, and the client enforces nothing and sees
nothing hidden ([[§10.10]], CLAUDE.md rule 7). It changes how cards look, so its pending fragment
claims it as a micro ([[R2529000]]).

Rejected: a hand-drawn silhouette for each set (a later set would then need two drawings, and the
watermark could drift from its mark), and the fallback diamond as a watermark for a set with no
symbol (a diamond would pass for a symbol the set does not have); a quill for Custom's custom
cards (the builder rules, and nothing in the issue draws one); syncing the setting with the
account as Hover previews does (the issue says the device only, so the cards group leaves it
out).
