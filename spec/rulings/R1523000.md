One account holds at most one live game at a time, in any pair of modes: a 1v1 match, a Conquest series that is not over ([[R264]]) or a live co-op match ([[R1065000]]), as Hearthstone seats a player in one game at a time. [[R890000]]'s compare-and-set guarded only the in-match flag, which a series between games and a co-op match never set, so a co-op join racing a room join, a second room join or the queue sweep could still seat one person twice.

The guard is now one seat ledger in the server process, which holds the game each profile holds. Every door that starts a game (the queue's pair start and its ladder-bot starts, a room's join, a rematch, a series' next game, a co-op join) reserves all of its seats in one step: every profile it names, or none. A reserved seat is pending until the game stands, and a pending seat already counts as taken, so of two doors racing for one profile the first to reserve wins and the other answers at once with [[R1065000]]'s refusals, their codes, messages and details as they were; the loser writes nothing. A held seat admits only itself again (a retry, and the bot a rematch claims first, [[R639000]]) and, for a series between games, that series' own next game. A door that fails before its game stands gives its seats back; a rival refused meanwhile was refused for nothing and may retry. Bots are profiles and reserve as people do. The doors that only ask (enqueue, and making a 1v1 or a co-op room) read the ledger.

The in-match flag stays the record and a second guard: the doors still write it compare-and-set, the endings still clear it, and a flag the compare-and-set refuses after the ledger granted the seat is logged as drift and undone as [[R890000]] undoes a lost seat. This is not the per-profile advisory lock [[R890000]] rejected: that was a Postgres lock, and the ledger is in the server's memory and holds no lock in the database.

Every ending releases its seats: a 1v1 result (the reaper's ceiling draw included), a series game's result (its sides go back to between games), a series that is over, a co-op result, a co-op match the sweep ends, and a voided game ([[R679]]). A door that writes the in-match flag holds its seats from the moment the flag lands, and a start that fails after that lets them go as its cleanup clears the flags, so a cleanup that fails leaves both held, in the ledger as in the record, until the reaper's sweep of stale reservations frees them ([[R1450]]); that sweep, and the release of a cut-off bot start ([[R1454]]), bring the ledger to the record at once. The server fills the ledger from the record at boot, before it answers its readiness probe and before any loop starts, and on every reaper tick it frees a seat whose game the record says has ended and adopts one the record holds that the ledger lacks, both logged as drift, so a missed release holds a player for one tick at most.

A deploy runs two servers side by side for a short time, each with its own ledger, so the database holds one seat epoch. A booting server moves it on by one before it fills its ledger, and every transaction that claims a seat first takes the epoch's row for share while it still holds the epoch its server booted on. A claim made on an older epoch writes nothing and its door answers `503 unavailable`, to be retried. Shared locks never wait on each other, so claims never queue behind one another; they only make the bump wait for the claims in flight, so the new server's ledger reads every seat the old one committed. A session-level lock was rejected: through a transaction-mode pooler it would stay held on a pooled connection.
