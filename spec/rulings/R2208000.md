A game on a server seed ([[R1303000]]) decides each AI move under `PRACTICE_EARNING_AI_CLOCK_MS`,
many times the `PRACTICE_AI_CLOCK_MS` that every other practice game keeps: a free game without a
server seed, a tutorial lesson and a sandbox game ([[§9.9]]). The node budget, which the server's
clock-free re-run replays ([[R1303002]]), stays the real bound; the cap only backstops a stuck
worker, so a slow device lets the AI finish where it would have cut the move short to a different
one and made the claim pay nothing.

A decision that cap still cuts marks the game. The mark is kept in the game's save, so a game
resumed after a reload ([[R668]]) knows it too, and it reaches the page beside the claim, never in
it: the claim the server folds is unchanged, and the mark names no card.

The claim is still sent, since a cut move often matches the full one. When the server refuses it as
`ai_mismatch` and the game carries the mark, the result dialog says "this device ran out of time on
one of the AI's moves"; every other refusal reads as before, marked or not.

Rejected: not claiming a marked game, since a cut move often matches the full one and the game
would lose a reward it earned. Rejected: no cap at all, since a stuck worker would then hold the
game for ever.

Hearthstone semantics: the client never decides a reward, but it says why the server's check failed.

Superseded by issue #2560 ([[R2560000]]): with no re-run, a game on a server seed decides under
`PRACTICE_AI_CLOCK_MS`; `PRACTICE_EARNING_AI_CLOCK_MS`, the mark and its wording are gone.
