Not a rule of the game (CLAUDE.md rule 7): how the client asks before it spends what the
server holds.

[[R1953001]]'s offer, on a card's foil, finish, border or full art in its view or on a
playmat, backdrop or card back tile, no longer spends on its first press. The press asks in the
offer's place, as the shop's card token did: an alert dialog, "Unlock Galaxy? This spends 1 Epic
token.". It names the cosmetic in the reader's language and the token the offer spends, the
cheapest held that covers it ([[R1305003]]), so a Rare cosmetic offered an Epic token says Epic.

Confirm sends `POST /api/tokens/redeem-cosmetic` once. Cancel spends nothing, holds the focus
as the question opens, and puts the offer back with the focus on it. Escape answers Cancel and
nothing else, so the card view stays open.

The question is drawn inside the offer, which since [[R2730000]] stands in the item's fullscreen
preview, a modal, so it is inside the modal and in Tab's reach.

Busy, a refusal (the server's words, nothing changed) and a redemption stay as [[R1953001]]
has them.

This amends [[R1953001]] (*A cosmetic token is spent in place*: the offer asks before it sends).

Hearthstone semantics: the shop asks before it spends gold or runestones on a purchase it
cannot take back.

Rejected: asking only when the token is above the cosmetic's rarity, which leaves a tile one
press from a spend; an undo, which the server's redemption cannot take back; and a separate
modal over the page, which in the card view would lie under that view's scrim.
