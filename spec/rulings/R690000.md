A ruling added from this one on ([[§11]], CLAUDE.md rule 3) takes the lowest number free in its issue's block: issue N owns the thousand numbers N×1000 to N×1000+999, so issue #690 owns R690000 to R690999 and issue #900 owns R900000 to R900999, and an issue's first ruling is the first number of its block. A sub-issue (a fullsend part, a tracker's part) uses its own number's block, not its parent's, and a pull request with no issue uses its own number's: GitHub numbers issues and pull requests in one sequence, so no two blocks overlap. Branches on different issues therefore never take the same number, and merging `main` into one never renumbers its rulings. The note's file is `R` and the number, zero-padded to four digits at least (`R0058.md`, `R690000.md`), and its proving test is named after it as before (`fn r690000_…`, `it("R690000 …")`).

Numbers taken before this ruling keep theirs. They are sequential and lie below R2000: a branch that took one under the old rule (the last row of `spec/INDEX.md` on `main` plus one) keeps it, the numbers a tracker held stay held, and issue #1, whose block would overlap them, has none. When two branches on one issue take the same number, the one that merges second moves to the next number free in the block, renaming its note, its `id`, its tests and its citations, as `docs/issues-and-patches.md` (Ruling numbers) sets out. A conflict on `spec/INDEX.md` or `spec/11-rulings.md` alone is no clash: `cargo jackioh spec index` rewrites the index with both rows. A number on `main` is never reused or renumbered.
