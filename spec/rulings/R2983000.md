When the build names Google among its OAuth providers ([[R666]]) and sets the public `VITE_GOOGLE_CLIENT_ID` (a Google web client ID, never its secret), the sign-in screen signs in with Google through Google's own button, drawn by Google Identity Services on this site's own origin, so that Google's screen names this site and not the auth provider's host. Google's script is loaded on `/login` only, and only then. Each attempt is armed with a fresh nonce from the platform's randomness: Google is given its SHA-256 in hex, and the raw nonce stays in memory, never in storage or a URL. The ID token Google returns is exchanged with the auth provider at `grant_type=id_token` together with the raw nonce, in a request body; the implicit flow is never used and no token is ever put in a URL. The session that comes back is kept as R666's code exchange keeps it, past its second step if the account has one, and a refusal says `oauthFailed` in the client's own words (a rate limit and a fault say so, as everywhere). The fallback is R666's PKCE redirect, which stays on the screen while Google's script loads and remains whenever there is no client ID, the script does not load or is blocked, or Google cannot draw its button (its API is missing or throws, or the browser cannot hash a nonce). The account is R666's: new or matched by a verified address, it starts `pending` and passes the invite gate like any other ([[§9.4]]); the server, not the screen, decides it. The site's CSP widens by Google Identity Services' sources alone: its script, and its frames, styles and requests under its own path.
