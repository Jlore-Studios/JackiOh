A private lobby's Start ([[R3730000]]), `POST /api/lobbies/:code/start`, is its host's alone. It is refused while the guest's seat is empty or either member is not ready ([[R3730001]]), and once a Start has landed.

- The Start is written first, compare-and-set on the lobby's revision, so one Start wins and nothing changes the lobby under it.
- It then checks again what the lobby could not hold: the running catalog ([[§9.4]]), and both seats of the seat ledger ([[R1523000]]). A member who meanwhile holds a game is refused as a room's join refuses one ([[R1065000]]): the host as `assert_free_to_play` answers, the guest as busy. A refusal takes the Start back off, every Ready kept.
- A 1v1 lobby's game starts as a room's does: the room opens under the lobby's code with the host's pick and is claimed at once with the guest's, the seats by the seed's coin, unranked ([[R604]]). A co-op lobby's starts as a co-op room's join, the host in seat A1 and the guest in A2, against the AI team at the lobby's difficulty, pinned to the running catalog ([[R767000]]).
- Each client counts `LOBBY_START_COUNTDOWN_SECONDS`, 3, down from when it sees the Start before it opens the board, so no clock of the server's and the browser's need agree; the game itself starts at once.

Rejected: a server that waits out the countdown before it starts the game, which a restart in those three seconds would lose with nobody to finish it.

Amended by [[R3731000]] and [[R3731001]] (issue #3731): a 2v2's Start needs all four seats filled and ready and starts the Duos match whose team A the seed's coin picks, each team's first seat in duel 0.
