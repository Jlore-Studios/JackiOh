The API answers a browser from an allowed origin by echoing **that one origin**, never `*`, and never sends `Access-Control-Allow-Credentials`: [[§9.1]]'s client authenticates with a bearer token in a header, so no cookie is in play and a response carrying credentials would let every allowed origin act as the player. Every response the layer touches carries `Vary: Origin`, because the answer depends on the request's origin and a shared cache must not serve one origin's answer to another. An unlisted origin is **not** an error — it gets the ordinary response with no CORS headers, which is what the browser needs in order to refuse it; a 403 would tell a page nothing it could not already tell and would change the answer a non-browser caller gets, and [[§9.1]] puts the rules in the server, so CORS must never be load-bearing for a refusal. The list is the same one [[§9.2]]'s WebSocket origin check reads, so the two doors cannot diverge
