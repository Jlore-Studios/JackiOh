[[R1846001]] left a single-player set built card by card before its mode ships to a hold of its own, added by the issue that builds it, since a `SinglePlayer` row's cards join every `everySet` pool from the patch that adds them. The Infinite Assault (tracker #4576, [[§8.13]]) is the first such set, and its first card part (issue #4577) adds the hold: a stage of the set table ([[R3114000]]), `HeldSinglePlayer`, its rows listed by `HELD_SINGLE_PLAYER_SETS`.

A `HeldSinglePlayer` set is in neither the catalog order (`CATALOG_SETS`), the sets that ship (`SHIPPED_SETS`) nor the open single-player sets (`SINGLE_PLAYER_SETS`). So no deck and no random deck holds its cards, and no pool that names no set reaches them, `everySet` included ([[R380]], [[R1846001]]): only a pool that names the set (`set`, a card text's "Infinite Assault card") or its cards (`defId`) does, as a pool that names its set keeps to it whatever the set's stage. The testkit's `preview_sets` and `preview_every_set` open it on a thread as they open a set held before it ships ([[R1420]]), so `cargo jackioh fuzz`, which previews every set, deals its cards from the day they land, while a golden trace, dealt from the sets that ship, moves for none of them. It counts toward no total and no tag census, its cards take no patch fragment, and `spec check` reads a ruling's `IA #N` as the set's card N. Its row is appended at the table's end like any set's, so its place in `SetName` never moves.

The release that opens the mode turns the row to `SinglePlayer`, and its cards join the `everySet` pools then, as [[R1846001]] says of a single-player set. This amends [[R1846001]]: a single-player set is in an `everySet` pool once its row is `SinglePlayer`, not while it is held.
