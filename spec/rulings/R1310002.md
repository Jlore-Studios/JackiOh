[[§14.12]]: an existing account keeps every card granted to it, so nobody loses a deck; its
economy starts at zero, and the ledger records the move with a reason that says it was the
launch; and the full-art faces start unowned for everyone. Migration 0050 does it, once per
database: `app.settings.economy_launched` marks the reset done, with the time it ran, and a
re-apply of the file skips it. It runs in the one transaction the migration runner gives a file,
so it lands whole or not at all.

- **Every card stays.** No `collection` or `collection_grants` row is touched: the cards of
  [[R111]]'s and [[R481]]'s grants, of a dev account's fill, of a pack or a token are all still
  owned.
- **Every economy holding goes to zero** by an offsetting ledger row, reason `launch` and ref
  `launch:0050`, written before the holding's own row is deleted, so each ledger still sums to
  what is held ([[§14.11]]): the Jlore in every wallet ([[§14.1]]); the unopened packs and unspent
  tokens of the inventory; the pity counters, both token bars, the cosmetic token cycle's place
  and the Chase Shard bar ([[§14.4]], [[§14.5]], [[§14.6]]); every set track, its XP, its level
  back to the first and its levels paid ([[§14.7]]); and every held quest, as a `removed` row. Every
  economy ledger takes the reason `launch` for it, the collection's own since migration 0002.
- **The tracks start over.** Every set track row is deleted, not reset, since a row is what makes
  an older set's track active ([[R1302003]]): only the newest set's track is active again, and
  each account's first payout after the launch pays its first level ([[§14.7]]).
- **The quests start over.** The quest schedules, which keep no ledger, are deleted with the held
  quests, so each account's clock starts again at its first visit after the launch
  ([[R1304000]]).
- **No full art is owned.** Every owned full-art cosmetic ([[R1313000]]) is taken back by a
  `launch` row on its card.
- **The starter cosmetics need no row.** Every person's account owns them with no row
  ([[§14.2]]), so there is nothing to zero; the rows a dev account's fill wrote for them stay and
  own nothing more than every account owns. Every cosmetic a player picks today, in the settings
  or a deck's slots, is a starter, so no picker checks ownership; the issue that adds the first one
  that is not brings that check, as [[§14.12]]'s "every cosmetic added later must be owned" asks.
- **Dev accounts too.** §14.12 makes no exception, and while the switch was off a dev account's
  holdings were its own tools' grants ([[R1300000]]): it is zeroed like any other and grants
  itself again with its tools ([[§14.10]]).

Hearthstone semantics: Hearthstone wiped its beta accounts' collections and gold before its open
beta; the spec keeps every card and zeroes the rest, so what is left to decide is how the ledger
records it.

Rejected: deleting the holdings' ledger rows with them, since a ledger row is never edited and goes
only with its account, a mistake corrected by an offsetting row ([[§14.11]]); resetting each set
track row to its first level, which would keep active an older track a dev tool had unlocked; and
sparing the dev accounts, which would start the people who test the economy ahead of the players
they test it for.
