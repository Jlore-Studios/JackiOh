Each level of the Fleet track pays a cosmetic with the game ([[R3335001]]), but `forgetPaidReads` ([[R3206000]]) predates the track. So the owned cosmetics kept for the page ([[R1313000]]) stayed as they were: the reward showed locked and could not be equipped, until a reload or a pack opening ([[R1955000]]).

A game's paid result (`announceWallet()` with no balance, which the match, the practice board and the co-op board announce) also drops the kept `/api/cosmetics` answer (`forgetPaidReads`) and calls `forgetOwnedCosmetics()`, so every mounted `ViewerFullArt` and `ViewerAccountCosmetics` reads it again.

One more read per paid result, the same read a pack opening already causes. Practice and co-op announce through the same branch and re-read too, which is harmless. A result carrying a balance (`announceWallet(n)`) re-reads nothing.

The client decides no ownership (CLAUDE.md rule 7): it shows what the server's `GET /api/cosmetics` answers.

Hearthstone semantics: a reward earned in a game is usable when the game ends.

Rejected: having the server's result name the Fleet rewards so the client re-reads only when one was paid (a wire change to save one read); marking the reward owned from the result (the client decides no ownership, [[R1955000]]); a read per route change.
