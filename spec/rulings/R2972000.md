Not a rule of the game (CLAUDE.md rule 7): how the client asks before it throws away dungeon
progress it cannot take back.

Abandoning a run settles its loss and clears the kept run, so there is no undo. The start
screen's first press on "Abandon the run" asks in its place instead of abandoning: an alert
dialog, "Abandon this run? It ends here and cannot be undone.", with Cancel focused. Only
Confirm calls `abandon`, once. Cancel and Escape answer Cancel and call nothing, and put the
Abandon button back with the focus on it, as the token's redemption asks first ([[R2480000]]).
Hearthstone semantics: the shop asks before it spends gold or runestones on a purchase it cannot
take back.

A fight left unfinished is dealt again from its seed once the run, still on its fight, starts it
again ([[R2706000]]), so leaving one in progress asks first too. While the fight has no result,
every in-app move off it is held by the page's leave guard ([[R1754000]]), and the page asks
"Leave this fight?" with "It ends here and the fight starts over from its first turn.", as
practice asks before it leaves a game, minus the Save and leave a dungeon fight never has. "Keep
playing" stays and keeps the focus; "Leave fight" makes the move the player took. Once the fight
has its result nothing is held, nor on the stopped screen, whose Try again deals the same fight
again from its seed, so there is no live fight to keep. The guard is released when the store moves screens on its own
(Continue sends the report and unmounts the fight), as the online match releases its own
([[R2479000]]). The browser's Back or a phone's back gesture closes the open question first
([[R2127000]]), as with practice's and the online match's questions.

The run map links back to the Play menu, as the run's start screen does: the run stays saved,
and the start screen offers Continue beside a new run.

Every new sentence goes through `t()` with a `zh-CN.json` entry ([[R711000]]).

Rejected: an undo for an abandoned run, which the settlement ([[§15.8]]) cannot take back; a
`beforeunload` prompt on a reload, which re-deals the fight from its seed by design
([[R2706000]]); and reusing the online match's question, which names a server disconnect grace
that a dungeon fight has none of.
