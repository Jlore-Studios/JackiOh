A mail scanner opens the links in a mail by itself, so a link that acts on arrival proves nothing about the address and can be spent before its person clicks it. So each emailed link (a sign-up's confirmation, a password reset, the email sign-in link, an email change's confirmation) opens `/login?token_hash=…&type=…`, which does nothing by itself: it is read and scrubbed like any link ([[R193]]), sends nothing, and shows what the link is for with one button. Only the press goes on to the auth provider's verify address, built by the client from the link's token and type alone, on this site's own project, so a link can send no one anywhere else ([[R323]]'s PKCE code then comes back to `/login`, and [[R324]] holds for a link opened elsewhere). A token of another shape or a type outside those four is no link. A link mailed before the templates changed goes straight to the provider, as it always did. The templates are `infra/email-templates/`, and `cutover.yml`'s `email-links` step writes a project's only once its site serves this button.
