An open daily board (`/daily/<matchId>`) and the Daily list (`/daily`) read the server again only when the social read's `dailyWaiting` changed ([[R3727000]]). That number counts the games waiting on the player, so a game that ended on the opponent's move (a concede, or a deadline that passed while it was their move) left it unchanged, and the open page showed the game as running until a reload. The board read again only on a change while the move was not the player's, so an opponent's concede while the move was the player's, which lowers the count, was ignored too.

**The rule.** `/daily` and `/daily/<matchId>` read the server again every `DAILY_REREAD_MS` (60 seconds, a client constant, CLAUDE.md rule 9) while the tab is visible, and once when it shows again, through `pollWhileVisible` ([[R3205000]]): a hidden tab reads nothing. The board does not read once its game is over, nor while one of its own actions is in flight, which answers with the game as it stands. The read of a change of `dailyWaiting` stays, for the moves that do change the count and are shown at once.

Presentation only: the reads are the routes the screens already use, who holds the move and whether the game ended are the server's (CLAUDE.md rule 7), and nothing new is revealed.

Hearthstone semantics: a game that ends shows as ended to both players.

Rejected: (a) a version number in the social frame that moves with any of the player's daily games, which needs a new store query on both stores, a wire field and a contract test, for a result the slow read also gives; rereading on every social frame, which would read the daily screens on every chat or friends frame; a guard that drops an older answer, since a read that started before a send and answers after it is rare and heals on the next read or on the `stale` refusal that reads the game again.
