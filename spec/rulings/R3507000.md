Once Roblox is linked ([[R3147000]], on `/account`'s list of [[R3025000]]), its row also says which Roblox account it is, from the claims Roblox's `profile` scope gives the project's custom provider, held in that identity's `identity_data` of the auth provider's user record (the call that lists the identities already returns it, so no scope, request or server change is needed): `preferred_username`, the username [[R3147003]] starts its prompt from, shown as `@username`, with the display name (`name`, else `nickname`) before it as `Display Name (@username)` when it differs, and `picture`, Roblox's headshot, as a small image of one fixed size before it. Each is kept only when it is a non-empty string, trimmed; the picture only as an `https:` URL on Roblox's one image host, `tr.rbxcdn.com`, any other scheme, host or malformed value being dropped. Without a username the row is what it was, a headshot alone included, since the username beside the image is what names it (its `alt` text is empty); without a usable picture the row shows the username alone, and an image that fails to load is removed, so no broken image shows. An unlinked Roblox row, and every other provider's row, show nothing of this. It is display only: `identity_data` is the provider's to fill, so nothing in the client decides on it, and the server reads none of it. The site's CSP names that one host in `img-src` and no wildcard ([[§9.2]], `apps/web/public/_headers`).
