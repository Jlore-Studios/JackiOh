A queue ticket froze its player's deck or trio at enqueue, checked against the catalog of that moment ([[§9.4]]), and carried that catalog's version, but nothing read the version again. A card patch restarts the server and the ticket stays in `tickets`, so the next sweep seated the wait in a game played on the new cards, usually against a ladder bot once the fallback time had passed ([[R1453]]), with a deck only ever checked against the old ones and a tab still showing the old card text. A rematch ([[R1638000]]), an unstarted lobby ([[R4072000]]) and a room's join already end at a patch; the queue was the one door into a match that did not.

Each sweep now first cancels every open ticket whose catalog version is not the running one, in every mode (Best of 1, Conquest and All Random), before any pair and before any ladder-bot start. It does not wait for the listening window of [[R897000]]: a stamp needs no listening, so the cancel also happens on the first sweep after a restart. The cancel is [[R897000]]'s cleanup for a stale ticket (the ticket closed, its seed, its seat entry and its presence forgotten) and is logged as `queue.catalog_changed`. The player's wait ends the way a timed-out one does: their next `GET /api/auth/me` answers `queued: false`, they queue again, and the deck or trio is frozen under today's cards. No match, series or bot is made, and no in-match flag is set. The versions are compared for inequality, as a room's join does, since the server has no order on them. Tickets on the running catalog pair and fall back to bots as before.

The cancel runs under the seat epoch's fence ([[R1523000]]), as a pair's claim does. A draining older server in a deploy overlap holds an older version than the newer server's, and an unfenced cancel would end the newer server's fresh tickets; fenced, it cancels nothing and leaves every ticket to the newer server's sweep. A fenced cancel is skipped without failing the sweep. Only an open ticket is closed, so a pair that was claimed in the meantime stands.

Where the spec is silent this follows Hearthstone semantics: a patch going live ends the matchmaking a client began on the earlier version.

Rejected: re-freezing the player's saved deck under the new catalog, since they may have edited it since they queued ([[R4072000]] rejected the same for lobbies); checking the frozen deck again at pairing and keeping the ticket when it is still legal, which adds a validation path no other door has and leaves the old tab drawing the old cards ([[R1638000]] rejected the same for rematches); an unfenced cancel, for the overlap above.

Left out: queuing again from a tab opened before the deploy still runs the old build until its next move between menus ([[R4605000]]), which belongs to the client.

Amends [[R897000]], whose sweep gains this cancel before its own, and [[§9.4]]'s list of the doors that refuse a stale catalog.
