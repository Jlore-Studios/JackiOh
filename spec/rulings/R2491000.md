[[R978000]] kept each patch's report for `CARD_STATS_CACHE_TTL_SECONDS` under `CARD_STATS_KEPT_REPORTS` (256), sized for 30 patches and three pilots. The key has since gained `?mode=`'s four match types and `patches.json` 80 versions (at v0.5.11), so once every view's drill-down had been opened within the TTL, each kept report pushed out the one the next page read next, and every later page loaded each patch again, one after another, on the pool the live matches write through.

- **One kept history per pilot and mode.** The card drill-down's patch history for one `?pilot=` and `?mode=` is read off every patch's totals in one load, as `GET /api/stats/cards`' windowed report is ([[R1367000]]), and kept as [[R978000]] keeps a report: for the TTL, computed once however many requests miss it together, a failed load kept for no one, and shared by every card's page. It holds each shipped patch whose live games clear [[R654]]'s gate, in `patches.json`'s order, with each card's in-deck games and win rate there.
- **The current patch's drills stay its own.** The turn and co-played figures still read the current patch's kept report, so a drill-down that misses makes at most two loads however many patches ship, and the drill-down keeps at most a history and a current report for each of three pilots and four modes.
- **The figures are the same.** Each patch's row is cut from the one load by the counting its own load had, so for the same records every response is byte for byte what it was ([[R654]], [[R1451]], [[R1044000]]).

Rejected: raising `CARD_STATS_KEPT_REPORTS`, which still costs one load per patch on every missed drill-down and holds a full report per patch, pilot and mode in memory; and dropping the entry used longest ago, which [[R978000]] already rejected and which thrashes the same way once the working set passes the bound.
