---
id: R1023000
title: Development records reach the database through stats-import or POST /api/stats/dev-records
cards: "§9.11, R378, R654"
proven_in:
  - crates/server/tests/api/stats.rs
---
**Why.** Each training lane loaded its finished days' game records into Postgres itself, running
`jackioh-server stats-import` on the box with the database's own connection string. That kept the
master credential on a box the lane users share, broke on the pooler's address and the password's
shape, rebuilt the whole server on two cores after every move of `main`, and loaded each batch
almost a day late (issue #1023).

**The rule.** A development record enters the database through `jackioh-server stats-import` or
through `POST /api/stats/dev-records`, and [[R378]]'s refusals apply to both. The route takes the
JSON Lines `cargo jackioh stats --out` writes, one `GameRecord` per line, and files them by calling
`import_dev_records` unchanged, so a body holding a record that is not `source: "dev"`, one whose
id does not begin `dev:`, or a forced-run record is refused whole with 400 and writes nothing; a
record the database already holds is skipped, so a retry never writes one twice, and each written
record is folded into the totals the way `stats-import` folds it ([[R1044000]]). The route is
write-only behind its own credential, `STATS_INGEST_TOKEN`: the bearer is compared in constant time
and Supabase is never called, a user's token opens nothing here and the ingest token opens no other
route, and with the variable unset the route answers 404 as an unknown path. A body past
`DEV_RECORDS_MAX_BODY_BYTES` (1 MiB, about 550 records) is refused before parsing, and the
per-address rate limit counts the route as every route. A leaked token can only add fake `dev:`
games, which never count as live games ([[R378]]) but pad a patch's public figures until the gate
clears ([[R654]]); changing the variable revokes it.

**Unchanged.** `stats-import` stays, for a person loading a pre-release run from their own machine.
No store, migration or client change: the route folds records the same way `stats-import` does.

Rejected:

- Leaving `DATABASE_URL` on the training box: the lanes would keep the database's master credential,
  readable through `systemctl show`, on a box that runs sessions as the lane users.
- Opening the route with a user's bearer token: any account could then file development games, and a
  leaked lane credential would open every user route instead of none.
- Sharing `API_MAX_BODY_BYTES`: a gather batch of 100 games is about 180 KB, past what one account
  statistics copy may hold, so the lanes would have to slice every batch at tens of records.
