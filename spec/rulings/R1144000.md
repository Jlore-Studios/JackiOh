---
id: R1144000
title: A failed refresh of the sign-in key set keeps the last good keys
cards: "§9.2, §9.4"
proven_in:
  - crates/server/tests/api/auth.rs
---

[[§9.2]] signs in at the provider and has this server verify the token against the project's
published key set (tier 1 of `verify_access_token`), refetched once it is older than
`JWKS_CACHE_MAX_AGE_MS`. When a refetch fails — the timeout, a 5xx, a bad body — the failure does
not sign every player out: verification keeps going against the last good set for at most
`JWKS_STALE_MAX_MS` past its age limit (about one access-token lifetime, so no token outlives its
own `exp` through the stale set), as an unreachable provider keeps the identity under [[R159]].

A failure is retried at most once per `JWKS_COOLDOWN_MS`, with one fetch in flight at a time while
the other requests read the cache. A successful fetch replaces the set whole, so a key the
endpoint dropped is refused at once. Every failure is logged as `auth.jwks.fetch_failed` with its
cause. Past the stale cap with the endpoint still failing, the token is refused until the endpoint
answers again.
