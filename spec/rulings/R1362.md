A fatigue draw whose hit the hero's Armor takes whole is still reported ([[R240]]), and since patch v0.3.X by the pipeline's own report ([[R1361]]): the `fatigue` event ([[R315]]) and then `damageAbsorbed` from no source on that hero, with the whole hit as `absorbed`. The `damage` of 0 R240 wrote is gone, so the draw is reported once.

It keeps the place in [[R68]]'s order that R240's `damage` of 0 had, the one report of a whole stop that joins the trigger loop's frontier, which holds it as that same hit of 0 and answers it with nothing ([[R63]]). So a game with an absorbed fatigue draw folds to the state, and the final hash, it always had ([[R768]]).
