A network has rows only for the sparse keys it was fitted on, and a key it has no row for is no input to it ([[R1010000]]). A layout that only adds sparse key families to an older one, as version 3 adds the keys of what each card is to version 2 ([[R3112000]]), so gives a network fitted on the older one exactly the correction the older layout gave it, bit for bit: the dense features are the same in the same order, and its rows read the same keys.

`FEATURES_READ_SINCE` (`crates/ai/src/features.rs`) is the oldest version whose networks this build reads so, and the compiled-in network's `featuresVersion` may be any version from it to `FEATURES_VERSION`; [[R1010000]]'s test fails outside that range, and still fails on a dense layout other than this build's ([[R1006000]]). Any change to the dense layout or to what an existing key means raises `FEATURES_READ_SINCE` to `FEATURES_VERSION`, so a network fitted before it no longer ships. The training lane's loader still refuses to fit one network on rows of two versions.
