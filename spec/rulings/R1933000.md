Not a rule of the game: where each site's card statistics are filed, and so what production's
public figures count.

Production and staging each have a database of their own, a Supabase project apiece
(`docs/deploy-cloudflare.md` section 8). A development record enters a database only through
`jackioh-server stats-import` ([[R378]]), and the only workflows that run it, the gather lane and
the learn lane's import ([[R1976000]], [[R1676000]]), connect through `STATS_IMPORT_DATABASE_URL`,
staging's. Production's database is read through `STATS_DATABASE_URL`, which no import uses. So
production holds live games alone, and the move's copy of the original database into production
brings no development row either.

Production's public figures therefore count live games only. Below `PUBLIC_STATS_MIN_LIVE_GAMES`
the gate in [[§9.11]] finds no development games to pad with: the figures are still labelled
provisional ([[R661]]), and a card shows "not enough games" until its window holds
`CARD_STATS_MIN_SAMPLE` of them ([[R654]], [[R1367000]]). `winrates-refresh.yml` reads production,
so the provisional refresh of [[R2386000]] has no development games to pad with either, and the
Tech decks' table waits for live games. Staging's site reads both sources as before.

The owner's decision (2026-11-01): the figures players see rest on players' games.

Rejected: copying the development totals into production once, at the move, which would pad the
patches already gathered and no later one, so the figures' basis would change from one patch to
the next; and filing every development run into both databases.
