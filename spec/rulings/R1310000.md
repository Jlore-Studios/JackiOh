[[§14.12]] has a new account start with the starter cards and its tracks' first rewards once the
economy goes live, and leaves to the going-live sub-issue which cards those are, as data, and
whether a deck save checks ownership. The economy is live: `ECONOMY_LIVE` is on, in the server and
in the client, which reads it from `serverConfig.ts`, so a finished game pays ([[R1302006]]),
quests arrive ([[R1304002]]), a free practice game asks for a seed and claims ([[R1303000]]), every
active account sees its packs on `/account`, not a dev account alone, and a production build prints
a full art only on its owner's own copies ([[R1313000]]).

- **The starter cards** are `STARTER_CARDS` (`crates/server/src/config.rs`, exported to
  `serverConfig.ts`): the 39 Core cards of the three practice decks, Human Vanguard, Blitz and
  Fortress ([[§9.9]], `apps/web/src/practice/decks.ts`), their union. A new player may have met
  them in practice already, so the account can queue any of the three decks offered there, and
  they are more than `DECK_SIZE` distinct collectable cards, so it can build a deck of its own too.
- **The grant.** `seed-catalog` writes the list to `app.settings.starter_cards` in the transaction
  that stamps the catalog version, before the stamp, so the list has one source. The activation
  grant ([[R111]]), on the `pending → active` transition, grants one copy (`launch_quantity`) of
  each non-token card of the current version the list names, and nothing else: reason `launch`,
  ref `launch:<version>`, idempotent as before. A listed id the catalog lacks, or a token, is
  skipped. The in-memory store reads `STARTER_CARDS` itself, and the store contract holds the two
  stores to one answer.
- **The first rewards.** The redemption that makes the account active also pays the newest set's
  track its first level, the level a track starts at ([[§14.7]]): that level's rewards from the
  set's reward table, 100 Jlore today, once, since a track pays a level once. The older sets'
  tracks are not active yet, so each pays its first level when it unlocks, as any track does
  ([[R1302003]]). An account that was already active pays its newest track's first level at its
  first payout ([[R1310002]]).
- **Ownership** is checked where it always was: queueing a deck or a trio, or bringing it to a
  room, refuses a card the account does not own under [[§9.4]]'s L5, naming the deck and the
  card ([[R253]]). A deck save still checks structure alone ([[R250]]): a draft may hold any
  deckable card, so a player can plan a deck around a card not yet owned, and a deck code a
  friend shares imports whole. For an account that owns only the starter cards, L5 can now fail
  alone ([[R141]]).

Hearthstone semantics: a new Hearthstone account starts with a basic collection to play its first
decks with, a reward on the way in, and earns the rest; a deck may be built from the cards it
owns, and a deck code naming cards it lacks still imports, with the missing cards shown to craft.

Rejected: a Core card of every rarity, or every Common, as the starter list, which would hand a new
player cards they have never met while leaving one of the practice decks they learned on
unqueueable; refusing a deck save that names a card not owned, which would lose a player's draft
([[R250]]) and break an import of a friend's deck code; and paying every shipped set's track its
first level at activation, which would pay an older track before it is active ([[§14.7]]).
