The `learn` lane (`training/learn.md`, `.github/workflows/learn.yml`) retrains the learned evaluation ([[R1010000]]) on fresh self-play and promotes it with no LLM in the loop (`docs/learned-eval.md` D2). Its gate, `cargo jackioh promote --lane learn`, is the improve lane's ([[R850000]]): `TRAINING_LEARN` plays 400 games against the parent, 200 deals each played twice with the seats swapped, and promotes on 220 wins. Its deals are its own, `learn:<tree>:<d>`, a hold-out set read only by the committed AI they are named for ([[R850001]]): `arena` and `selfplay` refuse a base that names them ([[R1006002]]), and a dry run refuses uncommitted changes, as the improve lane's does.

A run screens first, on the dev set, and plays the gate only when the screen's `edgeLow` is above zero, so the gate's deals are read once per candidate. A pass lands as `AI gen <N> (learn): …` from `ai/learn`, which CI's training gate holds to the same rules as the other lanes' branches: only `crates/ai/**` and `training/history/**`, one generation on from `main`, and the gate played again (`promote --verify`).

The improve and unban lanes are the supervised half of the AI, a model's sessions changing the hand evaluation and the search; the learn lane is the learned half, a network fitted to the AI's own games correcting the hand evaluation it is given. Both share `main` and its generations.
