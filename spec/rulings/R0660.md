Presentation only (CLAUDE.md rule 7): no rule, state, event or message changes. A card's flavour line and artist credit live in a sidecar beside the catalog, `crates/cards/flavour.json`, keyed by catalog id with `{ flavour?, artist? }`, never in `catalog.json`: an edit to it is not a card patch and claims no pending fragment, `patches check` and `catalog check` never read it, and the client reads it from the bundle as it reads the catalog, so no server route or seed carries it. Every key is a catalog card or token, every card and token has a flavour line, and each entry is a trimmed single line of at most `FLAVOUR_MAX_CHARS` (120) characters of flavour and `ARTIST_MAX_CHARS` (60) of artist. No flavour line uses a word on the voice lines' rules-word list (`BANNED_RULES_WORDS`, [[§10.11]]), with none of the voice lines' allowance (issue #115). The line, then "Art by" and the artist, show under the glossary in the hover preview's column (which a card with no text now draws for its flavour alone), the touch sheet and the detail view, the deck builder's and the Card Almanac's ([[R630]]); never on a face, and never for a face with no catalog definition, the hidden sentinel or a match-made definition ([[R77]]), which have no entry. Real art is `apps/web/public/art/<id>.webp` for the base face and `<id>-radiant.webp` for the Radiant face: WebP, square, exactly `ART_SIDE_PX` (512) px a side, at most `ART_MAX_BYTES` (96 KiB), listed in `ART_MANIFEST`. A check fails on a manifest line for an id the catalog lacks or naming neither face, a listed file that is missing or breaks the convention, and a file no line lists. Procedural art stays the fallback for every card the manifest does not list and every file that fails to load
