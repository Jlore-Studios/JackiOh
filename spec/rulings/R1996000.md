title: "The queue readout is counted at most once every few seconds and kept (issue #1996)"
cards: "§9.5, R640002, R978000"
proven_in:
  - crates/server/tests/api/queue.rs
---
`GET /api/queue/population` counted the hour again on every request, and every waiting client asks every `SERIES_POLL_SECONDS` (2 s). The server now keeps what it counted for `QUEUE_READOUT_CACHE_TTL_SECONDS` (5 s) and answers every readout inside that time with it.

- **One answer for everyone.** The route takes no parameter and names nobody ([[R640002]]), so one kept answer serves every caller. Its numbers may be up to the TTL old.
- **Not shared in flight.** Readouts that miss together each count, and the last one kept wins. The numbers need not be exact (the owner's call on #1996), unlike [[R978000]]'s reports, which are computed once. A count that fails is kept for no one: the next readout counts again.
- **In memory.** A restart, or a test's app, starts with none.
- **The response is unchanged.** The same body, still `no-store`: the route is for signed-in users, and a `public` max-age would let a shared cache answer anyone.

Rejected: a longer TTL, which shows numbers late while the queue moves; and indexes alone (migration 0062, no ruling), which make each count cheap but still count on every poll.
