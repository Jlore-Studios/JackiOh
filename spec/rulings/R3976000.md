A replay drew both heroes as the default portrait whoever played, and a GIF made from it did too,
though [[R513000]] has a GIF draw its seats as their portraits ([[R641]]). The spec said where a
match's portraits come from ([[R642]]) and what a replay's pages carry ([[R768]], [[R1834003]]), but
not that a replay draws them, nor that a page carries them.

**The pages.** Each page of `GET /api/replays/:matchId` ([[R768]]) carries `portraits`, `{ p1, p2 }`,
both seats' portraits as the match fixed them ([[R642]]), and `vanilla` for both for a match from
before portraits, as the replay list's rows already carry them. A friend reading a shared replay
from the sharer's seat gets them on its pages as it gets the loadouts ([[R1834003]]): a portrait is
cosmetic and both seats were already told both. They are never part of `PlayerView`, an action, the
log or a replay hash (CLAUDE.md rule 7).

**The player.** The replay player draws each hero as its source's portrait for that seat: an online
match's from its pages (so a replay opened by match id, as "Watch the replay" ([[R768000]]) and a
friend's share open one, has them from its first page), a practice game's from its kept summary,
and a downloaded file's from its `game.portraits` ([[R1141000]]). The page deals a free practice
game's portraits into the config it starts the game with, so the summary holds the ones its board
drew and a resumed game keeps them. A GIF made from a replay draws the same pair ([[R513000]]). A
source with none (an older server's page, an older file), or naming an id this build does not know,
draws `vanilla`. A replay's hero opens no emote menu ([[R643]]): the portraits are drawn and nothing
more.

Hearthstone semantics: a replay shows each hero as it was played.

Rejected: reading the portraits from the replay list's row alone, since a replay opened by match id
has no row; and drawing the daily board's and a watched live game's portraits here, since neither
is sent portraits today and each needs a server read of its own.
