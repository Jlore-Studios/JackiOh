A replay of a finished game is its action log folded once and then read a step at a time. Step 0 is the state after `begin_game`. Step k is the state after the k-th log action `reduce` accepted, so an action the reducer refuses is no step ([[§9.2]]).

A replay of seat s at step k is exactly `view_for(state_k, s)` with that state's turn ([[§10.8]], [[R97]]): the replay's seat sees what that seat saw, the opponent's hidden cards hidden. Hearthstone's replay viewers likewise show one seat. Nothing outside the log is replayed: no clock (a replay's view has no `clockMs`), no emotes, no presence and no rematch offers, because none of them is an action and none is in the state ([[R643]]).

Before any step is given, the whole log is folded. A game played on another catalog version than the build's is refused as `earlier_patch`, before anything is folded. A fold that does not hash ([[§9.3]]) to the game's recorded final hash is refused as `rules_changed`: a rule has changed since the game was played. A refusal gives no step.

A state is kept every `REPLAY_CHECKPOINT_EVERY` accepted actions, so reaching any step costs at most that many `reduce` calls, and so does a page of at most `REPLAY_PAGE_STEPS` steps. A page that would cost more ends early, and the next page starts where it ended. The function reports how many `reduce` calls it made, since a pure crate keeps no counter (CLAUDE.md rule 4).

The kept states hold hidden information, so only the server or the practice worker may hold them, and what leaves them is a `view_for` (CLAUDE.md rule 7). It changes no rule of play, adds no field to `GameState` and changes no hash.
