The compiled win-rate table, `crates/cards/data/win_rates.json`, that M #50 CN Tech and M+ #2 NA Tech read is refreshed once per X, the version span a major or a patch opens ([[R1365000]]). `cargo jackioh winrates --refresh <input>…` decides whether a refresh is due. Its input is JSONL game record files or one windowed report: `jackioh-server stats-cards --window[=<version>]` prints it off every patch's totals, which alone hold every game a window spans, since a record's detail is purged after `GAME_RECORD_RAW_RETENTION_DAYS` ([[R1044001]]); `stats report --window <version> --json` prints it off record files. It reads the windowed report at the newest shipped version, through the function `/api/stats/cards` calls ([[R1367000]]).

- **Due** when the window every card shares (the X's) has `PUBLIC_STATS_MIN_LIVE_GAMES` (1000) live games ([[R654]]) and the table is filed under a version outside that window. The table is then rewritten from each card's in-deck wins and games over its own window, filed under the newest shipped version. It is live unless a card's window counts a development game.
- **Not due** while the X's window is short. The table keeps the previous X's numbers.
- **Not due** when the table is filed under one of the window's versions. It was refreshed in this X already, and the micro its fragment ships as stays inside the X, so a refresh is never due twice in one X.

A due refresh also writes a pending fragment. The fragment claims the table (`winRates: true`, [[R1329000]]) and, through `plays` ([[R1366000]]), CN Tech and NA Tech, whose play the table changes. It claims no catalog card, so `patches ship` names it a micro. A refresh is refused while another pending fragment claims the table. Each shipped version keeps the table it shipped with, so an older shipped catalog still folds with its own table ([[R1329000]]).
