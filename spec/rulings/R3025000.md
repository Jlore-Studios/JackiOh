A provider's account whose verified address matches a JackiOh account already joins it ([[R666]]'s automatic linking). For any other, `/account` lists each OAuth provider the build names, linked or not. Link asks the auth provider, with the session's own token, for the provider's page (`/user/identities/authorize`, never a URL anyone could start), with a PKCE challenge of its own flow, and returns through `/login` like R666's sign-in ([[R323]]). Its code is exchanged only with that verifier, and the session that comes back, the same account's, is kept as R666's is, past its second step if the account has one, and the player lands on `/account`, which says it is linked. A link that comes back with an error lands there too and says it could not be linked (the provider's account may be another JackiOh account's), in the client's words. Unlink removes that provider from the account. The account's last way in is never offered for removal, and the auth provider refuses it as well. Nothing shows on a build that names no provider. The projects' manual linking is on for this.
