Wherever a player can start a game on a random deck, they may also pick the set they want more cards from: [[R924000]]'s "More cards from" picker (none, "The newest set (…)", or any set that ships) sits beside that random deck, and its pick leans their own dealt deck as [[R924000]] leans it. The lobby's All Random and its rematch ([[R1372]]) and practice's Random deck ([[R1373]]) had it; three more doors now do:

- **Challenging a friend to All Random** ([[R1831000]]): the challenge dialog shows the picker under All Random, and the challenge's room is opened with the challenger's pick (`leanSet` on `POST /api/challenges`, the body `POST /api/rooms` takes).
- **Accepting an All Random challenge**: its toast shows the picker, and Accept joins the room with the friend's own pick (`leanSet` on the join). Each seat leans on its own pick, or none, as in any All Random room.
- **A Duos room on a Random deck** ([[§13]]): the co-op panel's picker replaces [[R1372]]'s switch, and the room's create and join send `leanSet` instead of `leanNewest`, so a co-op player may lean on any set that ships, not only the newest.

The challenge dialog and toast are part of every screen, some of which paint before the engine's module is in (issue #778), and the picker states the share of the deck a pick asks for, a number the engine holds: there the picker comes once the module is in, which it then loads, and if it never arrives the picker stays away and the device's pick still travels.

These are all online games, so they share one pick on the device with the lobby and the rematch: each starts from the pick made last, wherever it was made, and a change writes it. Practice keeps its own ([[R1373]]). With no pick the request carries no lean at all, as before. A link that starts a game itself still deals the deck it names ([[R1373]]). The server already read `leanSet` on each of these requests and deals every deck, so nothing but the client changes (CLAUDE.md rule 7).
