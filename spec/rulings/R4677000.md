**Why.** The patch bar offers the newest patch and the five newest with enough games ([[R3324000]]), and every other patch was a `?patch=` away. The owner asked for a search through every patch (#4677, [[R4677001]]) and a limit on how far back it reaches, except for a dev account ([[§14.10]]).

**A patch and its line.** A patch is the page's: a window every card shares, a major or a patch with its micros ([[R1973001]]), as `GET /api/stats/cards`' `patches` lists them, newest first ([[R1973002]]). A patch's line is its version's `major.minor` (v0.6.x is the line v0.6). Each line opens with a major, so no window spans two.

**Who reads what.** The server decides (CLAUDE.md rule 7):

- **Anyone but a dev account**, signed in or not, reads the longer of two newest-first runs: every patch of the newest patch's line followed by the `PUBLIC_STATS_PATCHES_LINE_BEFORE` (2) newest of the line before it, or the `PUBLIC_STATS_PATCHES_NEWEST` (5) newest. Both are prefixes of the list, so the longer is their union. While the newest line is long (all of v0.6 and two of v0.5) the first is longer; just after a major (v0.7.0 and two of v0.6) the five newest are.
- **A dev account** (`api::dev::is_dev`: `DEV_PROFILE_IDS`, or the end-to-end fixture `e2e-econ` in end-to-end mode alone, [[R1300000]], [[R1310004]]) reads every patch back to v0.1.0.

The routes stay open ([[R654]]). A request carrying a token is read as its account's when the token verifies and the account has a profile, and as anyone's otherwise: a token that does not verify never refuses an open route, and no profile is created. A signed-in caller counts as presence, as every signed-in request does ([[R3210000]]).

**What is limited.**

- `GET /api/stats/cards?patch=` and `GET /api/stats/games?patch=` answer a version of a patch past the caller's with 403 `patch_dev_only`, before any figure is read and writing nothing. No `patch`, the current one, is open to everyone. A version no listed patch holds is no shipped patch and reads its own totals as before ([[R3067000]]).
- `patches` lists the caller's patches alone, so the bar, its arrows and the search never offer one the server refuses; `previousPatch` is null when the version before is past them; and `olderPatchesForDevs` is true for anyone but a dev account, for the search's closing line ([[R4677001]]).
- The card drill-down's Win rate by patch (`GET /api/stats/cards/:id`, `patches`, [[R2491000]]) lists the caller's patches alone, so the limit cannot be read around through it.
- Left alone: the Experimental tab's pooled views (#4671), which are no patch query, and the Sets tab's patch before, which the limited list already bounds.

**Caching.** The kept figures ([[R3067000]]) are the same for every caller; only what an answer lists of them is the caller's, cut after the cache. Anyone's answer stays `public, max-age=CARD_STATS_CACHE_TTL_SECONDS`; a dev account's is `private, no-store`; and each of the three routes' answers carries `Vary: Authorization`, which the CORS layer now keeps beside its own `Vary: Origin` ([[R162]]), so no cache, the browser's included, hands one caller's answer to another. Nothing in front of `/api/*` caches (#4011).

**The client sends the session.** `/stats` sends the signed-in token, when there is one, with its card statistics, game figures and drill-down reads, and keeps each answer under its account, so a dev account is told apart. An address naming a refused patch opens on the current patch with the search's closing line, never an error page.

**Outside callers** (CLAUDE.md rule 13). The routes stay. The deploy jobs poll `/api/catalog`; `winrates-refresh.yml`, `cargo jackioh stats` and `analysis/` read the totals or record files, not the routes; the admin dashboard reads none. The bot's status issue (`bot/go/internal/cardsets`) walks back from the newest version through `previousPatch` at most 30 versions, which today stay inside v0.6; at the limit's edge the walk now meets a null `previousPatch` and stops, rather than a 403.

Hearthstone semantics: a stats site's public history is its recent patches.

Rejected:

- Refusing a version no listed patch holds: it is no patch, and its own-totals read ([[R3067000]]) stays as it was.
- Keying the kept figures by caller: they do not differ, so the list is cut per answer instead.
- A `public` answer for a dev account under `Vary` alone: `private, no-store` keeps it out of every shared cache whatever a cache does with `Vary`.

Amended by [[R4965000]] (issue #4965): a dev account's drill-down history stops at the patches whose card totals the kept snapshot holds as filed; an older patch's figures are a `?patch=` away, read on demand.
