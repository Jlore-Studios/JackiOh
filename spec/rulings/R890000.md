A match seat is claimed compare-and-set: `profiles_set_in_match` seats only a free profile in one statement and answers `false` without writing when another match holds the seat, so a queue pair, room join, rematch or series game racing for one player leaves exactly one winner — the first writer wins ([[§9.5]]'s "not in a match"). Clearing with no match stays unconditional, and a new conditional clear undoes only a seat that points at the match being undone, so a start-failure cleanup never wipes a rival match's flag, which is what orphaned the second of two live matches before.

Each starter maps the lost seat onto the cleanup it already runs for a failed start: a queue pair drops its uncommitted seats, forgets the claim's `open` skeleton and records the failed start with the tickets claimed; a room join drops its uncommitted seats, deletes the claim (which frees the room code) and answers 409; a rematch stops the actor and erases the started match with no result ([[R679]]), whose `on delete set null` releases the winner seat's flag while the taken seat keeps its game, and the seats re-offer; a series game does the same and reports a game that never started, so the next transition retries with the same id. A host holds at most three unclaimed unexpired rooms (`MAX_OPEN_ROOMS_PER_HOST`), so its rooms cannot amplify a seat race without bound; the cap is advisory, the seat claim is the guard. Endings still clear unconditionally ([[R1450]]).

Rejected: a per-profile advisory lock — heavier, and `tickets_claim_pair` already sets the compare-and-set precedent; and a host predicate in `rooms_claim` — that statement runs as the guest, so a host-row guard cannot be trusted there, while the seat claim covers room-vs-room and room-vs-queue uniformly.
