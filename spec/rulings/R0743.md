The designer asked on #290 (jgoetzmann, 2026-10-05) for the patch history to read in order, without the gaps the hand-picked names had left (v0.2.0, v0.2.4, v0.2.5, v0.2.10, …): a normal patch (`Patch vA.B.X`) takes the next number and a micro patch (`Patch vA.B.Y`) the next letter ([[R650]]). Every card patch after v0.2.0 was renamed that way in `patches.json`'s order, with its snapshot, its `shipped.json` entry (the same commit and blob, since no snapshot's bytes moved), its title and `index.json`: v0.2.4 (#45, the card text pass) is v0.2.1, v0.2.5 (#149, the mechanics changes) v0.2.2, v0.2.10 (#113, the Animated pass) v0.2.3, v0.2.11 (#181, aimed random casts and Deft) v0.2.4, v0.2.12 (#218, the Animated pass undone) v0.2.5, v0.2.13 (#271, Book of Wildfire, [[R671]]) v0.2.6, v0.2.14 (#126, More card patches) v0.2.7, the micro patch v0.2.14b (#260, the yellow glow for ten Core cards) v0.2.7b, v0.2.16 (#170, Glitch, [[R673]]–[[R679]]) v0.2.8, its micro patch v0.2.16b (#323, Gary the Gambler's buff) v0.2.8b and v0.2.17 (#44, the rarity pass, [[R739]]–[[R742]]) v0.2.9, which is the catalog version; #88's pending v0.2.15 (balance patch 1) ships as v0.2.10. This spec, the docs and the code use the new names; commit messages and issue titles keep the names they were written with, and this row is the key between the two. The patches that changed no card data (#48's statistics, "Patch v0.2.5"; #49's ladder, "Patch v0.2.6"; #51's music, "Patch v0.2.7"; the codebase pass, v0.2.8; #54's Almanac, "Patch v0.2.9") were never catalog versions and keep their titles, though the card patches now use those numbers too, and the Heroic Power patch the design brief planned as v0.2.1 (docs/classic-sets.md B3.2 rule 10) has not shipped and is called the Heroic Power patch. From here on a normal card patch takes the next number after the newest card patch on `main`, shipped or pending, and its fragment is named that number; a micro patch is named when it ships ([[R650]]); a patch that changes no card data ships no version and takes no number, keeping its `X` or `Y` title, so it leaves no gap. A database that served the old names renames each row carrying one, once (migration 0025): the catalog version of `cards`, `decks`, `tickets`, `matches` and `series` (a series' rename takes its next compare-and-set version, [[R263]]), a game record's patch with the copies in its record and a development record's id ([[R378]]), the patch and catalog version of `rated_games`, the patch version of `seasons` and `app.settings`' catalog version, one name at a time and oldest first, so each name is free before it is taken again and no row is renamed twice; `collection_grants` is append-only and keeps its `launch:<version>` references, and the legacy loadout tables stay unwritten ([[R254]]). The order of patches is still `patches.json`'s, and nothing compares version strings ([[R105]])
