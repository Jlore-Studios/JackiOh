[[§14.11]] says every roll is seeded and logged so it replays exactly. The tiered roll
([[R1339000]]) keeps [[R1301003]]'s and [[R1306003]]'s seed, log, lock and transaction as they
were; what moves is the order of the draws.

- **A card pack** draws from the engine's seeded generator from cursor 0, in this order and no
  other: each slot's tier, one integer draw below `TIER_WEIGHT_TOTAL`, in slot order, the floored
  slot's included; pity, which takes none ([[R1339001]]); then, slot by slot, the card's one and,
  for a duplicate, its cosmetic tier's one and the pick's one when there is something to pick
  ([[R1301002]]). Every list it walks is in catalog or registry order.
- **A cosmetic pack** draws slot by slot, in this order and no other: the slot's tier, then its
  cosmetic's pick and, for a per-card cosmetic, its card's pick, each only when there is something
  to pick. A spent slot ([[R1306001]]) takes only its tier's draw.
- **The log** holds what it held: the seed, what the roll read but the holdings, and the result
  (the slots, a card pack's pity counters and the draw count). A replay is `roll_opening` or
  `roll_cosmetic_pack` over the holdings before the opening, as before, and an integer draw lands
  on the same tier in the replay as in the opening, with no float rounding between them.
- **Older logs.** An opening logged before #1339 rolled the old way, so it replays only under the
  roll of its day, in the history of `crates/server/src/economy/`; its logged result audits it
  without a replay ([[R1301003]]).

Hearthstone semantics: as [[R1301003]]; Hearthstone shows only the result.

Rejected: logging each draw's value, which the seed and the count already replay ([[R1301003]]); a
field naming the roll an opening took, which no reader needs while the logged result audits every
opening; and drawing which slot pity forces, which would make a force random where the floored
slot's order makes it plain.
