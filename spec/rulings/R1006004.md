`cargo jackioh positions` writes, after a header naming `FEATURES_VERSION` and the dense features, one row per position of each game it keeps ([[R1006003]]): the game's seed, the seat, the turn, the step (the actions folded before it), the feature version, the catalog, the seat's features (`features_of`, [[R1006000]]), the hand eval's score and the outcome for the seat: 1 for a win, ½ for a draw, 0 for a loss.

- **Which positions.** `--every turn`, the default, takes one position per seat per turn: the seat's first decision of its own turn in the main phase, with no prompt open. That is the position the search scores its finalists at once the opponent's reply has been played out. `--every decision` takes every decision a seat makes in a main phase.
- **The hand eval.** `evaluate(state, seat, next, &AI_EVAL)`, with `next` the swing rule `reply_score` applies: `NextSwing::Seat` when the seat is the one to act, `Enemy` otherwise. It is computed on the true state. The search computes the same score on a determinized world, which the seat cannot tell from the true state, and the true state is one such world, so the row holds a score the search could have given there. The network takes it as an input with a skip connection (`docs/learned-eval.md`, D4): it learns only what the hand eval misses. The features never read the true state.
