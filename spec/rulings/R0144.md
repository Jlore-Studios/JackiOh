id: R144
title: Fixture accounts are reseeded per run
cards: "§9.4"
proven_in:
  - crates/server/tests/api/e2e.rs
---
In end-to-end mode the server reseeds its fixture accounts and invite codes at boot, and again on `POST /api/e2e/reseed`, which spec 10 calls before its first test, so a spec that activates the pending account or spends an invite code is repeatable against one server with no restart. Outside end-to-end mode that route answers as a path nobody serves (404). Without this the invite-gate spec passes once and fails on every later run, which is indistinguishable from a regression
