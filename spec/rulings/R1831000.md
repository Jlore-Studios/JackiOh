Accepting a friend's challenge was joining its room by its code with the lobby opened and the code filled in ([[R767]]): the friend left the screen they were on, picked a deck and pressed Join. Issue #1831 does it from the toast. The toast shows the challenge's mode and a picker for the deck, or for the trio in Conquest, which starts on the pick last used for that mode in this browser, else the first complete one (the first saved when none is complete, as the lobby picks, and the server refuses it if it may not be played); Accept joins the room by its code with that pick, which marks the challenge accepted as before, and goes to the game. An All Random challenge needs no pick, so Accept just joins. On a screen with unsaved work the player is asked first, as before ([[R1754000]]), and the join waits for the answer. If the server refuses the join, a deck it rejects or a challenge gone, the toast shows its words and offers "Open in lobby", the [[R767]] path with the code filled in; with no saved deck or trio for the mode, only that path is offered. [[R767]] still governs room links. The pick last used is kept per browser, not in the settings the account syncs ([[R634]]), and the server still decides whether the deck may be played. Hearthstone goes straight from accepting a friend's challenge to choosing a deck.

Rejected: keeping the lobby as the only way in, which is the steps the issue set out to cut.
