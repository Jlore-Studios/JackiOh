A game is set up in one of two ways. `create_game` makes a game now (`SetupKind::New`) and holds
every seat with no handicap to `DECK_SIZE` ([[R1705000]]), so a new game refuses a 20-card deck
there under L2. `create_recorded_game` builds again a game already made (`SetupKind::Recorded`):
every fold of a log, a match's rebuild and a replay among them, a game's summary, a Glitch reset
([[R676]]), the golden traces, a fuzz corpus record, and each duel of a co-op game folded again
([[§13.2]]).

A recorded game in which some seat with no handicap holds exactly `EARLIER_DECK_SIZE` (20) cards was
made before `DECK_SIZE` became 25. Its seats with no handicap are held to 20, and a handicap equal to
a human's at 20 is not stored, as it was not when the game was made ([[R180]]), so the game is dealt,
hashed and folded exactly as it was played and reaches its recorded hash. Every other recorded game
is held to `DECK_SIZE`. A seat with a handicap is held to its own `deckSize` either way ([[R184]]).
The size is read from the decks the record holds, so it needs nothing the record does not carry.

Hearthstone semantics: a game is played, and played back, under the rules it began under; a patch
changes the games made after it and leaves the ones before it as they were.

Rejected: the issue's own proposal, keying the size on the catalog version a game folds under
([[R767000]]). The golden traces carry no version, and a rule-only change goes live when it merges,
before `patches ship` moves the version, so games made at 25 and at 20 would share one.
