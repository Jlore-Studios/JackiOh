A `KEPT_SCRIPTS` row ([[R767000]]) is keyed by a shipped version or by `"fragment:<stem>"`, the stem of the pending fragment that ships the change (its file name in `crates/cards/patches/pending/` without `.json`, [[R1366000]]). `patches ship` records on each version it adds the stem it came from (`fragment` in `patches.json`, [[R388]]); a cut, which ships no fragment, records none. The build carries that map, and its history resolves every key once as it loads, before any fold reads one: a version stands for itself; a stem a shipped version names stands for the version just before the first that names it, so of one ship of V1 then V2 the second fragment's key is V1 and the first's the version before V1 (a stem the very first version shipped from covers nothing); and a stem no shipped version names yet stands for the newest shipped version, since every version shipped so far ran the script it keeps. A branch's row therefore covers every version shipped while it was built or sat in the merge queue, and the earliest kept at or after a game's version is read off the resolved keys. `cargo jackioh patches check` fails a key that names neither a shipped version nor a pending or shipped fragment, so a typo cannot read as pending forever, and a pending fragment whose stem a shipped version already names, which takes another title. Rows keyed by a version before this stay as they are. Rejected: `patches ship` rewriting each key in `history.rs` into a version, which would edit the lines queued card branches append beside and conflict in the merge queue; a `classify` check that a branch's new row names the base's newest version, which never runs in the merge queue, where versions ship under a waiting branch, and leaves every catch to a re-key; and inferring a row's version from the shipped `plays` and `changes`, which are incomplete (v0.6.9m shipped issue #4423's Corpse Eater change without listing `core-089`).
