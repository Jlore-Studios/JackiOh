A seat of a co-op match whose row has an `ended_at` may open `/ws/duos` onto it, while the server holds no actor for it, only while no more than `REMATCH_OFFER_TTL_MS` has passed since that `ended_at`: the window a finished 1v1 match's socket reopens in ([[R1285000]]), counted the same way. Past it the seat is refused as a profile that holds no seat is, not found (4404, [[§13.9]]), and no actor is rebuilt, so no old log is folded and no report is filed for a game recorded under rules since changed ([[R1156000]], [[R767000]]). The game stays in its replay, which either seat still opens. An actor still in memory keeps its sockets as before, and a live match, one with no `ended_at`, attaches as before. Hearthstone semantics: a finished game's board goes when its end screen is left, and it is seen again only as a replay.

Rejected: refusing every finished co-op match with no actor in memory, which would shut both seats out of the end screen after a server restart during it; a co-op constant for the window, since the rematch window already is one; 4403 as [[R1285000]] answers a 1v1 seat, since the co-op socket answers every seat it will not attach not found ([[§9.1]]); keeping a finished co-op actor in memory through the window as the 1v1 reaper does, which the issue left optional: a reconnect inside the window folds the log again, as it did before.
