Amends [[R388]] and [[R646]]: a patch's snapshot is still the whole catalog as that patch left it, but no version keeps it as a file of its own. Each shipped version keeps `crates/cards/patches/deltas/<version>.json`, `{ set, unset }`: the entries whose bytes differ from the version before it in `patches.json`'s order, whole and key order included, and the ids it removed; the first version's delta sets every card. `crates/cards/patches/order.json` lists every card id a version ever shipped, in the one order every snapshot lists its own. A version's snapshot is the fold of its delta and every one before it, its cards in that order, and every reader folds the same way: the tools (`read_snapshot`), the cards crate's build of the carried history ([[R767000]]), the server's `GET /api/catalog/:version` through it, and the client's patch source. `patches ship` writes each version's delta against the snapshot before it, `patches cut` an empty one ([[R3944000]]), and `patches retcon` moves a delta to its new name ([[R1371000]]). A version may add and remove cards but never move a shipped one: `patches check` fails on a catalog that lists shipped cards in another order than `order.json`, and on any `<version>.json` whole-catalog snapshot under `crates/cards/patches/`, which `cargo jackioh patches encode` turns into its delta (it proves each fold before it deletes a file, and a second run changes nothing). `shipped.json`'s `blob` stays the git blob hash of the snapshot's bytes, now the bytes the fold rebuilds (the catalog pretty-printed as `patches ship` writes it, with its final newline, or without it for the versions shipped while `catalog.json` ended without one); shipped entries are never amended, so v0.4.0b, v0.4.0c and v0.4.0d, whose files were formatted by hand, keep the blob of their original bytes, which git keeps under it, and fold to the same JSON. The 286 snapshots kept as files until this ruling were 8.1 million lines; their deltas are 115 thousand.
