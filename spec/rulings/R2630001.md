A gated screen that calls the engine waited three times in a row: for `GET /api/auth/me`, then for the engine's WebAssembly module (`EngineGate`, about 4.1 MB gzipped), then for its own code, since each was asked for only once the one before it had answered. [[R2116000]] already starts both on intent toward a link; a direct load, a reload or a redirect had nothing to start them.

A gate now starts its screen as it mounts (`startScreen` in `routes/chunks.tsx`): the screen's code always, and the engine's module when the route marks the screen as one that calls it (`<Gated engine>`, every gated route whose screen opens with `EngineGate`). The account read starts first and the two loads beside it. Both loads are the ones the screen makes anyway, shared, so nothing is fetched twice, and a failed early download is the screen's to report and retry as before. The player is going to the screen, so saving data does not hold either back, as it holds back a prefetch on intent. With no session stored the gate sends the player to sign in, so nothing starts.
