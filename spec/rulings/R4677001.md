Presentation only (CLAUDE.md rule 7): the dialog lists what `GET /api/stats/cards` sends ([[R1973002]], [[R4677000]]) and decides nothing.

**Why.** The patch bar's tabs offer the newest patch and the five newest with enough games ([[R3324000]]); any other patch was reachable only by typing `?patch=` into the address. The owner asked for a search that opens any patch the caller may read.

**The button.** One button, no more: a magnifier at the patch bar's end, after its arrows ([[R4674000]]), named "Find a patch" in its `aria-label` and its `title`. The bar stays one row on a desktop.

**The dialog.** It opens a `Dialog` ([[R3221000]]) titled "Find a patch":

- A text box filters the patches by version: a patch is listed while one of its versions, micros included, holds what is typed, a leading `v` read as nothing, so `0.5.8` finds the patch holding v0.5.8 (as `patchIndex` reads a version, [[R1973001]]). An empty box lists every patch; one that matches none says so.
- The patches are listed newest first, grouped by line under its name (v0.6, v0.5, …), each with its name and its games, or "Collecting data" for the newest patch while it is short of games ([[R3324000]]). The patch shown is marked current.
- Picking one shows it as a tab does: `?patch=` in the address (none for the newest), and the bar shows it as the shown patch, a tab of its own when it is not one already. The dialog closes.
- For anyone but a dev account (`olderPatchesForDevs`, [[R4677000]]) the dialog ends with one line, "Older patches are for dev accounts.", and never lists a patch the server refuses. An address naming a refused patch opens on the current patch with that same line under the bar.

Hearthstone semantics: a stats site's patch picker is a searchable list of its patches.

Rejected:

- A second row of controls or a dropdown in the bar: the tracker allows one button (#4670).
- Matching on the patch's name alone: a micro would find nothing, where the page reads a micro as the patch that holds it.
