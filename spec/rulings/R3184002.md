Presentation only (CLAUDE.md rule 7): no rule, state, event, endpoint or response changes.

**Why.** The Created cards table ([[R2089000]]) listed its rows in the server's order alone (enough games first, then the most games, then by name), so no reader could rank them by a figure. The owner asked in #3184 for every column to sort.

**The sort.** Each header (Card, Games, Used, Not used, Used Radiant, Used normal, Used vs not used) sorts the rows by its column:

- **A press:** the first sorts descending, or ascending for the card's name; the next flips it. Enter and Space press it, as on the deck table's headers.
- **Its mark:** an arrow on the sorted header and its `aria-sort` set, every other header's `none`.
- **A figure the row does not show:** a rate below [[R654]]'s floor or with none, or a delta the server withheld, sorts after the rows with one either way, as on the deck table. Rows that tie keep the server's order.

Until a header is pressed the rows keep the server's order. The sort is the table's own and is not kept in the address.

Rejected: keeping the sort in the address as the deck table's is, since `?sort=` already names the deck table's and a second key would only matter to a link nobody shares; and sorting a rate below the floor by its hidden figure, which would rank rows by numbers the page does not show. No Hearthstone rule is involved.

Amended by [[R3324002]]: the Tokens and the Other created cards are one table with a Win rate column, and each opens sorted by Win rate, best first, not in the server's order.
