The daily super run (`.github/workflows/super.yml`) tests the whole game on `main` once a day, and said how it went only in the `CI: daily super run failed` issue it opens on a red run. Its runs are now on the public statistics page, live, beside the cards and the players.

- **What is shown.** The Daily runs tab lists the last `CI_RUNS_LISTED` (14) runs of `CI_RUNS_WORKFLOW` on `CI_RUNS_BRANCH`, newest first, as GitHub lists them: when each started, its commit, shortened to seven characters, and its result. A run is running until it finishes; a finished one passed when GitHub concluded `success` and failed for any other conclusion, cancelled and timed out among them, as the workflow's own report counts a run red. For a failed run the tab lists each job that finished and did not pass, with GitHub's conclusion beside it; success, skipped and neutral pass, as in that report. The run and each job link to GitHub.
- **The insights.** Above the runs the tab sums up the finished ones, a running run having no result yet: how many passed of how many finished; the streak, the newest finished run's result and how many finished runs in a row share it; and the job that did not pass in the most of them, with in how many, a tie going to the newer run's job and a job counted once per run. With no failed job it says nothing failed.
- **The route.** `GET /api/stats/ci` is open, and its body is `{ runs: [{ id, url, startedAt, commit, result, failedJobs: [{ name, url, conclusion }] }] }`: only what GitHub shows anyone about the public repository.
- **Live, and kept.** The server reads the runs from GitHub's Actions API at most once per `CI_RUNS_CACHE_TTL_SECONDS` (120 s), as [[R1583000]] keeps the play rates: requests that miss together wait for one read, a read that fails is kept for no one and answers `unavailable`, and the response's `Cache-Control` max-age is as long. A finished run attempt's jobs never change, so they are read once and kept while the run is listed. The open tab asks again every `CI_RUNS_CACHE_TTL_SECONDS` and stops when another tab is chosen; a refresh that fails keeps the runs it showed, and a first read that fails offers Retry. Without a token GitHub allows one address 60 reads an hour, so the server reads with `CREATE_ISSUES_TOKEN` when one is set. The end-to-end server reads nothing and lists no run.
- **Rejected.** The night bot's status issue: it is the bot's, and players never see it. The client reading GitHub itself: the site's content security policy reaches only its own server, and every viewer would spend GitHub's allowance. A running run's failed jobs: a fail-fast run cancels the rest, so its jobs are read once it has finished.
- **Off the page.** [[R1973000]] took the Daily runs tab and its insights off `/stats`. `GET /api/stats/ci` stays, as it was, for whatever calls it (CLAUDE.md rule 13).
