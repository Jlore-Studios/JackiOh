[[§9.5]]'s room had no life past its creation: the code lived only in the host's page, so a reload lost it, the room stayed joinable until it expired, a joiner met "the host of that room is playing another game right now", and the room held one of the host's open-room slots ([[R890000]]). As Hearthstone's friendly challenge can be withdrawn before it is accepted, the host may close a room nobody has joined, and the lobby lists the host's open rooms back to them:

- `DELETE /api/rooms/:code` frees the code at once ([[R110]]), drops the room's end-to-end seed ([[R143]]) and frees a slot of the open-room cap ([[R890000]]). It answers `200 {cancelled}` and is idempotent, like leaving the queue: `false` when the code holds no unjoined room. A joined room is never touched, even when the join races the cancel. Another player's room is `404`, the miss an unknown code gets in a join. A room a friend's challenge holds is `409`, because its challenge's cancel frees it.
- `GET /api/rooms` answers the caller's own rooms nobody has joined and whose time has not run out, newest first, as `POST /api/rooms` answered them, never a challenge's, and at most `MAX_OPEN_ROOMS_PER_HOST` of them.
- A lobby that opens with no queue wait and no room link shows the newest of those rooms as a ticket again, with its copy actions and a Cancel room button.

Rejected: an `openRoom` field on `auth/me`, which every screen polls, for what only the lobby reads; showing every open room, which a lobby holding one ticket at a time never makes.
