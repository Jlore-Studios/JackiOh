[[§9.13]] says nothing of a daily game when one of its players deletes their account ([[§9.4]]). A daily game sets no in-match flag ([[R3727004]]), so `DELETE /api/account`'s refusal in a live match let it through, and in Postgres migration 0012's `matches_seats_filled_unless_over_check` then refused the delete, since the match would lose a seat mid-game, which surfaced as a 500, while the in-memory store let it go. A running daily game now holds its account as a live match does, and as a live co-op match does ([[R1497000]]): `DELETE /api/account` first ends on time each of the account's daily games whose move has run out ([[R3727000]]), then answers 409 `conflict`, deleting nothing, while any still runs, so its player finishes or concedes it first. Should a game start in between, 0012's check refuses the delete in Postgres, and the in-memory store refuses it too. Once a daily game is over the delete goes through as for any finished match. The age screen's deletion of an account under the minimum age ([[R757000]]) shares the refusal; it only ever meets a pending account, which plays no daily game.

Rejected: conceding the account's running daily games for it as it goes, which would hand its opponents wins they did not play for and make the server send moves no player made; and letting the delete through by emptying the seat, which would leave a game with one player and nobody to lose it on time.
