Every shipped catalog version is renamed to what the classifier ([[R1365000]]) would have called it, by `cargo jackioh patches retcon`. The map is computed, never written by hand: in `patches.json`'s order, each version's tier is the classifier's stage 1 over its snapshot and the one before it, each with the sets its cards belong to, as `patches ship` reads a patch ([[R1366000]]), plus the card scripts its own shipping commits changed, from the Rust scripts on. A script change counts only beside a catalog change in the commit that shipped it, so the mass rewrites, which shipped in no patch, claim nothing; versions from before the Rust scripts are read from their snapshots alone. The names follow with `name_by_tier` from v0.1.0, the first major. The dry run prints the map; a person approves it before the write.

Old and new names overlap (the old v0.3.4 is the new v0.2.7b, while the new v0.3.4 is the old v0.3.12), so a bare name cannot say which it means, and every stored name is renamed exactly once, in one release: the repository's patch history, version sites, data files and the string literals of its code and tests (never its comments or docs, which keep their old names; `docs/issues-and-patches.md` holds the map to translate them); the database in one migration that renames each column in one statement joined to the map; and the record files outside the repository by `patches retcon --records <dir>`.

**The marker.** A file the build writes that names a catalog version says which scheme names it: a downloaded replay and a Duos replay by their format's version (2), and a game-record line, a self-play game, a practice save or kept game and a `cargo jackioh replay` input by `versions: 2` (`VERSIONS_SCHEME`). A file without the marker was written before the retcon and names its versions the old way: its reader maps each through `crates/cards/patches/aliases.json` (the record's patch and the versions its id spells too), once, and only such a reader consults it. The repository and the database hold no unmarked name after the retcon, so neither is read through the map. `aliases.json`'s presence says a tree was retconned, and the command run again changes nothing.

An app bundle cached before the retcon is at an old name no new name reuses (v0.3.15 to v0.3.17), so its catalog check misses and it reloads, as at any catalog bump ([[R105]]).
