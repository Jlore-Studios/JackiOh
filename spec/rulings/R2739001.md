While a player answers an engine card picker in a live match, pointing at an option or giving it the keyboard's focus, the client sends a top-level `{ type: "choiceHover", index }`, `index` being the option's place in the prompt's options or `null` when the pointer and the focus leave them, sent only when it changes, and `null` too when the picker folds or closes. The mulligan, a play's own choices and a replay's read-only prompt send none; the other card pickers (a `hand` or `pick` prompt) do, and the actor drops them, since the other seat is shown no count of theirs. The actor relays it to the opponent alone as `{ type: "choiceHover", from, index }`, and the opponent's backs ([[R2739000]]) outline the one at `index` in the chooser's color, the look of [[R738]]'s marked hand card, still and so the same under Reduce Motion; a `null` clears it.

The parse rebuilds the frame field by field: `index` must be present and be `null` or a whole number of at least 0, read as the protocol reads every whole number, and anything else (a missing `index`, `-1`, `1.5`, `"1"`) is answered `malformed`. The actor drops a hover silently while no prompt of the sender's is open, while the opponent's view of it carries no `optionCount` (a prompt whose count hides something shows no outline either), and when `index` is not under that count. Relays are coalesced per seat to one per `AIM_RELAY_INTERVAL_MS` (100 ms), the newest pending hover going alone when the interval ends. The actor relays a `null` in place of an outline that is up when the prompt it pointed into is answered or replaced by another (before the view that shows it gone), when a later hover is one it drops, when the sender's socket closes, and when the game ends.

An index says only which face-down slot the pointer is over, never what is in it. A hover is never an `ActionBody`, so it reaches neither `reduce`, the log, the replay hash nor a game record, is never part of `PlayerView`, and no rule is decided from it (CLAUDE.md rule 7). Hotseat, practice and replays relay nothing, so their backs carry no outline.

Decisions the issue left open, each with the alternative rejected:

1. It is coalesced by the aim's interval, `AIM_RELAY_INTERVAL_MS`. A twin constant was rejected: both are a pointer's relay, and one number keeps them at one pace.
2. The outline is still. A breathing outline was rejected: [[R738]]'s mark holds still under Reduce Motion, and a still one reads the same everywhere.
3. Duos (§13) relays no aim, so it relays no hover; it is a follow-up should Duos gain the aim.
4. A picker that gives its first card the focus as it opens (an `answer`, a `reward`) outlines that back at once, since the focus is where a keyboard would pick. Sending only a focus a person moved was rejected: telling it from the picker's own would lean on the browser's `:focus-visible` guess.
5. An outline up when the opponent's socket comes back is sent again only once the hover changes, as [[R738]]'s aim is. Sending the last relay on every attach was rejected as a second path for a cosmetic.
