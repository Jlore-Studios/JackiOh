[[§9.4]] step 1's "verified email" is read from the auth provider, and only the **positive** answer may be remembered, briefly and per user id. Caching the yes is safe because confirmation does not go backwards in normal use; refusing to cache the no is what lets an account that has just clicked its link see the code screen unlock at once rather than after a cache window. Asking the provider on every request would put a round trip in front of every authenticated call. A provider that cannot be reached fails closed — the identity stands and the email counts as unverified — so the cache can only ever shorten the path to a yes the provider already gave
