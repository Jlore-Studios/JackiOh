Malformed frames used to be answered one by one with no accounting: each is still answered `malformed` as before, but past `MALFORMED_FRAMES_PER_WINDOW` (10) inside `REJECTION_ALERT_WINDOW_MS` the seat's socket is closed with the policy-violation code 1008. Ten is past what a stale client sends and short of what a flooder leans on, so the close names abuse, not a bug.

The budget is per home seat ([[R137]]'s scope), like [[R109]]'s action budget, and the close is that seat's alone: the opponent's socket is untouched. Closing starts the seat's ordinary disconnect grace ([[§9.5]]), since the close handler runs as any other close. Every `parse_client_message` failure counts, server-only action types included; binary and oversize frames never reach the actor — the pump answers those itself — so they are outside this budget.

The budget holds before a hello too, on the two sockets that wait for one, `/ws/duos` ([[§13.9]]) and `/ws/watch` ([[§9.5]]): their one hello gate answers each frame that is not the hello `malformed` and, past `MALFORMED_FRAMES_PER_WINDOW` inside the window, closes the socket with 1008. No seat is known before the hello, so that budget is the socket's own. After it, a co-op seat's frames are its actor's, which keeps the seat's budget as the match actor does, and a watcher's are dropped unread. The gate waits `WS_IDLE_TIMEOUT_SECONDS` from sign-in for the hello and then refuses the socket (`forbidden`, 4403), so a client that answers pings but never says hello no longer holds a task and one of its address's sockets for as long as it stays connected.
