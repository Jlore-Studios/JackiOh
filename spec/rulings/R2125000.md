A menu screen no longer waits behind its skeleton on every visit: the client keeps the last answer of each menu read, in the tab's memory only, and a screen that finds one draws it at once and reads again behind it.

**What is kept, and its key.** The last answer of the collection, the wallet, the packs, the cosmetic packs, the set tracks, the quests, the owned cosmetics, the tokens, the decks and trios and the ladder (`keptPaths` in `net/api.ts`), of one filter's statistics table (`cardStatsPath`) and of the friends list (`FRIENDS_PATH`). An answer is keyed by its path, the query included, and its account: the `sub` claim of the session's token, so a renewed token keeps its answers while another account never finds them. The statistics table is public, so its key holds no account; each filter keeps its own. At most `READ_CACHE_MAX_ENTRIES` answers are kept, the one kept longest ago going first. Nothing is written to `localStorage`, `sessionStorage` or IndexedDB: a reload starts empty.

**Reads.** A screen with a kept answer starts on it and draws it at once, with no skeleton ([[R2115000]]), reads again and takes the new answer when it lands. A read that fails behind a kept answer leaves it on screen and says nothing: no alert, no Try again. A screen's error is only for a first visit, a visit that has nothing kept. A panel that needs several answers (the wallet's three, the shop's two) starts on them only when it holds every one; half a panel is a first visit.

**Clearing.** Signing out empties the cache, and so does the first answer kept for another account: an account switch never shows the other account's data.

**Writes.** A mutating answer that carries a new value updates its entry, so a revisit never shows the old value first: a bought pack's wallet and counts, an opened pack's pity and counts, an opened cosmetic pack's shard bar and count, a chase bought, a token redeemed, a deck or trio saved, deleted or imported (a deleted deck empties the trio slots that named it, [[R252]]), and a friend accepted or removed. A write with nothing kept for its entry changes nothing; the next read keeps it.

**The decks workshop.** `/decks` opens the workshop on the kept decks and reads them again. Its store is made once, from the decks it opens on, so when the decks that land differ from the ones shown it reopens on them; when they are the same it stays as it is. The player's unsaved edits are kept by the workshop's own store and mirror ([[R256]]).

**Never kept.** What a match, a series, a duos room, a watch or a replay reads, and anything that is not a `GET`. The friends list that the watch and the replay share reads is read without keeping it.

Presentation only (CLAUDE.md rule 7): the answers are the server's, about this account alone and as the server sent them; nothing here predicts, enforces or reveals game state, and no hidden information is ever kept.

Hearthstone semantics: its collection and shop open on what the client last held and update behind it.

Rejected: `localStorage` or IndexedDB, which outlive the tab and a sign-out; a time to live, since every visit reads again anyway; caching every `GET` in `apiRequest`, which would keep a match's and a replay's reads; an error over kept data; keying by the token, since a renewal would empty the cache.
