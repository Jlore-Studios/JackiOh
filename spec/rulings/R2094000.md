A co-op room is shared as a link instead of a bare code: `/together?coop=<CODE>`, [[R767]]'s twin for a co-op room. The room's ticket offers Copy invite link beside the code, which opens the browser's share sheet where it has one and writes the link to the clipboard where it does not, saying "Link shared" or "Link copied"; a share that is closed or a clipboard that is refused says nothing, as the 1v1 room's link button does. The chat invite carries the link beside the code, so the friend can press it instead of typing.

A lobby opened on the link reads it once. `coop` leaves the address bar at once (other parameters stay), so a reload or Back never refills a code that is stale by then. The code is read as a typed one is ([[R191]]): checked against the room code format, six characters of [[R104]]'s alphabet in any case and with any spacing. A code that fails is ignored quietly, with no notice and no error, and one that is stale fails when it is joined exactly as a typed one does. A valid code fills the join form, upper-cased as the Join button sends it, and puts the cursor on Join. It never joins by itself: the joiner still picks a deck ([[R264]] decides, in the server's words) and presses Join. Opening a link changes nothing the server knows.

A visitor who is signed out is sent to sign in first, and the link waits for them in this tab only (`sessionStorage`, [[R632]]), as the code alone and never a path, and the next Play together uses it once and forgets it: back to the menu and in again, the form starts empty. A signed-out visitor still has the code after signing in, as a `/play` link does (B35).

The join deck starts on the last co-op pick the tab remembers, when that deck is still saved; else on the first saved deck; else on a random deal. A pick the player makes is remembered, and a room made or joined remembers its deck, so joining from a link is one press.

A message holding a room link of this site draws a Join button under its text: this origin's `/play?room=…` (as [[R767]]'s `roomLinkOf` reads it) or `/together?coop=…`. The button opens the link inside the app, adopted as if it had been opened: a 1v1 link opens `/play` with the code filled where the joiner picks a deck and presses Join, and a co-op link opens Play together with the join form filled as above. The message itself stays text, never markup: the button is built from the parsed link, never from the message's substrings. A link to any other origin, or a malformed one, draws no button.

This is presentation only. No endpoint changes, no rule changes, and the client enforces nothing: it fills in a form and the join route decides ([[§9.5]], [[§13.9]]).
