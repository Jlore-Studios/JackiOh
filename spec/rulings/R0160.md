Sign-up and sign-in answer identically for every outcome that depends on **whether an account exists** — no such account, wrong password, already registered — so neither becomes an account-enumeration oracle. This is [[R145]]'s principle one door earlier: [[R145]] makes the redemption error identical for everything that depends on the code and distinct for what depends only on the caller's own account, and an email address is exactly the fact an unauthenticated caller must not be able to probe. [[§9.8]] asks the invite gate to resist enumeration, which a sign-up endpoint answering "that address is taken" undoes. One error per endpoint, not one shared between them, since the route already distinguishes them. [[R192]] names the one carve-out: sign-up's own 429 for the provider's mail interval, which says that an unconfirmed sign-up for the address was mailed in the last interval
