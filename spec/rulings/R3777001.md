`legalActions` offers an enemy face-down backrow card as a declared target by its id alone
([[R177]]), but the view draws it as a back with no id ([[§10.8]], [[R33]]), so a client had no way
to tell which zone that id lies in: the board lit nothing for #36 Magic Jammed aimed at a face-down
card, and a click on the card's zone matched no listed play.

The `PlayerView` now carries `hiddenTargets`: for each card the viewer may not read that one of the
viewer's own listed plays, activations or Heroic Powers names as a declared target, its `instanceId`
and its `zone` (`{ player, row, lane }`). Nothing else of the card goes with it. The id is the one
`legalActions` already sends the same seat, and the card took it fresh as it was set ([[R227]]), so it
names nothing the seat did not already hold; the zone is public, since both players see the card's back
lie there. It is the position a prompt option offering a face-down card carries ([[R821000]]), given to
the declared targets a play is built from. The key is absent when there is none, so every other view
is what it was, and it is empty while a prompt is open (a prompt's options name their own zones). It is
read off `legal_actions`, which stays the one answer to which targets are offered; the golden fixture's
view texts leave it out, as they leave out everything that only dresses the view. The fuzz monitor's
hidden-information check (I6) lets the view name a hidden card's id at `hiddenTargets[n].instanceId`
only while the listing it is checked beside offers that id, and nowhere else ([[R97]]).

The client lights the zone of each listed target it may not read while a play is built, as it lights a
card it may read, takes a click or a drop on that zone as the pick of that id, and its target picker
lists it as "Face-down card" and where it lies.

Rejected: an `instanceId` on every face-down back in the view, which would make [[§10.8]]'s face-down
marker (unknown but for its cost) carry more and name ids no action offers; and a `zone` selection for
a backrow target, which would change the protocol and every recorded log that names the card by its id.
