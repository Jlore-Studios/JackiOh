The log ([[§10.10]]) shows the whole game, not only the view's last N events ([[§10.8]], [[R168]]), which are sized for animation. The client joins each view's window to the last one the same viewer was shown, with the animation runner's own diff (`newEventsSince`), and keeps a line whose event has left the window as it read when the event arrived: its words and the face of the definition it names, never an instance id, so it holds only what a view once said and follows no card into a hidden zone ([[R97]], [[R223]]). A line still inside the window reads from the current view. Each viewer has its own history, so hotseat's two seats never share one; a new game starts it empty; it holds at most `LOG_HISTORY_LIMIT` lines (1000), the oldest dropped first; a divider stands before each turn's first line. A view that shares no event with the one before (a reconnect after a long drop, [[§9.5]], or a board that caught up past a whole window) cannot be joined: the log keeps what it had and says in one line that events may be missing there. Presentation only: nothing reaches the engine, the view or the wire (CLAUDE.md rule 7)
