Each card the learned evaluation's features name by id ([[R1006000]]: a unit on either board, a card in the seat's own hand, a card the seat can read in either backrow) also has the sparse keys of what it is (`attributes`, `crates/ai/src/features.rs`), in its zone (`board`, `hand` or `backrow`) and on its side (`own` or `enemy`):

- `<zone>.type:<side>:<type>`, its running face's type ([[§5.2]]; `card_type_of_face`, so an animated card on the board names the type its face prints);
- `<zone>.cost:<side>:<n>`, its printed cost as every definition is read ([[R65]]'s `query_cost`: an embiggen card's base, an X card's 0);
- `<zone>.tag:<side>:<tag>`, one key per tag;
- `<zone>.kw:<side>:<keyword>`, one per keyword of its running face, counted as the dense keyword counts count it (Brittle N and Spell Damage +N count N);
- `<zone>.attack:<side>:<n>` and `<zone>.health:<side>:<n>`, its running face's printed attack and health, when it has them;
- `<zone>.face:<side>:Radiant`, when it is Radiant.

A number is clamped to 0 to `ATTRIBUTE_TOP` (10): a card at 10 or more names 10. The printed numbers are the card's; the dense features already hold what the units on the board are now ([[§10.4]]'s layers). A Radiant card in the seat's own hand keeps its `hand_radiant` key ([[R1012004]]) and has no second set of attribute keys. A card with no id key has none: the enemy's hand is a count and a hidden backrow card is counted, never read ([[R185]]). Two copies of a card, or two cards that share a key, add up in that key's count.

A card the network has no id row for, a new set's or a custom one's (#915), so still moves the evaluation through the keys it shares with the cards the network was fitted on, until a refit gives it a row of its own. This is `FEATURES_VERSION` 3.
