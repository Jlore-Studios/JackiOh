Issue #39 (2026-09-30) asked for card patches to be tracked, retroactively too, so older versions of cards can still be read (docs/classic-sets.md B4.2), and its first build landed on main beside patch v0.2.0's own ([[R388]]). When the two met, [[R388]] and [[R507]] kept the rule and the first build (`snapshots/`, `changes.json`, `src/history.ts` and the client's `History.tsx`) was removed, so this row now only fixes what both agreed on: the versions before v0.2.0 are, in order, v0.1.0 (the initial commit), v0.1.0b (the balance changes of issue #1), v0.1.0c (#95's text and The Coin), v0.1.0d (the Radiant pass, [[R275]]–[[R279]]) and v0.1.1, the first four labels given later to states git recorded (the three revisions were v0.1.0-r1 to -r3 until #85 gave a revision a letter, docs/issues-and-patches.md); the order of versions is `patches.json`'s, never a comparison of version strings; and the newest version's name is what every game record is filed under ([[R376]]). Patches may ship out of name order (issue #63): a version's place in `patches.json` is fixed by when it lands on `main`, whatever its name, so v0.2.0 landing after v0.2.5 reads after it and its snapshot includes v0.2.5's changes; names were the designer's labels until [[R743]] numbered the card patches in order, a shipped version never reopens (a follow-up ships as `vX.Y.Zb`, then `c`, and so on), branches build as pending fragments under `patches/pending/` ([[R646]]) and never edit the history, and the current version — the site footer, the patch a game record is filed under — is the newest entry, which between a merge and its promotion is still the previous patch
