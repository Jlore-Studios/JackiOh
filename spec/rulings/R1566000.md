[[§13.8]] says the menus' banner offers the way back to a co-op game as it offers a live match
([[R765]]). But that banner reads only `GET /api/auth/me`'s `currentMatchId` and `currentSeriesId`,
and a co-op match sets neither ([[R1065000]]). This amends [[R765]], which changed no endpoint, and
edits [[§13.8]] to cite it.

**The account read.** `/api/auth/me` answers `currentDuosMatchId`: the newest live co-op match holding
the caller in either seat, the same answer `GET /api/duos/live` gives. It is null when there is none
or once the match has ended. Like `currentMatchId`, it holds only the caller's own match.

**The banner.** While it is set, the main and practice menus show [[R765]]'s banner. It says the
player is in a co-op game and that the AI plays their seat once they are away
`DISCONNECT_GRACE_SECONDS` ([[§13.8]]), and **Rejoin** links to `/duos/<id>`. It is read again every
`SERIES_POLL_SECONDS` and goes once the game is over. A match or series comes first, though
[[R1065000]] lets no one hold both.

**The hub's refusal.** On the Play hub, an `already_in_match` refusal that names the co-op match
(`details.duosMatchId`, [[R1065000]]) shows the server's sentence and a link to the game, as a
refusal naming a series links the series screen.

**No pairing.** A co-op game starts from a Play together room that takes both people to it
([[§13.9]]), so it is no pairing. The queue follow ([[R765]]) and the hub's take-back on opening
([[R1578000]]) keep to the match and the series. A co-op player who opens the hub stays there, and a
refusal links them back.

Hearthstone semantics: offer to reconnect to a game in progress. Rejected: reading
`GET /api/duos/live` on each menu, when the account read can carry it. Rejected: following a co-op
game from the queue follow, which would announce "Match found!" over the board the room's join
already opened (its start cancels the ticket, [[R1065000]]).
