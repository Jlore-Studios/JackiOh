A dungeon run's Combat artifacts give the human's hero Armor for each fight ([[R2922001]]), and a
handicap ([[R180]]) had no field for it. So a handicap takes one more optional field, `heroArmor`:
the Armor that seat's hero starts the game with. Hearthstone lets a hero start with Armor, and here
it is the hero's own Armor (`HeroState.armor`), the Armor C+ #46 already leaves on a hero for the
rest of the game: [[§4.4]] step 2 takes it off every hit, it adds to every other source of Armor
([[R124]]), and nothing spends it. It is not Hearthstone's pool that a hit uses up, because
[[§6.1]]'s Armor reduces each hit and this is that Armor.

It must be a non-negative integer (`validate_handicap` refuses a negative one, naming the field and
this ruling). 0 means none, and, like `heroHealth` ([[R290]]) and `heroFloor` ([[R2201000]]), it is
serialized only when set and stored only above 0, so no other game's state, hash, replay or golden
trace moves. A Glitch reset rebuilds the game from the stored handicap, so the hero starts the new
game with it again. No tier and no lesson sets it; only a run's fight does ([[R2922001]]).
