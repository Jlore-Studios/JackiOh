A trio is shared as a code: `JKT`, `TRIO_CODE_VERSION`, a dot, then base64url of the trio's name, one byte saying which of its three slots hold a deck, each of those decks as [[R255]] writes one (its name, then its cards as catalog numbers, each carrying its set), and one checksum over all of it. Since patch v0.2.0 `TRIO_CODE_VERSION` is 2, its decks written as [[R255]]'s version 2 writes them, and a version 1 code is read as Core numbers. Input longer than `TRIO_CODE_MAX_INPUT_LENGTH` (2048) is refused unread, as are a wrong prefix, a version other than 1 or 2, a slot byte naming a fourth slot, a payload that declares more than it holds or holds more than it declares, and a failed checksum, each with its own sentence; a deck code pasted as a trio code, or a trio code as a deck code, is sent to the other import. Each deck is read as [[R255]] reads one — what no deck could hold dropped and listed, unowned cards kept and marked — and a name D1 or T1 would refuse arrives as "Imported deck" or "Imported trio". Decoding never throws. The code is the client's, as a deck code is; the server checks what an import sends ([[R341]])
