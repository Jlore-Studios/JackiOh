**Why.** [[R4965000]] bounds what the snapshot [[R3067000]] keeps, but not what it reads. To fold every deck card's play versions before the run it keeps as filed, a load reads and decodes nearly every row of `card_totals`. The table gains a few thousand rows for every version main ships, micros included, in both databases, because the gather lane files each version it plays into staging's and production's statistics. The snapshot is loaded again at every server start (the bot pool's refresh reads the win-rate snapshot, [[R3049002]]) and every `CARD_STATS_CACHE_TTL_SECONDS`. The container sleeps after five idle minutes, so nearly every visit to `/stats` waited on a load whose cost grew with every version shipped, all inside the client's `API_REQUEST_TIMEOUT_SECONDS` on a quarter of a processor. On 2026-11-27 `/stats` stopped loading again, the third time in four days (issue #5129, issue #5174).

**What a load reads.** A read of the snapshot names its reach (`api::stats::Reach`):

- **The versions kept as filed** (`Reach::Kept`): the cards, the game figures, the drill-down's history and drills, and the win-rate snapshot every match and the bot pool's deals start with ([[R3049000]]). Its filing folds no play version, so the store reads those versions' rows alone, through `card_totals`' primary key (`CardRows::patches`): its cost is the versions the page shows, not every version filed. These figures never read a total before the run ([[R4965000]]), so they are the same figure for figure.
- **Those and the older play versions folded** (`Reach::Folded`): the play versions' table ([[R4675001]]) and the Hall of Fame cut from it ([[R4681001]]), which sum every version a play version spans. This is the one read that still goes over every version's card totals, and it is made only when one of them is asked for.

**One time for both.** When the play versions' table asks first, its snapshot is the one every read takes, so nothing is read twice. When it asks after a read of the kept versions, its snapshot is made beside that one under the same time. Everything cut from either is then kept, and dropped, together, so no figure is older than `CARD_STATS_CACHE_TTL_SECONDS`, as [[R3067000]] has it.

A dev account's older patch ([[R4965000]]) reads its own reach through the same list of patches.

Amends [[R4965000]] (what the snapshot reads, beside what it keeps).

Hearthstone semantics: Hearthstone settles nothing here.

Rejected:
- Keeping the folded play versions in the database, refreshed as records fold: a migration, and a second copy of the totals to keep true. The read on demand costs the Experimental tab alone.
- A longer `CARD_STATS_CACHE_TTL_SECONDS`, or loading in the background and serving the old snapshot: the container sleeps after five minutes, so a new process loads from nothing whatever the TTL. Holding two snapshots during a refresh also doubles the peak [[R4965000]] bounds.
- A larger instance: a billing decision for the owners, and it only moves the limit.
