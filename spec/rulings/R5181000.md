Tipsy X is now **Woozy X**: only the name changes, and the counter, its decay, the stamp and the blur stay
[[R3548000]]'s and [[R3548001]]'s. Every card that printed Tipsy prints Woozy, in English and in Chinese
(晕乎 for 微醺). The keyword kind, the glossary, the client's words and chip (WZ), and the engine's
module, constants, types and fields name the new word, as does every test that named the old one.

The keyword kind is renamed as Magnetic was renamed Equip ([[R781000]]): the shipped snapshots print
Tipsy, and the kind reads `Tipsy` as an alias of `Woozy` and never writes it.

What a game writes keeps the old name, so nothing recorded or compared before the rename changes:

- **The state.** The replay hash runs over the serialized state, and every game that played the keyword
  before the rename was filed with a final hash over the key `tipsy`, both the player's counter's and a
  card's stamp's. The engine calls both fields `woozy` and stores them as `tipsy`, so a stored replay
  folds to the hash it was filed with.
- **The views and the events.** The side's counter is sent as `tipsy`, a card's blur as `tipsyBlur`, and
  the counter's kind on `counterChanged` as `tipsy` (`CounterKind::Woozy`). A view and an event list are
  the same text they were, so a client still on the older build reads them, and `classify`'s replay of
  the same games on the build before ([[R1365000]]) blames only what the new words reach: a fused
  definition, which carries its ingredients' words, so a unit a Woozy Fruit fused into reads Woozy there
  and its patch claims it as playing differently.
- **The blur's seed stream** keeps its key, `:tipsy-blur`, so a replay of an older game blurs the same
  words it did.

The only traces of the old name are the shipped snapshots and their player notes, the keyword kind's
alias, those keys and the counter kind's literal (with the generated client types that spell them), the
seed stream's key and one history line in [[§6.1]]'s Woozy row.
