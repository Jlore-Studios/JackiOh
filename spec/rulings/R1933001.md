Not a rule of the game: where each site's card statistics are filed, and so what production's
public figures count.

The development lanes, the gather lane and the learn lane's import ([[R1976000]], [[R1676000]]),
file each file into both projects' databases: staging's through `STATS_IMPORT_DATABASE_URL`, then
production's through `PRODUCTION_STATS_IMPORT_DATABASE_URL`, each where its secret is set. Each
database claims a file by its SHA-256 on its own (`game_record_batches`), so a run that failed
between the two files, when run again, only where the file is missing. The development rows filed
before this were copied into production once, on 2026-11-03 (`cutover.yml`, step `dev-stats`,
which replaces production's development rows with staging's and can be run again whenever the two
may have drifted). Live rows are each site's own, as before.

So production's figures are read as staging's are: below `PUBLIC_STATS_MIN_LIVE_GAMES` (1000) live
games on a patch, [[§9.11]]'s gate pads them with the development games, labelled provisional
([[R661]]), and at 1000 the gate counts live games alone. `winrates-refresh.yml` reads production
through `STATS_DATABASE_URL`, a read-only login (`stats_reader`) that no import uses, so
[[R2386000]]'s provisional refresh has development games there to cover a new set.

The owner's decision (2026-11-03): with fewer than 100 players online at once, a patch seldom
reaches 1000 live games before the next one ships and its count starts again ([[R1367000]]), so
under [[R1933000]] production's `/stats` would say "not enough games" nearly always and CN Tech's
and NA Tech's table could never cover a new set.

Rejected:
- Pointing `STATS_DATABASE_URL` at staging's database. It fixes only the win-rate table, leaves
  `/stats` on jackioh.com without figures, and mixes the testers' games on staging into it.
- Copying the development totals into production once, without filing on. It pads the patches
  already gathered and no later one, so the figures' basis would change from one patch to the next
  (as [[R1933000]] said).
- Keeping [[R1933000]].
