**Why.** [[R2982000]] sent Claim all as one claim per entry, one after another. Each claim was its own
request and its own transaction under the account's turn and lock, about twenty statements to the
database each, and every answer carried the whole board. With some fifty entries live in a
`NEWS_TTL_DAYS` window, one press waited on fifty requests and about a thousand statements in turn, and
the owner found it laggy.

**The route.** `POST /api/news/claim-all` is a spend of the economy ([[§14.11]]). It claims its account's
turn ([[R2378000]]) and takes an optional `Idempotency-Key` ([[R2124000]]) kept under its own route, so
the same key sent to one entry's claim is another request, 422. Under the account's economy lock
([[R1301003]]), before any check, a key the account committed answers what it answered then. It takes no
list: the server claims every entry live now ([[R2875001]]) and every dev post standing now
([[R3074003]]) that the account has not claimed, the same test one entry's claim puts to it
([[R2875000]]), so nothing the client sends changes what is paid. While `ECONOMY_LIVE` is off it is
refused with 409 and writes nothing, and a pending account is refused as on every economy route.

**One transaction.** The claims are written in one statement, and the key of `news_claims` decides what
is paid: only an entry whose claim that statement wrote. Then one statement per ledger pays them: the
wallet moves by the sum of the Jlore rewards and each inventory item by the sum of its own, and each
entry still writes its own ledger row with the reason `news` and its id as `ref`, so the ledgers read as
if each had been claimed alone. A post pays nothing. However many entries there are, the transaction
costs the same few statements. With nothing left to claim it writes nothing and answers the board.

**The client.** One press sends one request, and while it is out every Claim and Claim all wait
([[R2378000]]). Its answer replaces the list, so the bookmark's count moves once, to what the server
says ([[R2875002]]). A refusal claims nothing and shows its reason. The wallet is announced once for a
press that paid Jlore ([[R2982000]]).

Hearthstone semantics: a collect-all collects everything in one go.

Rejected: keeping one claim per entry and sending them side by side, which the account's one turn at a
time ([[R2378000]]) would refuse past `ECONOMY_SPENDS_WAITING_MAX`, and which would still cost a
transaction each; a list of ids from the client, which would add a check of the client's list and
change nothing the server does not already decide; and all or nothing, which would let one entry that
expired mid-press keep the rest from being claimed.
