The production build writes `dist/version.json` beside `404.html`, naming its entry script
(`static-pages.ts` `VERSION_FILE`): the script Vite names by its content hash, so a build's entry
differs from every other build's. `/version.json` is served `no-cache`, so a tab that loaded
before the deploy reads the new name.

A tab checks for the next build when it wakes (its tab shows again or the network returns,
`game/net.ts` `pageWake`), at most once per `UPDATE_CHECK_MIN_MS`, and only in a production
build: the dev server and a preview check nothing. A different deployed entry than the running
one sets the update as waiting. A failed fetch, a missing file, the same entry, or a check
inside the window changes nothing and sends no request.

With an update waiting, the next move from one menu to another is a full page load to the
target (`location.assign`, `location.replace` for a `replace`) instead of the in-place push, and
the player lands on the screen asked for, up to date. The leave guard ([[R1754000]]) still holds
the move first, so unsaved work is asked about as today. The move skips its cross-fade
([[R2117000]]) and starts with an empty tab-memory read cache ([[R2125000]]): one extra read per
screen, once.

Never over a board. While a board is on screen the moves stay in place, and the full load comes
with the first move after the board is gone. A practice game resumes after the load ([[R668]])
and a live match is rejoined ([[R765]]), as after any reload.

A screen that still fails on a stale chunk reloads once by itself: when the boundary's error is
a chunk-load failure and `version.json` names another build, the tab shows "JackiOh was just
updated. Loading the new version…" and reloads. A `sessionStorage` key holding that entry stops
a loop: a second failure for the same entry shows the connection panel, as does a chunk failure
with the build unchanged.

Presentation only (CLAUDE.md rule 7): the client fetches one static file and reads no game state.

Hearthstone semantics: its client refuses an old build at the door; a browser tab has no door,
so the tab loads the new build on its next menu move instead.

**Rejected:** asking on every wake with no interval, which polls the server for a tab nobody
touches; reloading over a board, which ends a game in progress; reloading a failed screen
without checking the build, which loops a tab whose network is truly down.
