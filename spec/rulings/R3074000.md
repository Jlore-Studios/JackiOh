The dev dashboard is `apps/admin`, an app of its own at its own hostname (`admin.jackioh.com` for production, `admin-staging.jackioh.com` for staging), served by a Worker of its own that forwards only the routes it needs to the site's server. It needs no route on the player site, so the player bundle carries none of it. Three locks stand in front of it, each enough to stop a stranger: Cloudflare Access on the hostname, an email allow list as staging's; the account's own sign-in, with its two-step code where the server is strict; and the server's own check of `DEV_PROFILE_IDS` on every route ([[R1300000]]). The dashboard only sends intent (CLAUDE.md rule 7): no service-role key or database address reaches the browser, and it reads nothing but the server's answers.

**Strict.** The server's `DEV_STRICT`, `on` unless it says `off`, is on for production and off for staging and end-to-end mode. On a strict server every `/api/admin/*` route needs the caller's session to have proved the second factor (its token's `aal2`, [[R665]]) and answers a dev account's `aal1` session 403 `forbidden`, as it answers every account the list does not name. The `/api/dev/*` tools that the Dev tools panel sends (the front screen's Dev button since [[R3156000]]) keep their own gate, the list alone, since they touch only the dev account's own holdings and every row they write is marked `dev`.

**The audit.** Every write of a dev or admin route, `/api/dev/*` (XP, Jlore, the fill, each clear, each bar, the quest tools) and `/api/admin/*` (a hand-set rating, its reset, a post, a take-down), writes one row of `admin_actions` in the transaction that does it: who, which route, the request, the values before and after, and when. A read writes none. The table is append-only, server-only and never read by a client but through `GET /api/admin/audit`, which answers a dev the newest `ADMIN_AUDIT_PAGE` rows; when an account is deleted its rows stay and forget who ([[§14.11]]'s rule for a ledger, kept for the audit's sake).

**Caps.** One request of `POST /api/dev/jlore` gives at most `DEV_JLORE_PER_REQUEST_MAX` Jlore and one of `POST /api/dev/xp` at most `DEV_XP_PER_REQUEST_MAX` XP; more is 400 and writes nothing. This amends [[R1300000]]'s positive whole numbers. Keeping `/account`'s Dev tools beside the dashboard was the issue's proposal, and nothing was removed (CLAUDE.md rule 13).
