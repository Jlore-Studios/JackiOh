id: R315
title: Fatigue is reported before its hit
cards: "#75, §2.4, §10.3, R3, R240"
proven_in:
  - crates/engine/tests/rules/overflow_events.rs
---
[[§2.4]] and [[R3]] made the Nth draw from an empty library deal N damage, and the only event it produced was that damage instance: a hit from no source that looked like any other, and none at all to a viewer whose hero's Armor took it whole ([[R240]]'s zero report aside). Every fatigue draw now emits `fatigue { player, count, amount }` first — `count` is the owner's fatigue count after the draw (the Nth), `amount` the hit before Armor, `FATIGUE_DAMAGE(count)` — and its `damage` follows at once, [[R240]]'s zero report when Armor takes it all. It names no card, and the fatigue count is already public ([[§10.8]]), so both players read it in full. It is a report, like [[R240]]'s: no card answers it. A draw #75 Infinite Reserves replaces is not a fatigue draw and emits none; the Rush Token card's `drawn` reports it. The draw itself is unchanged: the same count, the same hit, the same rng
