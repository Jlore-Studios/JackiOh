A write names the groups a device has changed, and a group replaces the stored one only when its time is strictly later: a stale device can never undo a newer change, a tie changes nothing (so the same write twice is the same write once), a group a write does not name stays, and a change to one group never undoes another's. A time after the server's clock counts as now, so a device whose clock runs ahead cannot pin its settings. The merge runs under a lock on the profile, so two devices writing at once cannot lose each other's group. The client keeps, per group, when the device last changed it, and on a screen with an active account reads the account's copy once and takes the newer side of each group: a group the account holds with a later time than the device's, or one the device has never changed, is applied to the device's store (which keeps what it knows and clamps the rest); a group the device changed later than the account holds is sent up. After that each change on the device (a switch, a slider, a reset, another tab's change) is sent a moment later, so a dragged slider is one request, one request at a time, the answer reconciled again; a group the server kept, with this device's values, at an earlier time than the device's is held at the server's time, so a clock running ahead does not resend it for ever. The device's copy is the one the game reads and is authoritative for the session: a request that fails or never answers changes nothing on screen and raises nothing, while the next change, coming back online or the next load sends what is owed. Signed out, pending or banned, settings stay on the device and nothing is sent. Settings belong to the device as much as to the account, so signing in on a device adds its later changes to the account
