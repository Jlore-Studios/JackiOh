Every card figure was read off the game records themselves, so each report read every record of a patch and the records grew without end: the gather lane alone files about 4,000 games a day, some 7 MB a day of decklists, hands, draws and plays. The figures now come from totals the records are folded into, and every report is byte for byte what the same records gave ([[R978000]]).

- **What the totals hold.** Records counted by patch, source, mode and both seats' pilots, from which a query's games and decks and [[R654]]'s gate are read for any pilot filter. For each patch, source, mode, seat pilot and card, [[R377]]'s six breakdowns (games, wins and draws), and the drill-down's games and wins by the turn the card was played on and with each card that shared its deck. Each pair keeps where it was first met, the records taken in id order, so the drill-down still lists a tie in the order the records met it. For each patch, the distinct decklists people took into live Best-of-1 games, each with its games and wins and the deck as the first record held it, in the order first held, for the ladder bots ([[R1454]], [[R750000]]).
- **One counting path.** The totals are the engine's (`StatsTotals`, beside `card_stats` in `crates/engine/src/wire/stats.rs`), and `card_stats` over record files folds them too, so a run's file, `stats-cards` and the public figures cannot count differently. Adding totals is commutative and associative, so records folded in any order or in pieces make the same totals.
- **Folded as written.** The server folds a record into the totals in the transaction that writes it, and only when the write is new, so a second write of the same game counts nothing, whether a live match's result came twice or `stats-import` read a day's file again. `stats-import` folds a file `STATS_FOLD_BATCH_RECORDS` (500) records to a transaction. A record written before the totals existed is folded once, by the retention loop before each purge or by `jackioh-server stats-fold`, a batch at a time, and marked folded with its counts.
- **Who reads them.** The public card routes ([[R654]], [[R807000]], [[R1451]]), `stats-cards` in every filter ([[R377]], [[R378]]), `balance-watch`, and the ladder bots' deck draw read the totals. `stats-export` and the analysis notebooks read the records whose detail is still held ([[R1044001]]).

This amends [[R978000]], whose note rejected aggregating a patch for now: the totals are not aggregated in SQL at read but folded in Rust at write, by the counting the records were read with, and the kept reports stay as they were. It amends [[R376]] in that a record is now kept for what it adds to the totals, and its detail only as long as [[R1044001]] says.

Rejected: counting the drill-down's co-played cards for live games alone, since a provisional patch's figures count development games too and would change; keeping only each card's top co-played cards, which a later game can overtake; one totals document per patch rewritten on every game, which writes the whole patch for each game; and aggregating in SQL, which would be a second counting path to keep equal to the engine's.
