A pending fragment names no version. `cargo jackioh patches "<title>"` writes `crates/cards/patches/pending/<slug>.json`, its name the title's words lower-cased and joined by dashes without the `Patch …:` prefix, holding `{ title, sources, notes, player, cards, plays, rule }` and the win-rate claim ([[R1329000]]). `cards` is the catalog claim, diffed against the newest snapshot as before ([[R646]]). `plays` (`--plays <ids>`) names the shipped cards whose play changed with no catalog change, through their script or the engine, and `rule` (`--rule`) a divergence no card explains, both as `cargo jackioh classify`'s second stage finds them against the base build ([[R1365000]]). Neither is claimed from the diff alone, since only that stage tells a refactor from a change. A fragment written again keeps its player note, `plays` and `rule` unless a flag restates them. The old form, `patches <version> [date] "<title>"`, still writes a fragment; its version and date are ignored, and a fragment an older build wrote with a `version` is read with it ignored.

`patches ship` names each fragment, in ship order, from its tier, after the then-newest version (the last entry of `patches.json`, [[R388]]). It snapshots the patch before it with the fragment's claims ([[R646]]), and reads the tier from the two snapshots, each with the sets its cards belong to, and the fragment's `plays` and `rule`, through the classifier's own `read_diff` and `classify`:
- a **major** (the snapshot holds a set the one before it does not, the set having reached `SHIPPED_SETS`, [[R1420]]) is `v0.(Z+1).0`;
- a **patch** (`PATCH_MIN_CARDS` or more families play differently, or a rule) is `v0.Z.(X+1)`;
- a **micro** (anything smaller, wording alone included) is the newest version with the next letter. A fragment that changes no card, the win-rate table alone, is a micro, since every patch bumps the catalog version.

No title, flag or label names a tier. The patch records its `tier` and `plays`, the families that play differently, so later readers read fields and never parse a version ([[R105]]). Every snapshot, tier and name is computed before anything is written. `patches ship` runs no second stage: the pull request's `classify` check confirmed the claims.

`patches check` no longer checks a fragment's version or its file name. It requires each `plays` id to be a shipped card. A fragment must claim something (a card, a play, a rule or the table). It does not ask for a claim on a changed script, which the `classify` check holds.

This supersedes the numbering clauses of [[R646]] (a fragment's version, revision letters for a reused name), [[R650]] (a micro named from a `vA.B.Y` fragment) and [[R743]] (a normal patch taking the next number its fragment names). Their other clauses stand.
