**One socket per tab.** A signed-in tab holds one WebSocket at `/ws/social` beside the match socket. Its upgrade is the match socket's: the token is an offered `jackioh.bearer.` subprotocol, never the address ([[R1379000]]), only `jackioh.v1` is echoed, the upgrade is one request against the account's budget, closed with 4429 past it ([[R2478000]]), and §9.4's gate refuses a pending or banned account with 4403 ([[§9.4]]). Every refusal is one `forbidden` frame and a close with [[R148]]'s codes. An account holds at most `SOCIAL_SOCKETS_PER_ACCOUNT` (5) of them, the next refused with 4403 "too many open tabs", and an address's social sockets are counted apart from its match, co-op and watch sockets, each against `WS_MAX_CONNECTIONS_PER_ADDRESS`, so a person's idle tabs never take the room a game's socket needs ([[§9.8]]).

**What it is sent.** Three frames, each only what its own account may read. `social {incoming, outgoing, unread}` is exactly that account's `GET /api/social` answer ([[R3210000]]), read for it alone: first as the socket opens, then after each change to its challenges or unread counts, and in answer to a hello. `chat {friendId}` says a message between it and that friend was sent, either way, with no body: the tab reads the conversation itself. `friends` says its friends list changed: the tab reads the list itself. Each push is made after its change's commit, on the success path only: a challenge made (both accounts, and both again when it lapses `CHALLENGE_TTL_MS` later), declined or canceled (both), or accepted (both, once the room's game or series has started, so the challenger's follow finds it); a message sent (`chat` to both, `social` to its recipient) and a read that marked one (`social` to the reader alone); a friend request made, accepted, declined or canceled (`friends` to both); a friendship ended (`friends` and `social` to both); a block (`friends` to the blocker, and to the blocked, with `social` to both, only when it ended a friendship, a request or a challenge between them, so a blocked stranger is told nothing and a blocked friend learns no more than an unfriend tells it) and an unblock (`friends` to the blocker). A friend's status is not pushed: it lapses on a clock (`PRESENCE_TTL_MS`) and games start and end on many paths, so the friends list keeps its own `FRIENDS_POLL_MS` read, which already runs only on Play together or while the friends panel is open. An account with no social socket costs no read, and a read that fails is logged and dropped: the tab's next hello, or its polls once the socket is gone, reads it again.

**What it takes.** One frame, `{type: "hello"}`, answered with a `social` frame at most once a `WATCH_HELLO_INTERVAL_MS`, [[R2609000]]'s interval, so a woken page's probe ([[R1441]]) hears a live socket and a flood costs one read a second. Anything else is answered `malformed`, and past `MALFORMED_FRAMES_PER_WINDOW` of them the socket is closed with 1008 ([[R835002]]).

**The session while it stays open.** Every `SOCIAL_SESSION_CHECK_SECONDS`, one [[R194]] window (`AUTH_SESSION_LIVE_CACHE_SECONDS`), the server checks again what the upgrade checked, counting no request: a token the auth no longer verifies (a session the provider ended, an expired token) or a profile gone is closed with 4401 "sign in first", and an account banned meanwhile with 4403 and the gate's words. A check that could not be made is logged and the next one tries again. So a revoked session's socket is cut off within the window its polling tab's next request would be refused in.

**The tab.** While its socket is live (its first `social` frame came), the tab sends no social poll and no chat poll: the pushed `social` read stands in for the first, and an open conversation reads its newest page on a `chat` frame naming its friend and once each time the socket comes up or drops. A `friends` frame reads an open friends list again. When the socket drops or never opens the polls run at their pace, reading at once on the drop, and a hidden tab's still pause ([[R3205000]]): a hidden tab reads nothing on a drop or on a `chat` frame (a chat read marks the page read), and reads once when it shows. A drop reopens on the match socket's backoff, which the poll's read on the drop does not cut short; a 4401 reopens at once with a renewed token ([[R1115000]]) and otherwise, like a 4403, waits for the session to hold another token. A socket speaks only for the token it was opened with: once the session holds another (renewed, signed out, another account), a frame it brings is dropped and the socket is replaced. Older tabs keep polling, and the reads stay.

**Hearthstone semantics.** A friend's challenge or message shows as it happens, not on the next poll.

Rejected: server-sent events, since `EventSource` cannot offer a subprotocol and the token would ride in the address ([[R1379000]]); chat bodies in the frames, which would put another copy of each message on the wire and in the socket's queue; pushed friend statuses, which need presence events the server does not keep; one per-address count shared with the game sockets, under which idle tabs could refuse a match socket; closing an account's oldest socket past its cap, which lets a script cycle a person's tabs; and a session check that verifies only the token, which would miss a ban.
