A username is a display label and nothing more. The database, the server and every request refer to a player by profile id: foreign keys, ratings, results, game records, rooms, rematches, series, logs, caches and API parameters. Nothing looks a player up by username but the taken-name check behind the preview and the save ([[R1435]]), the public players tab's search, which matches the NFKC case fold of the username ([[R654]]), and a sign-in by username, which finds the one profile holding the typed name to ask the auth provider for its session and answers nothing about that profile but the session ([[R1443]]). No table but `profiles` stores a username ([[R1434]]) and every read joins it in, so a rename shows everywhere at once, past games included, with no other row rewritten; a game record still names no account ([[R376]]). A request about the caller names nobody, since the token says who, except a sign-in by username, which comes before there is a token ([[R1443]]); a request that has to name another player sends that player's profile id, taken from the response that showed them (none does yet). Every response that shows a player carries both their `profileId`, the client's list key and what any request back sends, and their `username`, what the client renders: `GET /api/leaderboard`'s rows, the caller's own standing in `GET /api/ranked`, both seats of `GET /api/matches/:matchId/ranks` ([[R612]]) and the rows of `GET /api/stats/players` ([[R654]]). The old `tag`, a hash of the profile id shown as a name, is gone. The client never renders a profile id or anything derived from one. It renders every username isolated (`<bdi>`, `dir="auto"`), so an Arabic or Hebrew name never reorders the text around it or its own `#n`; a script the game's font lacks falls back to the system's fonts; and every place a name shows fits 16 wide (CJK) characters, or truncates the name with an ellipsis and keeps it whole in a `title`.
