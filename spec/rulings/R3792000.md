The wait's account reads (every `SERIES_POLL_SECONDS`, [[R897000]]) ended in a silent catch. When the connection dropped, "In the queue" stayed on screen while the server, which cancels a ticket it has not heard from for `QUEUE_TICKET_STALE_MS` (12 s), had already taken the player out; they learned it only when the network came back ([[§9.5]]).

**The rule.** When `LOBBY_UNREACHABLE_AFTER_READS` (3, in `routes/play.tsx`, about 6 s at the poll's pace, inside the server's ticket timeout) account reads of a wait in a row fail as unreachable (`ApiUnreachableError`: a transport failure or a timeout), the queue wait and the room wait show one `role="status"` notice, "Can't reach the server. Still trying…", beside the status line. The status line stays. The client restates no server number: the threshold is its own, named constant (CLAUDE.md rule 9).

**Clearing.** Any read the server answered clears the notice and resets the count, including one that was refused (an `ApiRequestError`, which proves the server was reached and is not counted as a failure). Fewer failures than the constant show nothing, so a flaky link that drops one or two reads stays quiet.

**The ticket logic is unchanged.** R897000's `QUEUE_ENDED_AFTER_READS` count and the pairing navigation work as before; a failed read counts neither as a read saying the ticket is gone nor as a good one. A lobby that is not waiting shows nothing.

**Presentation only.** CLAUDE.md rule 7: the server still owns the ticket and its timeout; the notice only reports what the client could not do.

**Rejected.** Counting every rejected read, which would call a 401 or a 5xx an outage; putting the words inside the status line, which would replace the queue line the player still needs.

Hearthstone semantics: the "Reconnecting…" banner when the connection drops.

Amended by [[R3730006]] (issue #3730): `/play` has no room wait any more, since a friend game starts in a private lobby ([[R3730000]]), so the notice is the queue wait's alone. A host waiting for a friend waits on the lobby's own screen, where a read that cannot reach the server takes the lobby's place at once with "The lobby could not be read", `ApiUnreachableError`'s words and Try again. While the social socket is down the lobby reads itself every `LOBBY_POLL_MS`, and the first read the server answers brings the lobby back. A lobby member holds no ticket the server cancels when it goes unheard ([[R3730000]]), so no count of failed reads waits before the screen says so.
