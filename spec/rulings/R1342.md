A seat's hand rides in the `portraits` message ([[R642]]), never in `PlayerView`: `{ type: "portraits", p1, p2, emotes }`, where `emotes` is the hand of the account that receives it and never the opponent's, so a socket learns nothing it does not show. It goes out on join and again on every reconnect and `hello`, the same eight each time ([[R1341]]). A client reads an `emotes` that is not `EMOTE_HAND_SIZE` distinct pool ids as a bad frame and keeps what it had; a frame with none (a server that deals none) leaves it on the default hand ([[R1343]]).

The match actor refuses an emote of the pool that is not in the sender's hand: it is never relayed, the sender gets no error and nothing is written, as with [[R643]]'s rate-limited drop, and it is checked before the rate gate, so a refused emote spends none of the limit. The actor logs it as `match.emote.outside_hand`, which is not a rejected action. The client makes the same check before its own gate: the menu offers only the hand, and a send of anything else (a stale menu, a test, a hand-made call) shows nothing, plays nothing and is never sent. An id outside the pool is still `malformed` ([[R1340]]). The rate limits are unchanged.
