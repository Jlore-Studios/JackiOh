Two base names ([[R1432]]) clash when their NFKC case folds match: `Max`, `max` and `ＭＡＸ` are one name, and so are `Straße` and `STRASSE`. The server computes that key in Rust and stores it beside the display form (`profiles.username_base`, `username_key` and `username_tag`), so no Postgres collation decides it, and a unique index on `(username_key, coalesce(username_tag, 0))`, every tag 1 or more, holds it. The first player to pick a base name gets it bare; each player after gets the lowest free tag from `#1` up. A tag is freed when its holder renames or deletes their account, and the next player to pick that name can get it. A player's own current name never counts as taken against them. A new account starts as `Player#n` with the lowest free `n` from 1: a default always carries a tag, and `Player` is otherwise a base name like any other ([[R1433]]), so a player who picks it gets bare `Player` while it is free. Taking the lowest free tag, for a pick or for a new account's default, is one transaction under a transaction-level advisory lock on the key, so two players taking the same name, or two sign-ups, at the same moment get different tags. Migration 0028 gives every existing profile a `Player#n` default in order of sign-up (`created_at`, then id), so the earliest accounts hold the lowest numbers, and marks each one not yet prompted, so its player meets the prompt once ([[R1435]]). No table but `profiles` stores a username ([[R1436]]), and `authenticated` may read the columns but never write them: a username is written only through the API. `profiles.display_name` is gone.
