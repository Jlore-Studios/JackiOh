[[§9.8]] says "accounts with an unusual rejection rate raise an alert", but only the first half existed: every reducer refusal is logged as `match.action.rejected` and every refused overflow as `match.action.flooded`, with no escalation. The actor now counts both toward one per-seat window and raises one alert per match per seat through the same `log_alert` sink the codes circuit breaker uses.

The count is per home seat ([[R137]]'s scope), kept over `REJECTION_ALERT_WINDOW_MS` (60 s) and crossed strictly over `REJECTION_ALERT_THRESHOLD` (20 refusals): the 21st refused action inside the window emits `match.rejections.unusual` with the seat's profile id, the match id, the count and the window, and nothing emits it again for that seat this match. Old refusals fall out of the window, so a slow trickle never alerts.

Only the two refusal paths count: the reducer's own refusal and the flood limit's ([[R109]]). Emote drops are never rejected actions, malformed frames are answered `malformed` on their own budget ([[R835002]]), and post-game `MatchOver` refusals and store failures count for nothing. In memory only: the sentence targets abuse within a live match, and a cross-match account score would need a store change.
