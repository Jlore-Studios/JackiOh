The designer asked (#1563) that Meditative+ #26 Scratch Pad be "actually coding with a physical text editor". Its `craft` prompt ([[R1182002]]) opens a text editor in place of the block canvas: the player types the card's code, and the client reads it into the recipe its answer carries. The code is a spelling of the recipe and nothing more: `card <Type> "<Adjective> <Noun>" { … }`, the type one word (`Unit`, `Spell`, `FieldSpell`, `Trap`), then `stats(attack, health)`, `keyword(Kind)` or `keyword(Armor, N)`, `echo(N)`, and each hat by its block name (`cry`, `death`, `startOfTurn`, `endOfTurn`, `whenCast`, `opponentPlaysUnit`, `opponentPlaysSpell`, `opponentAttacks`) holding its effects in braces, each its verb's block name with its N, keyword or card type in parentheses (`damageTarget(3)`, `grantKeyword(Taunt)`, `discover(Spell)`); a name of two words is written as one (`DivineShield`, `FieldSpell`); `//` starts a comment and `;` and line breaks are free. The cost is the prompt's, chosen before. A text that does not read is a syntax error naming its line, shown as a compiler shows one, and Craft stays off; a text that reads is judged by the engine alone, as a recipe of blocks is ([[R880]], CLAUDE.md rule 7), so a block the rules refuse (a retired verb, [[R1563009]]; a hat the type does not take, [[R883]]) reads and is refused, with no reason shown, as [[R1182002]] keeps it. The empty canvas opens as the code of a 0/1 Unit, and the blocks by name, which stay ([[R1182002]]), type their code at the caret. Nothing changes in the engine: the prompt, its answer and its presets for the AI and a timeout are [[R1182002]]'s, and it has no offer ([[R1563007]]). It edits [[§8.9]] and [[R1182002]].
