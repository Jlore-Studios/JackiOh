A dungeon run's fight in progress is kept the way [[R668]] keeps a free game: its config, its action
log, the cursor of the AI's own stream and the state's hash, after every answer, in the worker's own
storage (IndexedDB), never sent to the page, whose log would name the AI's hidden cards (rule 7).
It is kept in a slot of its own, keyed by the fight (its seed is the run's seed, row and column,
[[§15.6]]), so it never touches the free game's save: each slot holds at most one game, and a free
game and a run fight never overwrite each other in either direction.

When the run, still on that fight, starts it again, the worker resumes the kept fight: the log is
replayed action by action under the same nonces and must reach the saved hash, and the AI picks its
stream up at the saved cursor, so the resumed fight plays on exactly as it would have, on its turn
with its board, hands and log. A save from another fight, another catalog version, or one that
folds differently is refused and the fight is dealt fresh from its seed, as [[R668]] already does
for a free game.

A finished fight clears the slot, and an abandoned run and a new run clear it too, so a finished
fight, an abandoned run and a new run's first fight find no kept fight. A run fight is still never
kept for replay ([[R768]]), and the leave guard still asks first ([[R2972000]]), but its words now
say the fight waits. This amends [[R2706000]]'s "never saved" sentence on purpose: leaving no
longer deals the fight again. This follows Hearthstone semantics: a Dungeon Run match in progress
is resumed when the player comes back, not dealt again.
