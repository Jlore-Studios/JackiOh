A pending fragment that a `KEPT_SCRIPTS` row names by its `"fragment:<stem>"` key ([[R4779000]]) claims the change of the script that row keeps, so `cargo jackioh patches check` ships it with no catalog card, `plays`, rule, look, system or win rates of record claimed, where any other fragment that claims none of them still fails ([[R1366000]]). Such a fragment is for a script change that no game of `classify`'s stage 2 reaches ([[R1370000]]), a target's aim that only a stolen or random cast reads, say: its `plays` would be refuted, and no card's statistics should restart over it, yet a replay of a game played before it must fold under the kept script ([[R767000]]), which needs the version the fragment ships as for its boundary. A key naming another stem, or a version, does not count; the fragment ships as a micro, like every fragment that ships no set. Rejected: claiming `plays` anyway, which the pull request's `rust (classify)` fails; shipping with no fragment and the rows keyed by the newest shipped version, which would fold under the kept script every game played on that version after the merge and before the next ship; and a classifier batch that forces those casts, which needs a game mark the engine does not have.
