The sets made for single-player modes, the dungeon runs and their bosses, are Boss and Boss-X, the two sets `SetName` reserves ([[§5]]), which `SINGLE_PLAYER_SETS` lists. `SHIPPED_SETS` never lists one: no deck holds a single-player card and no pool that names no set reaches one, as [[R1420]] holds a set before it ships.

The catalog query's `everySet: true` ([[§5.1]]) widens a pool that names no set from the sets that ship ([[R380]]) to every set, single-player ones too: the sets that ship (and, under the testkit, a previewed set, [[R1420]]), then Boss and Boss-X, in `query`'s order. It reaches no other set, so a set the catalog holds before it ships stays out ([[R1420]]), and no custom card, which no catalog pool holds ([[R915000]]). A pool that names its set (`set`) or its cards (`defId`) keeps to them, and `everySet` changes nothing there; `false` is the default; a token joins only a pool that takes tokens ([[§5.1]]). Stinkyscape #109 xxFreshJack's "a random BUSTED card that exists anywhere in the game's code" is `{ busted: true, everySet: true }` ([[R1846000]]).

The catalog holds no single-player card yet, so today an `everySet` pool holds what the same pool without it does. A single-player set's cards join every `everySet` pool from the patch that adds them to the catalog; a single-player set built card by card before its mode ships needs a hold of its own, which the issue that builds it adds, as [[R1420]] added one for a set. This amends [[R1420]]: a set the catalog holds before it ships is in no pool that names no set, but a single-player set is in an `everySet` pool.
