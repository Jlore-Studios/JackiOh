**Why.** A Constructed deck is chosen and an All Random deck is dealt ([[R257]], [[R258]]), so a card's win rate in one says little about the other, and one rate over both says less. The owner asked in #2777 for the two to be read apart.

**Constructed.** `?mode=constructed` on these routes reads the two modes whose decks a player built, Best of 1 and Conquest, together, and no All Random record:
- `GET /api/stats/cards`
- `GET /api/stats/cards/:id`
- `GET /api/stats/games`

The engine's `ModeFilter` names it beside every mode and each of [[R257]]'s three. A Constructed figure is each mode's figure summed, as the live and development parts already are. [[R654]]'s gate still counts every mode's live games, so a card's window ([[R1367000]]) is the same whatever mode is read. `?mode=all`, or none, still answers every mode, for `stats report` and any other caller.

**The page.** `/stats`' match-type picker offers four choices:
1. **Constructed**, first, and what the page opens on. An address with no `mode`, or an old `mode=all`, reads Constructed, and the address names `mode` only when it is another.
2. **All Random**.
3. **Best of 1**.
4. **Conquest**.

It no longer offers "All modes". The Cards tab, the Sets tab, the Game figures and the drill-down read the mode picked.

Rejected:
- Showing a Constructed and an All Random column side by side. It would double every figure the table already shows.
- Keeping "All modes" on the page, which is the mix the owner called misleading.
- Gating each mode on its own live games. That would let a quiet mode's window differ from a busy one's, splitting [[R1367000]]'s window by mode.

No Hearthstone rule is involved.

Amended by [[R2777004]] (2026-11-04): the page offers "All modes" again, first, and opens on it. Constructed stays one of its choices, and this note's routes do not change.
