`POST /api/trios/import` takes the decks and the trio the client decoded, with ids the client minted ([[R256]]), and checks them as any save is checked: the catalog version, D1–D4 for each deck (a refusal names the deck), T1–T3 for the trio, the body's shape and every id a UUID. It then checks [[R340]]'s room and writes every deck, one millisecond apart in slot order so the saved list shows them in their slots' order, and then the trio, in one transaction, so a failure part-way leaves nothing behind; ids the caller already owns are a retried import and take no new slot, so the client may send the same import again after a lost answer, and does, with the same ids. It never goes through the autosave, which would leave half an import behind a refusal, and the workshop sends it only once every earlier edit has landed, so the caps it checked are the ones the server holds
