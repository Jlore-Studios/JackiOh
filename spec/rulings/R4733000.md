When a dungeon run's fight ends, its result counted only when the player pressed Continue: leaving
by Menu, Back, a reload or a closed tab forgot the fight was ever played, so a win had to be won
again and a loss or a concede got a free retry, although one lost fight ends the run ([[§15.6]]).
The worker clears a finished fight's kept game at once ([[R3476000]], [[R4582001]]), and the report
sat only in the fight screen's memory until Continue sent it ([[R4582000]]).

The report is now held beside the kept run or attempt, keyed to its fight, the moment it arrives:
the dungeon holds its `fightOver` with the run's row and column, the Assault holds its `fightOver`
with the attempt and the level. It is the run's own outcome action, never the game's log (rule 7).
Holding changes no screen: the board keeps showing its end until Continue, so [[R4582000]]'s
rejection of reporting automatically on arrival still holds.

Continue applies the held report as it does today, and the same write clears the hold. Leaving
applies it: the fight screen sends an unsent held report when it unmounts, so the dungeon's Menu,
the browser's Back and any in-app move send the result first, as the Assault's Menu already did
([[R4582001]]). Loading applies it: a store that loads a kept run or attempt still on the fight
its held report names applies the report once through the run's own reduce, then clears the hold;
the player lands where Continue would have taken them. A held report the run refuses, or one naming
no fight the run still stands on, is dropped, and the fight is dealt fresh from its seed as today
([[R3476000]], [[R4582001]]). Clearing the hold in the same write that appends the action keeps
Continue-then-leave and two tabs from applying anything twice.

This amends [[R3932000]]'s last paragraph on purpose: once the fight has its result, Menu still
navigates to the Play menu directly without asking, but it sends the report first.

This follows Hearthstone semantics: a Dungeon Run match already decided writes down its outcome
when it ends, not when the player gets around to it.

Rejected: keeping the worker's finished save until the result is taken, which would change the
shared practice host that saves no finished game ([[R668]]) and would add a resume path for a game
that is already over; writing on `pagehide`, which misses in-app moves and is unreliable on phones;
and re-dealing a fight whose report arrived but was never held, which is the free retry this ruling
closes. A reload inside the worker's single round trip between the game ending and its report still
deals the fight fresh; that window is accepted.
