A Death that runs more than once ([[R823]]: M #10 Double Counting runs its controller's Deaths once more) runs on the same snapshot of the dying card each time ([[§4.5]] step 3). A card that an earlier run set face-down under a fresh id ([[R227]]) is read under that id by the next run, as the cards in play read it ([[R3550007]]). So S+ #84 Bogos Binted's second reset of its side ([[R419]]) finds the Trap its first reset set again standing where the snapshot has it and keeps it, one card: it bounces nothing the first reset put back and sets no second copy. Hearthstone runs a doubled Deathrattle twice on the minion as it died, and the second run sees the board the first one left, which is what this keeps.

Before this, the copies of the snapshot a Death pass still owed sat in no zone, so `rename_in_board_history` never reached them: the second reset read the Trap under its old id, bounced the one the first reset had set, and set a duplicate whose `controlChanged` named the old, dead id as its `formerId`, which leaked into the opponent's view (Duos fuzz seed 476, invariant I6).

Engine: `state_check::run_death_pass` follows each `formerId` that one run's events carry into the side snapshot notes of the copies it still owes (`state::follow_fresh_ids`, the same rename `rename_in_board_history` does on the cards in play). Rejected: chaining `formerId`s in `view_for`, which would hide the leak and keep the duplicate.
