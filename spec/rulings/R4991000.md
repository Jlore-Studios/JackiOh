[[R781004]] draws the Aura's random combat keywords with the match rng as the card arrives on the field, and [[R4816000]] makes the card a Transform puts on the field an arrival. Both M #65 Keymaster Keenus and S #111 Shockwave447 drew only on a `summoned` naming them, so S+ #103 Transcend, S+ #104 Tireless Cultivation and #83 Transmogulate Embiggened left one on the field with its text and no keywords at all. In Hearthstone a transformed minion is a new minion, so it draws as it arrives.

- **What draws.** A `transformed` whose new card is the running card, acting on the field (`query::self_arrived_on_field`), draws as a `summoned` does: the Aura's number from the match rng into the list the Aura reads (`top_up_combat_keywords`, [[R3778000]]). The new instance holds no list ([[R78]]), so it draws the whole number: 5 for Keenus (10 on the Radiant face), 3 for Shockwave447. A Transform is no summon, so Shockwave447's Cry does not run ([[R1]]).
- **What does not.** A Transform in a hand or a library, which makes no card on the field; and a Vanilla's or a copied text's `transformed`, which names the same card on both sides and brings nothing onto the field.
- **Replays.** In every version before this change's a card a Transform made drew nothing: `script_before_transform_draw` of each card keeps that, keyed by this change's fragment, so every version shipped while it waited is covered ([[R4779000]], [[R767000]]).

Rejected: an engine draw for every `combat_keywords_follow` card on a Transform, which would refuse every replay since v0.6.0d it touches instead of folding it under a kept script; and leaving the Transform out of the arrival, which keeps a card standing with an Aura that gives nothing for good.
