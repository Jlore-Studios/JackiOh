The Friends page's Recently played tab ([[R3732002]]) lists the people a player lately played an unranked game with, each with Add friend. `GET /api/friends/recent` answers `{ recent: [{ profileId, username, playedAt }] }`: the other seat of each of the caller's newest `RECENT_OPPONENTS_SCAN` (50) finished games whose log is kept, newest first, one entry per person at their newest game, at most `RECENT_OPPONENTS_MAX` (20). A game the queue paired is ranked ([[R604]]) and a room, lobby, challenge or daily game is not, so the ranked flag alone is the line: the list holds the opponents of the unranked games and never one the queue paired. A ladder bot must be indistinguishable from a person ([[R1452]]), and a list of every queue opponent with an Add friend on it would hand the bots over, as would any list that kept them apart by name, rating or kind. The server decides nothing from the opponent: a person who is also met in the queue is listed for the unranked game alone. Left out of the list: the caller, a friend, and anyone a block stands between, either way, since a request to either is the unknown name a block makes ([[R1689000]]). A profile of a bot that somehow sat in an unranked game is left out as well, never shown. It reads no game's log or result beyond the end time, and nothing but the name and the end time of a game leaves.

A game from before the ranked flag (migration 0022) reads as unranked and could list a queue opponent; the flag was written on every queue game from the day it was added and no such game is still kept past the retention purge's window, so this stays a note and not a rule.

Rejected: listing every opponent and marking the queue's ones, which still hands the bots over; keeping queue opponents on the list for the player's own unranked rematches only, a rule the server would need a game's history to keep.
