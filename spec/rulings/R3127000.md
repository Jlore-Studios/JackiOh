The page Cloudflare serves, with a 404 status, for a path nothing routes (`not_found_handling: "404-page"`, both environments) is the client's own page: the build writes `404.html` from the built `index.html` (`apps/web/static-pages.ts` `notFoundHtml`), as it writes the public pages, and `public/404.html` no longer ships beside it. Presentation only (CLAUDE.md rule 7). It supersedes the static page of [[R3119000]].

**The client.** `404.html` loads the client's entry script, so the client starts, routes on `window.location.pathname` and draws its own 404 (`main.tsx` `NotFound`: the glitched real path, the lost card, three ways out), on the first render, with no wait and no sign-in before it. Its head names the 404 as the client does (`documentTitleFor`: "Page not found · JackiOh"), asks not to be indexed (`noindex`) and names no address of its own: no canonical link, no `og:url`, no structured data, which would name the landing page. Cloudflare's status stays 404, so a missing `/assets/*.js` still answers 404 rather than `index.html` read as JavaScript, which is why the 404 page exists.

**The fallback.** What shows with no script, and while or if the entry script does not start (a stale deploy, a blocked chunk), is the shell's own look from the app's assets: the tavern plank floor and brass-studded board, the stacked logo, the self-hosted Alegreya and Inter, the app's button "Back to the start" (`href="/"`) and the 404 panel's two sentences. Unlike the public pages' static body it is never hidden: no `static-body`, no `<noscript>`, and it stays until the client replaces `#root`, which it does when it starts.

**The hand.** Three cards: Error (cost 4), Not (cost 0) and Found (cost 4), read off the cost gems, which are the only numbers on them. Each is the frame `CardFace` draws (`.cf`, `.cf-scale`, `.cost-gem`, the art window, the name banner and the type line), as a Spell with no attack or health and an empty rules box, over the procedural art `CardArt` draws for its name. They are placeholders: no catalog id, set mark, rarity foil or crest, nothing a player could take for a real card. The build writes the markup (`handCardHtml`) from the same pure art builders `CardArt` calls, and a test holds it, element by element, to what `CardFace` renders for the same face, so the frame cannot drift from the game's.

**Still moving, still still.** The hand moves as [[R3119000]]'s did: the brand's card backs deal in stacked, fan out (−15°, 0°, 15°), turn over into the faces and float, in CSS alone (`notfound.css` `.nf-hand`), every rule the dealt, face-up hand with the animations only running toward it. Under Reduce motion the cards lie dealt and face up.

**One screen.** The fallback holds the one-screen rule ([[R1581000]]) at 1280x720 and 390x844, and its link the tap minimum ([[R2122000]]).

Hearthstone semantics: an error screen in the game's own look, which the game's own frame draws.

Rejected: rendering `CardFace` at build time with react-dom/server (it throws on `useCardSettings`' missing server snapshot, then reads `document` in Node, and the Vite config loader cannot import it for its `.css` imports; patching those hooks would change a surface the whole client shares, so a test holds the markup to `CardFace`'s output instead); the hand on the client's `NotFound` too (it already holds the lost card and three ways out, and the one-screen rule is tight there).
