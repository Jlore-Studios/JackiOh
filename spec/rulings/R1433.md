title: "The light profanity filter on usernames (issue #579)"

proven_in:

A username's only content check is a light profanity filter on its base name ([[R1432]]); there is no list of reserved names, so `Player` and `admin` are names like any other ([[R1434]]). The server refuses a base name that holds a word of a short blocklist compiled into it (`crates/server/src/username/blocklist_anywhere.txt` and `blocklist_token.txt`, read by `include_str!`), English to start; other languages' words may be added to the files later. What is matched is the name NFKC case-folded, stripped of combining marks (NFD, then every `M*` dropped, so `fück` matches `fuck`), stripped of underscores, read back from the common digit substitutions (`0` as `o`, `1` as `i`, `3` as `e`, `4` as `a`, `5` as `s`, `7` as `t`), and read as the plain letters that the Latin small capitals (`ᴀ`, `ʙ`, `ᴄ`, …) and the dotless `ı` and `ȷ` imitate, which NFKC and the case fold leave alone, so `ꜰᴜᴄᴋ` and `Bıtch` match as their plain spellings do (the name keeps them; only the filter reads them so). The anywhere list, slurs and the strongest profanity, which rarely occur inside an innocent word, refuses a name that holds its word anywhere. The token list refuses its word only as a whole token: the name as typed is split on underscores, at each boundary between a letter and a digit, and at camelCase (a lowercase letter followed by an uppercase one), and each token is read as above, so `Scunthorpe`, `Cassandra` and `Assassin` pass while `BigAss` and `my_ass` do not. Before that split, the substitution digits in a run of letters (the letters, marks and substitution digits between underscores and other digits) are read back as letters, and the name is split twice, since a digit at the edge of a word may be a letter or a number after it: once with every such digit read back, so `a55`, `my_a55`, `BigA55`, `5h1t` and `d1ck` are refused, and once with only the digits that have a letter on both sides read back, so a number beside a word splits off and `Dick1`, `1Dick` and `Ass420` are refused too. `Bob455` reads as the one token `Bobass` (or `Bob` and `455`) and `Tit4n` as `Titan` both ways, and they pass. A run with no letter keeps its digits, and a token with no letter in it is never matched against the token list, so the digits of `Bob_455` are not read as `ass`. A refusal says only "That name isn't allowed." and never echoes the word it matched ([[R1435]]). The filter is light by design: it stops the obvious cases, not every evasion.
