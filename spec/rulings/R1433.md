title: "The light profanity filter on usernames (issue #579)"

A username's only content check is a light profanity filter on its base name ([[R1432]]); there is no list of reserved names, so `Player` and `admin` are names like any other ([[R1434]]). The server refuses a base name that holds a word of a short blocklist compiled into it (`crates/server/src/username/blocklist_anywhere.txt` and `blocklist_token.txt`, read by `include_str!`), English to start; other languages' words may be added to the files later. What is matched is the name NFKC case-folded, stripped of combining marks (NFD, then every `M*` dropped, so `fück` matches `fuck`), stripped of underscores, and read back from the common digit substitutions (`0` as `o`, `1` as `i`, `3` as `e`, `4` as `a`, `5` as `s`, `7` as `t`). The anywhere list, slurs and the strongest profanity, which rarely occur inside an innocent word, refuses a name that holds its word anywhere. The token list refuses its word only as a whole token: the name as typed is split on underscores, at each boundary between a letter and a digit, and at camelCase (a lowercase letter followed by an uppercase one), and each token is read as above, so `Scunthorpe`, `Cassandra` and `Assassin` pass while `BigAss` and `my_ass` do not. A refusal says only "That name isn't allowed." and never echoes the word it matched ([[R1435]]). The filter is light by design: it stops the obvious cases, not every evasion.
