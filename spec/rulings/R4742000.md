Not a rule of the game (CLAUDE.md rule 7): where a finished game's result lets the player go.

Going back to the menu is the button players click most once a game ends, yet only the online match
("Back to the lobby") and the dev hotseat put a way back on the result itself. The practice result and
the lesson result had none, the dungeon run-over screen only a corner link scrolled off above its
statistics, the dungeon and Assault fights' result panels (Continue, Retry) only the board's Menu
behind the panel, and the daily and co-op results only a button to their own hub.

**One button.** Every mode's result offers **Main menu** (`t("Main menu")`), drawn by one shared
component (`game/MainMenuButton.tsx`; the two Dialog results use the same label as an answer in their
row, [[R3220000]], [[R3221000]]), and it comes after the mode's own ways on, never first: Continue,
Play again, Next lesson and Retry keep the first place, the primary look and the focus. It decides
nothing: each result hands it where to go.

**Where each goes.**

- The practice result and a lesson's result reuse practice's `onMenu`, as the board's Menu does once the
  game is over: it gives the free game up ([[R668]], [[R765]]) and leaves in one click; a lesson's progress
  is already kept by its result.
- The dungeon and Assault fights' result panels reuse their board Menu's handler, so a finished fight's
  Menu and the panel's Main menu do the same thing: the dungeon's sends the fight's report to the run
  first ([[R4733000]]) and goes to the Play menu without asking, the Assault's sends the fight's report to the attempt first and then leaves ([[R3932000]], [[R4582001]],
  [[R2972000]]); the leave guard is already released once the fight has its result ([[R1754000]]).
- The dungeon run-over screen, the daily game's result (a finished game and an expired one, [[§9.13]])
  and the co-op result go to the Play menu (`paths.play`), as the online match's "Back to the lobby" and
  the mode screens' back links do. The run-over screen leaves the run as it is: only Start a new run
  gives it up. The co-op result draws it only where its route hangs a way to go (`DuosChrome.onMenu`):
  `/dev/duos` has none. The daily result keeps Back to daily games, and the co-op result Back to Play
  together; Main menu sits beside them.

**Practice's menu leaves for the Play hub's Solo group.** The owner decided that practice and the
tutorial go to `/play`, landing on the group with the Practice card, and not to the landing page.
Practice's `onMenu` is that one place: the board's Menu control, its leave question's Leave without
saving and Save and leave, the practice result's Main menu and the lesson result's Main menu all end
there ([[§9.9]], [[§9.10]]), through `playSoloPath()` (`/play#solo`). The Play hub reads that fragment
once, on arrival: it scrolls its Solo group into view and focuses the Practice card; a plain `/play`
is left as it was. A move to a path with a fragment is held as any other move, and is the same address
only with that fragment too, so the same target made twice stacks no history entry; a fragment alone is
still the same screen, with no cross-fade and no scroll to the top ([[R2117000]]).

Not changed: the watch route and the assault day screens, which already have a corner arrow to Play,
and the load-error screen of a daily game, which is no end of game.

Presentation only: the client sends intent and renders the view (CLAUDE.md rule 7).

Hearthstone semantics: once a game is over, leaving to the menu is one click on the result.

Rejected: making Main menu the first answer or replacing a hub button with it (it would take the focus
and the primary look from the way on, or hide the player's way to their own mode's hub); leaving
practice's Menu at the landing page (the owner chose the Solo group, which is where Practice and the
Tutorial are, and the match, dungeon and Assault already leave for Play); putting `/play#solo` in the
`paths` table (its strings are routes the Worker must serve and the search index lists, and a fragment is
none); a hand-written button on each screen (one label in one place).
