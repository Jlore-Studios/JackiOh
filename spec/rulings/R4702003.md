Issue #1602 gave the evaluation two terms that shipped at weight 0 in both weight sets, so neither ran: `enemy_face_down_per_cost`, a price per crystal of the cost a backrow card the seat cannot read shows ([[R351]]), and `fatigue_draw`, a price per fatigue draw a side has taken ([[§2.4]]). Both are removed, with the read only the first used (`shown_cost`) and the tests that pinned them at other weights. Every evaluation is what it was, to the bit.

Their screens, which the config comments held: `enemy_face_down_per_cost` at 0.8 read 201-199 on the dev set, edge +0.005 (-0.017 to +0.027), 5 decided of 200 (won 3, lost 2); `fatigue_draw` at 1.0 read 199-201, edge -0.005 (-0.022 to +0.012), 3 decided of 200 (won 1, lost 2). Both inconclusive ([[R4319000]]). A new screen of either restores it from git first (`crates/ai/src/evaluate.rs` and `config.rs` as commit `e29de6c3` holds them).

Kept: the weights that are 0 today but stand in a table every keyword or term has a row in (`KeywordWeights`' rows, `dormant_card`, `drawn`, `position_grants`): a row is data, and taking one out removes no code a decision could not already skip.
