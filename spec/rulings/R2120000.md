[[§9.5]] said nothing of a message between the moment a player sends it and the moment the server answers: the panel held Send and showed the message only once the answer came.

A message the player sends shows at once at the end of the conversation, marked as sending, and the draft clears so the next can be written. Sends go to the server one at a time, each after the answer to the one before it, so the server stores them in the order sent. Messages still waiting for an answer come after every message the panel has read, in the order sent, and the server's copy of one (with its word filter applied, [[R1433]]) replaces its pending row when it answers. While any send is queued or on its way, a read of the conversation takes only the friend's messages, so a message the read brings back before its send has answered is never drawn beside its pending copy and shows once. A refused or failed send is marked failed in the server's own words, never the panel's, with Retry, which sends the same body again in the row's place, and Discard, which drops the row and sends nothing. Closing the panel forgets a failed send, while one already on its way still reaches the server.

Game actions still wait for the view ([[§10.8]], CLAUDE.md rule 7), and the shop and pack openings still wait for the server. The server alone decides what is sent; the panel only shows the player's own text to the player until the server answers.

Hearthstone's whispers say nothing of a send in flight, so this follows the common messaging pattern.

Rejected: sending in parallel, which the server may store out of order; and matching a read's message to a pending one by its body, which the word filter changes and which is ambiguous for two equal sends.
