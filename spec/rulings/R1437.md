title: "A result the store fails to take keeps the match live (issue #621)"
cards: "§9.5, R112, R263, R679"
proven_in:

---
The match actor's write of a finished game's result is the whole ending, in one transaction: the `results` row, the rating move, both players' in-match state, the match row's `finished` state and a series game's record ([[R263]]) land together or not at all, and nothing finishes the match row apart from it. A write the store fails is tried again, `MATCH_RECORD_RESULT_ATTEMPTS` (3) tries in all, waiting `MATCH_RECORD_RESULT_BACKOFF_MS` (250 ms) before the second and twice as long before each one after; a try that finds the result already written takes that row. When every try fails, the match stays `live` and both players stay in it. The actor leaves memory and closes both sockets as a restart does, without a code the client treats as final ([[R679]]'s is), so the client reconnects; the next socket rebuilds the actor by folding `(seed, log)` ([[§9.5]]) to the same ending, and the rebuilt actor writes the result as it arms. A match no socket comes back to is left to the reaper's ceiling draw ([[R112]]).
