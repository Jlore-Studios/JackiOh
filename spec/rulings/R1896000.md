title: "A result clears a seat's in-match flag only while it names the result's match (issue #1896; amends R890000)"

Every ending records a result and clears both players' in-match flags in the same write ([[§9.5]]). The write cleared each seat's flag whatever match it named, while every undo of a failed start already cleared only a flag that names the match being undone ([[R890000]]). So a result for an older match that landed after a player was seated in a newer one, a retried write or the reaper's, erased the newer match's flag, and that player's socket, which a live match admits only while the flag names it, could not get back to the table. That clear also erred on a seat whose profile row was gone.

Now the result write clears each seat's flag with the same conditional clear, only while the flag still names the match the result is for. The clear refuses nothing: a flag that names another match is that match's state, not this ending's, and stays, and a seat with no profile row has no flag to clear and raises no error. A results row that names a missing profile is still refused by its foreign keys (migration `0012_account_deletion`), and an account cannot be deleted mid-match, since `DELETE /api/account` refuses while its flag is set and 0012's `matches_seats_filled_unless_over_check` refuses a delete that would empty a seat of a match that is not over. Everything else the write does is unchanged ([[R1437]]). This follows Hearthstone, where finishing one game never ends another.

Rejected: keeping the unconditional clear and trusting the seat ledger ([[R1523000]]) to keep a player out of two matches. The ledger guards the doors, but the flag is the record that a socket's admission and the ledger's boot fill read, so a write that clears another match's flag breaks them all the same.
