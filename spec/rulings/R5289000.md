Amends [[R1329000]], [[R2173000]], [[R3882000]] and [[R5268001]] on how their files are written. The card data JSON is laid out a record per line rather than two-space: each container nested less than its file's record depth opens and closes on lines of its own, a member a line (`"key": value`, two spaces a level), when it is the file's root and not empty or when it holds an object or an array; every other container, each record among them, is written compact on its member's line, keys and numbers as written, and the file ends with a newline. So a list of ids (a delta's `unset`, a card's versions in `index.json`) stays on one line. Only white space outside strings changes, so every file parses to the same JSON, key order included, and the catalog the build compiles in, the deltas it folds and every replay's hash are the same.

The depths are `format_json.rs`'s constants: 1 for `crates/cards/catalog.json` (each card under its id), `chinese.json` and `flavour.json` (each card's entry), `patches.json` and `technical.json` (each element of the array), `index.json` (each id's versions), `card_metrics/` (each list) and every table folder's `versions.json`; 2 for each delta under `deltas/` (each card under `set`), each table under `records/` and `win_rates/` (each row of `cards`), `analysis/fixtures/dev-40.report.json` (each row) and `apps/web/src/audio/voice-manifest.json` (each line's entry under `files`). Every writer of these files lays them out the same way: `patches ship`, `cut`, `encode` and `retcon` (`patches_io::write_records`), `patches log`, `stats report --json`, the card-text export and `gen-voice.mjs` (through `json-layout.mjs`, `json_layout.rs`'s copy, which its test holds to the same bytes). `cargo jackioh format-json` lays out any file that is not (a hand edit of `catalog.json` among them), and `format-json --check`, which the tools' acceptance test runs on the tree, fails naming each.

`shipped.json`, `order.json`, `aliases.json`, the pending fragments and `voice-text.json` stay two-space. A snapshot's `blob` still hashes the two-space form [[R5268000]] names, which no file holds. A table's blob (`winRatesBlob`, `cardMetricsBlob`, `recordsBlob`) hashes the bytes it shipped as: its file's own bytes for a table shipped from this ruling on, and its two-space form for every one shipped before it, whose entry keeps that blob ([[R646]]: a shipped entry is never amended). The 333 files were 284,015 lines in the two-space form and are 19,883 laid out (the 147 the layout changed went from 283,143 to 19,011); the repository, measured on `main` at 551fc4c6c5 and on the branch built on it, went from 2,796,414 tracked lines to 2,533,094.
