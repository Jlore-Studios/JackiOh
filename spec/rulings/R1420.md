A set ships when `SHIPPED_SETS` lists it. A set the catalog holds before that, as the Meditative set is while issue #496 builds it card by card on `main`, is in the catalog, its cards scripted and tested like any other, and nowhere a player meets it: in no pool that names no set ([[R380]]: a pool that names no set draws from the sets that ship), so no random card, Discover, cast, determinization ([[R185]]) or AI deck ([[R184]]) reaches it; in no deck, since [[§9.4]]'s L3 refuses its cards as it refuses Tokens and `create_game` refuses them too, so no All Random deck ([[R258]]) or saved deck holds one; on no list a player reads (the Almanac's shelf and the deck builder's pool, [[R630]]); in no patch (its entries are left out of every snapshot, no fragment claims them, and `patches check` and `patches ship` read the catalog without them, [[R646]], [[R388]]); not seeded into the server's `cards` table, so no account is granted one, and not in the server's catalog (`GET /api/catalog`, the deck checks, the card statistics, [[§9.11]]). A pool that names the set (`set: "Meditative"`) or names its cards by id still reaches them, so a card of the set finds its own tokens and its set-named pools.

A set keeps its place in the catalog order (`CATALOG_SETS`: Core, Classic, Classic+, Meditative) before and after it ships, so a seeded pick over a pool that holds it replays the same on either side of the patch.

Under the testkit alone, a thread may preview a set that has not shipped (`preview_sets`, `preview_every_set`): pools that name no set and the deck checks then treat it as shipped on that thread only, so a test can deal its cards and the fuzz tool deals from every set (its pool is the whole catalog, each seed previewing every set on its worker thread). A production build has no preview. The golden traces deal from the shipped sets alone, so a set being built never moves a recorded game.

`catalog check` holds a set that has not shipped to its shape alone: every entry it holds is one of the indices its brief lists, once, with the id its index implies, and no rarity passes its count; none of its entries counts toward the totals or the tag census. The cards crate's fixture holds every entry it has to its row and lets a row wait for its card. The patch that adds the set to `SHIPPED_SETS` claims every one of its entries in one fragment, and from then on the set is held to every count like the others.
