The tutorial's Legendary and Mythic cards must not show up before its last lesson, in the lesson's
random cards too. So a handicap ([[R180]]) takes one more optional field, `poolHold`. A game whose
either seat's handicap sets it holds Legendary and Mythic cards out of every random pool it draws
from. It is a handicap field, not a game setting, so it travels in a lesson's replay inputs
`(seed, decks, handicaps, log)` with nothing new, and it is serialized and stored only when true, so
no other game's state, hash, replay or golden trace moves. Lessons 1 to 4 of the remade tutorial
(issue #2205) set it on the human's seat; the last lesson does not; nothing sets it before then.

What it holds:

- **Every `catalog::query` pool**, the one source of random pools and Discover ([[§5.1]]): add,
  summon, Discover and cast random, transform, fuse, shuffle-random, Call to Chaos's rolls, the Night
  Market, and every card script that draws from a query. A query that names one card by id is a
  lookup of that card, not a pool, and is not held; one that names several (a random Miner) is.
- **The weighted tables** (`roll_weighted`, [[R960]]): a held entry is left out and the rest roll by
  their own percents, so a Grape pick never rolls the Mythic Grape ([[R382]]); a table with nothing
  left rolls nothing.
- **The Marketplace's lots** ([[R1853001]]) and **Resource rolls** ([[R1840002]]) offer no held card.
- **Anomaly Found!'s random board** ([[R1879000]]) is drawn from the boards that lay no held card
  ([[R2204002]]).
- **The win-rate picks** of CN Tech and NA Tech ([[R1100]], [[R1183000]]) rank without a held card
  ([[R2386001]]).

What it does not hold: a card the text names outright ("Add a Badger, Honey Badger, Ozark, Orca and
Galaxy"), as [[R1420]]'s gate lets a named card through; a card only a rule makes ([[R1857001]]'s
Dormant Starship); the lesson's own dealt decks and what a Recruit takes from them.

The hold is read without the state, because most pools are built with none in reach: a thread-local
that each engine entry point that steps a game sets for its one call from that game's handicaps and
puts back after it, a panic included (`catalog::with_pool_hold`, CLAUDE.md rule 4's third engine
thread-local). The entry points are `reduce`, `reduce_unpiloted` and `begin_game`; `create_game` draws
from no pool. Every caller that generates cards goes through them:

- the browser (`crates/wasm`): `create_game`, `begin_game`, `reduce`, `fold`, `replay_open` and
  `replay_page`, the Duos `duos_begin` and `duos_reduce`, and the AI's `ai_decide`, `choose_action` and
  `lethal_hint`, whose search steps through `reduce_unpiloted`;
- the server (`crates/server`): the match actor's `create_game`, `begin_game`, `reduce` and `fold`,
  the Duos actor's `duos_reduce` and `fold`, and the bots' calibration games;
- every fold (`replay::fold`), the AI's matches (`play_match`, `play_ai_turn`) and the tools.

So a held step nested in an unheld one, or the reverse (the AI's search, the autopilot), reads its own
game's hold, and an unheld step after a held one on the same thread reads none. An AI estimate made
outside a step (`scorer::perfect_pool`) reads the unheld catalog: it is an estimate, never what a game
generates.

Hearthstone semantics: a scripted encounter deals from a pool of its own choosing, and the hold only
narrows each pool; every other rule of a pool stands.

Rejected: threading the state into every `query` caller (some 80, many card scripts with none in
reach); and a game setting beside the handicaps, which every replay input, the server and the web's
replays would have had to learn to carry.
