A Trap or Field Trap that goes face-down into a backrow — played from hand, cast ([[R70]]) or recruited ([[§6.3]]) — takes a fresh instance id as it goes, the next number, as a new card takes one. So the only handle the action protocol has for a face-down card (a play's target, a prompt option's answer, [[R177]]) is an id no player has seen before: an id seen while the card was public — a trap returned from its owner's graveyard to hand and set again, a card revealed from a library — never names it in its zone. It is the same card, not a new one: its flags and its cost history go with it. The `cardPlayed` and `summoned` events that set it carry the id it had as `formerId`, so the events that named the old id are judged by where the card is now, exactly as they were before ([[R97]]), and its controller's client finds the hand card it came from; a view that hides the card hides `formerId` too. Whether a card goes face-down is public ([[§10.8]] shows the zone occupied), so the number it takes says nothing. A Unit, a Field Spell, and a face-down card that moves or changes controller keep their ids
