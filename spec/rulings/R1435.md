A player may change their username once every `USERNAME_CHANGE_COOLDOWN_SECONDS` (24 hours). The first pick away from the default ([[R1434]]) is never blocked, and starts the clock. While the player types, the client asks the server for a preview, `USERNAME_PREVIEW_DEBOUNCE_MS` after the last keystroke: `GET /api/username/preview?name=…` answers either the exact username a save would give, in its stored NFKC form ([[R1432]]), saying whether the player would be given a tag ("Max is taken, so you'd be Max#3"), or why the name is refused: its characters, mixed scripts, its length, the filter ([[R1433]]), the name already being theirs, or the cooldown, with the time the next change is allowed. A save (`PUT /api/username`) sends the username the preview showed; if the outcome has changed since (someone took `Max` first, so the player would now be `Max#1`), the server refuses it with 409 and returns a fresh preview, so a player never ends up with a tag they were not shown. The preview and the save count against the per-account API limit like every other request ([[R109]]).

Once an account becomes active, right after its invite code is redeemed, its player sees a username prompt before anything else on the gated screens: the same field and preview, and "Skip for now" (`POST /api/username/skip`), which keeps `Player#n`. The prompt shows at each sign-in until it is answered, by a pick or a skip, and never after; a pending account still sees only the code screen ([[§9.4]]). `GET /api/auth/me` carries the player's own username, when they can next change it and whether the prompt is still owed, and nothing else carries the last two ([[R1436]]). The account page (`/account`) shows the username and a field to change it, and during the cooldown when the next change is allowed. The fixture accounts that `seed-accounts` and the end-to-end seed ([[R144]]) create get fixed usernames and are marked as prompted, so no end-to-end spec meets the prompt; an account from before migration 0028 sees it once.
