An account may add an authenticator app (a TOTP factor) on its account screen: enrolling shows a QR code and the key, and the factor counts only once a code from the app is typed, which also raises the session to the provider's `aal2`. Signing in by any way (password, email code or link, OAuth) to an account with a verified factor holds the session, in memory only, until the app's code is typed, and keeps only the `aal2` session that comes back; leaving the step revokes the held one. A recovery link for such an account asks for the code before the server is asked whose it is. The server honours a token for an account with a verified TOTP factor only at `aal2`: whether the account has one is read from the provider's user, never from the token, and the last such answer is remembered per user, so an outage cannot lower the bar; an unverified factor does not count. Removing the factor asks first and needs an `aal2` session (the provider's rule). The Data API's reads of a player's own rows are not raised to `aal2`: they reveal nothing the account's owner could not see, and every write goes through the server
