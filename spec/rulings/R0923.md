## R923 — Granted tags

`grant_tag` is an effect verb: `grant_tag { target/instanceId, tag }` gives the live card the tag
as a NEW `CardInstance.granted_tags`, once, silently. No event. Every read of an instance's tags
goes through the new `tags_of` (read off the state, same access cost as `def_of`), which group
B's list says (targets, scopes, declarations, filters, picks, plays counted by tag), with one
exception: Meditative #52 Economic Anxiety compares printed tags by its own ruling ([[R1120]]). A card that
already has the tag keeps one entry. Group B knew the full list: its Systems say which part builds
each read (and a later batch that uses tags first checks the list again). As built, the reads are
`targets::matches_scope`, `card_scope::matches_card_scope`, `play_choices::card_allowed` and
`play_choices::tagged_play_radiant`, `summon::matches_filter`, `choose::pickable` and
`play_counts::record_play`; the shipped scripts are Classic #4's steal (which reads the announced
card itself when it still exists, else its definition), Core #92's sum and Classic+ #46 and #46.1's
auras. Catalog pools never see them. A card copy keeps them (an instance copy: summon, copy,
library copies, shuffled-in copies); a Fuse unites them; a Transform drops them; T-AI-5's record
keeps none; a placeholder carries none. New field, new view key (only where it differs from the
definition's, never on a hidden card), new AI redaction, new client face field (which lists the
view's tags in play, the definition's outside it).
