[[§9.5]] pages a conversation `CHAT_PAGE` messages at a time, newest last. Both stores already ordered a conversation by the time a message was sent with its id breaking a tie, but an earlier page was asked for by the oldest message's time alone, so the messages that shared that millisecond with the page's oldest were skipped when the page before it was read. `send`'s stamp (a millisecond after the newest message it reads) does not prevent a tie: two sends that commit at once both read the same newest message and take the same time.

The order of a conversation is `(sent at, id)`, in the fake and in Postgres alike. A page answers `nextCursor`: the opaque cursor of its oldest message while the page holds `CHAT_PAGE` messages, else `null`, since a page short of `CHAT_PAGE` has nothing before it. The page before a cursor is the newest `CHAT_PAGE` messages that come before that message in this order, so a burst sent in one instant, whatever its length, reads every message exactly once and in order across any page edge.

The cursor is the message's time in epoch milliseconds, `_`, and its lowercase hyphenated id. The client sends it back as `before` unchanged and never reads or builds one ([[§9.1]]'s line between the client and the rules). A `before` the server did not write, an ISO time among them, is refused with 400 before any message is read; the server reads a cursor only in exactly the form it writes (a time of at least 0 written without a sign or a leading zero, an id in the one lowercase form), so the fake's string order of ids and Postgres's byte order of uuids agree. An absent or blank `before` gets the newest page. Show earlier uses the cursor the last page answered and shows while it is not `null`.

Hearthstone has no paged chat history, so this follows the standard keyset page.

Rejected: relying on unique timestamps, since concurrent sends tie; and an offset, which shifts as messages arrive.
