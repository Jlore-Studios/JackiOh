[[R1372]]'s and [[R1373]]'s switch, "More cards from the newest set", becomes a picker: "More cards from" none, "The newest set (…)", or any set that ships, in catalog order. The default is none, as the switch was off.

- **The choices** are "newest" and each set that ships ([[R1420]]), and nothing else: a set the catalog holds that has not shipped is no choice, and the server and the practice worker refuse it as a malformed request.
- **"Newest" keeps the switch's meaning:** the newest set that ships when the deck is dealt ([[R1371]]), resolved by the dealer, never written down by the client. A set picked by name is that set, whichever set is newest.
- **The deal** leans on the picked set exactly as the switch leaned on the newest one: at least `AI_DECK.leanMinShare` of the deck from it, a hard floor kept with the units' and the theme's, the rest dealt as without it ([[R1370]]). Only the asking seat's deck leans, and a ticket, room or rematch offer that picks one set pairs with one that picks another, or none.
- **On the wire** the pick is `leanSet`, `"newest"` or a set's name, on the queue's enqueue in All Random, on an All Random room's create and join, on a rematch offer, and on practice's Random deck choice. Absent or `null` is none. A client from before the picker sends `leanNewest: true`, which reads as "newest"; a body with both reads `leanSet`.
- **Stored picks keep their meaning.** Migration 0036 holds the pick as text (`tickets.lean_set`, `matches.room_lean_set`): a ticket or an open room stored with the switch on reads "newest", and one stored with it off reads none. A device that remembered the switch on reads "newest" until a pick is written, and a practice game kept to resume or to replay before the picker ([[R668]], [[R768]]) deals the same deck again.
