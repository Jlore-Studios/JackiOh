A dungeon run left half-played across a card patch picks up where it stood, on the map it was
dealt. The device keeps the catalog version with the run file when the run starts, and folds the
run under that version's content: the build's own for a run started today, the carried shipped
version's for an older one (`run_content_at`, [[R767000]]'s precedent for kept games). The rest of
the run then plays on the content it was dealt from. A run kept before versions were kept folds as
today's.

A run whose version this build no longer carries, or whose log no longer folds under a carried
version, cannot be replayed at all. It settles once as lost with no row, no score and no
Embers, because nothing can be folded to score it ([[§15.8]]), with the time played it was kept with ([[R3502000]]: never the calendar's gap
since it began, which a run left across a patch always holds), and still banks what it had
extracted of the cards and artifacts the current content knows. A version the bindings throw on is dropped silently, as before: a transient failure
must never mint a history record. The start screen says what happened in one line, and the stored
extractions are device data, as the whole Sandbox is (DR1), filtered against the content, never
trusted blindly. No migration: a run file of the old shape still parses, with no version.

A fight's game is built under the current catalog, as a fight started today is ([[§15.6]]). A card
the run holds that the catalog no longer knows is left out of the fight's deck, human and enemy
decks alike, with the marks re-indexed; it stays in the run. The kept fight still drops across a
patch ([[R3476000]]) and is dealt fresh from the filtered setup.
