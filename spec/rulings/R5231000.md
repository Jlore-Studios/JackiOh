[[R4977000]] named the match screen as the one place that refreshes after a paid result. A daily game's result is written by the same `record_result` ([[§9.13]]), but `DailyBoard` told nothing: the wallet answered the old balance inside `READ_CACHE_FRESH_MS` ([[R3206000]]), the kept quest, track and pack reads and the owned cosmetics ([[R4780000]]) were not dropped, and the page's proficiency copy stayed old, so a level the game reached did not show and its stamp could not be picked, until a reload.

A board showing a game that is over and whose result is not `voided` calls `announceWallet()` and `reloadOwnProficiency()` once per board. This holds for the move that ends the game, a reread that finds it ended on the opponent's move or on time ([[R3727000]]), and a board opened on a game already over (for example from its "game ended" notification). A `voided` game pays nothing, a running game has not paid, and an expired game ([[R3934000]]) has no board, so none of them announces. Later rereads, rerenders and the auto-end-turn setting's resend announce nothing more. The board remounts per game, so the once is per game.

Two cheap reads (the wallet and `GET /api/proficiency`) each time a finished daily game's board opens, the cost [[R4977000]] accepted per counted game.

The client decides no balance and no level (CLAUDE.md rule 7): it shows what the account answers.

Hearthstone semantics: a reward earned in a game is usable when the game ends.

Rejected: announcing only on the board's own change from running to over (it misses a game the opponent ended while the player was away and that the player opens from its notification); announcing from the Daily list's poll (the list is often not open when a game ends, and the board is where the result shows); the read carrying the payout (a server wire change to save two reads).
