[[R1420]]'s preview reaches the browser, in development builds only. The WebAssembly module `scripts/build-wasm.sh` builds by default (development, the web's unit tests, the e2e client) carries the engine's testkit behind crates/wasm's `preview` feature and binds `previewSets(sets)`: from that call on, the module treats those sets as shipped, as a previewing test thread does, so a deck may hold their cards and a pool that names no set reaches them. The production bundle's module is built without the feature (apps/web's `prebuild`, `JACKIOH_WASM_PREVIEW=0`) and refuses any set, so no player meets a set before it ships and [[R1420]]'s "a production build has no preview" holds.

Its one caller is the dev hotseat route's E2E injection (`preview`, read only outside a production build), which previews before it creates the game; the route's readable deck pre-check then accepts the previewed set's cards as the engine will, and still refuses a Token ([[§9.4]] L3). The dev decks deal from what ships, previewed or not. A game played so replays only on a module that previews the same sets. Spec 36 plays every card of the Meditative set this way: its decks from the catalog, its seats handicapped ([[R180]]), each card played once through the browser. Presentation and test tooling only (CLAUDE.md rule 7).
