**Why.** The raw record is purged `GAME_RECORD_RAW_RETENTION_DAYS` after it is folded ([[R1044001]]), so the variants, makers and picks ([[R4672000]] to [[R4672002]]) must reach the totals to outlive it.

**The totals.** Each card's totals row ([[R1044000]]), under the same key (patch, source, mode and the seat's pilot), holds three more lists in its stats, each a seat once a game as every figure counts it ([[R1147000]]), each split by face:

- `variants`: by a variant's label (its options joined by `VARIANT_MODE_JOIN`, then `X=<x>`, then Embiggened or Not Embiggened, joined by `VARIANT_PART_JOIN`), the seats that played the card with that variant at least once, by the card's face at that play; a seat that played two variants counts in both.
- `outputs`: by output card, the seats whose copy of the card made it at least once, used or not, by the face of the copy that made it.
- `offers`: by offered card, the seat-games the card's Discover-like choices offered it in and those they picked it in, by the asking copy's face.

They are kept as new keys of the row's `card_totals.stats` JSON, as [[R2089000]]'s Created tallies were, absent while empty: the store reads, adds and writes the row whole in the transaction that folds the record, so no migration, no second read and no second write is needed, a total written before them reads as none, and a record written before them adds none. The report reads them apart from the deck and Created rows (`CardStatsReport.choices`), and no row a client reads carries them: `GET /api/stats/cards` and the windowed report answer as before.

**Where it shows.** `jackioh-server stats-cards --card <id>` and `cargo jackioh stats report --card <id>` print the card's variants table and its outputs table (made by face, offered and picked) after the tables they printed, and `--json` writes them as `choices`. An AI development run builds its records with the same `summarize_game`, so its files carry them too. No back-fill and no refold: the splits start with the games played after this change; a record already folded was summarized without them, so folding it again would add nothing.

Rejected: a table of their own, which needs a migration and a second read and write per record; counting every play or output rather than seats, which every other figure avoids; and keeping them in the record alone, which the purge empties.
