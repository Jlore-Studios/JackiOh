The two-step code of [[§9.4]]'s sign-in (the authenticator app's 6-digit code, [[R665]]) is typed into one field drawn as six boxes, one digit per box, read as digits only. It reuses the invite code's field ([[R191]]): one real `<input>` with transparent text over six `aria-hidden` boxes, so paste, autofill (`autocomplete="one-time-code"`), undo and screen readers keep working; six separate inputs would lose SMS and keychain autofill, partial paste and undo, and read as six unlabeled fields. Its alphabet is its own: [[R104]] leaves out `0` and `1`, which a TOTP code needs, so the digits format is `0-9`, length 6, one digit per group, no separator (`TOTP_CODE_FORMAT`). The email code ([[R664]], 6 to 10 digits) keeps its plain field.

Rejected: six separate inputs, against the autofill, paste, undo and screen-reader handling above.
