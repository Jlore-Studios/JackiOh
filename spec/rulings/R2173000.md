[[R1846003]] owed, before the first card that reads the BUSTED or complicated lists ([[R1846000]]) ships, each shipped version's own lists, kept with its patch and read under a fold, as [[R1329000]] keeps each version's win-rate table. They are kept so:

- **The file.** `cargo jackioh patches ship` writes `crates/cards/patches/card_metrics/<version>.json`, `{ busted, complicated }`, each a sorted list of catalog ids, for every version it ships whose snapshot holds a card whose script reads the lists (a catalog query's `busted` or `complicated`, or the engine's `is_busted` and `is_complicated`: Stinkyscape #109 xxFreshJack and #111 Shockwave447). The lists are the ones the scripts make as they stand when it ships, counted by the counter the build compiles its own with (`jackioh_cards::code_lines`, which `crates/cards/build.rs` includes), against `BUSTED_CODE_LINES` and `COMPLICATED_CODE_LINES` as `crates/engine/src/config.rs` states them. `shipped.json` records the file's git blob (`cardMetricsBlob`) beside its snapshot's and its table's. A version that holds no such card keeps no file, and the version retcon ([[R1371000]]) renames a file with its version. The folder is beside the snapshots, as `win_rates/` is.
- **The fold.** `crates/cards/build.rs` puts each carried version's file into `history.json`, identical lists once, and that version's shipped catalog ([[R767000]]) carries them (`with_card_lists`). While a replay folds under it, `card_metrics`, and with it `is_busted`, `is_complicated` and the catalog query, answers that version's lists. A version with no file answers the build's, as before: it shipped before any card read the lists, so no game on it could read them. The code lines (`code_lines_of`) stay the build's under every fold: no card reads a count. `patches check` fails a carried version whose lists are not its file's, or that carries lists with no file.

The first version to carry lists is the one the Stinkyscape release (#1884) ships #109 and #111 in: its file is written when `patches ship` runs after the release merges. No version shipped before it has a file, so every fold of a shipped game reads what it read before, and no recorded hash moves.

Rejected: keeping the code lines per version too. Every script edit moves some count, so every version would carry a table of several hundred rows that no game reads; only membership in a list reaches a pool.
