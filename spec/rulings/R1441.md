A match socket that dies without a close (a laptop that slept, a phone that changed networks) used to keep its seat present until the operating system's TCP keepalive gave up, two hours by default, which is past the match ceiling: the 60 s disconnect grace ([[R79]]) never started, the opponent waited out the turn clock on every one of the absent player's turns, and the dead socket held one of its address's sockets. Three numbers in the server's config now find it, and each is read off a constant, never restated: `WS_PING_INTERVAL_SECONDS` (15), `WS_IDLE_TIMEOUT_SECONDS` (45) and `WS_OUTBOX_MAX_FRAMES` (256). The first two are the interval and three times it, so a slow mobile link that loses a pong or two is not dropped and the ping keeps the path open well under the minute common proxies hold a quiet connection to.

The server pings an attached match socket every `WS_PING_INTERVAL_SECONDS`, and drops it when no frame of any kind, a pong included, has arrived for `WS_IDLE_TIMEOUT_SECONDS`. Every frame the server writes, a ping and a close included, is bounded by the same deadline, so a peer that stops reading cannot hold the connection and its address's slot until TCP gives up. The drop sends no closing handshake, which a dead peer could not answer, and is the ordinary end of a transport: the actor detaches the seat, its grace starts and the opponent is shown the deadline ([[§9.5]], [[R147]]). A socket that answers its pings stays open for as long as it does. Pings run only while a socket is attached, so a server with none still sleeps on Render's free tier.

A match socket's outgoing queue holds at most `WS_OUTBOX_MAX_FRAMES` frames. A frame that finds it full closes the socket: the queue is let go, the transport sends what it holds and ends the connection, and the actor sees an ordinary disconnect. Views are full snapshots, so the reconnect that follows loses nothing ([[§9.5]]), and a peer that stops reading cannot grow the server's memory without limit ([[§9.8]]). The close handler never runs inside the send, because the actor sends while it holds its own lock and that handler takes it.

The client's half is a probe, not a drop. A browser answers the server's pings without telling the page, so a socket in a long quiet turn looks the same to the page as a dead one. When the tab turns visible or the network comes back (`online`), a socket the page has heard nothing from for longer than `WS_PING_INTERVAL_SECONDS` is sent a `hello`, which the actor answers with a full view and nothing else ([[§9.5]]); if nothing comes back in 5 s it is closed and a new socket takes its place, which sends its own `hello`. A socket that never opened by then is replaced at once. A healthy socket answers and is kept, so a tab switch never flashes the opponent's disconnect grace. Each reconnect backoff also gains up to 25% of itself at random, so clients a restart dropped together do not return on one beat; it only adds time, so the first retry never comes before 250 ms. The grace stays `DISCONNECT_GRACE_SECONDS` (60): a dead socket now loses its match 45 + 60 s after its last frame, which is already longer than a turn.
