A room's host can share it as a link instead of a bare code: `/play?room=CODE&mode=<mode>`, with the room's own code and mode. The room ticket's Copy invite link opens the browser's share sheet where it has one and writes the link to the clipboard where it does not. A share that is closed or a clipboard that is refused says nothing, as the code's own Copy button does, and a failed share does not fall back to the clipboard.

A lobby opened on a link reads it once. `room` and `mode` leave the address bar at once (other parameters stay), so a reload or Back never refills a code that is stale by then. The code is read as a typed one is ([[R191]]): checked against the room code format, six characters of [[R104]]'s alphabet in any case and with any spacing. A code that fails is ignored quietly, with no notice and no error, and one that is stale fails when it is joined exactly as a typed one does. A valid code fills the join form, upper-cased as the Join button sends it, and a valid `mode` is chosen. The mode is only a hint: a room plays the mode it was made with, and the server's refusal ([[R264]]) still decides and switches the lobby to the room's mode. A lobby that is still in a queue ([[R765]]) keeps that queue's mode and its notice, and the link fills in only the code. The lobby then says what to pick ("Pick a deck for Best of 1, then press Join.") and puts the cursor on that pick. It never joins by itself: the joiner still picks a deck or a trio ([[R264]]) and presses Join. Opening a link changes nothing the server knows.

A visitor who is signed out is sent to sign in first, and a sign-in lands on the main menu with no destination remembered (B35, issue #479); a pending account is sent to the invite page instead, and the link waits for it the same way. The link waits for them in this tab only (`sessionStorage`, [[R632]]), as the code and the mode and never a path, and the next lobby uses it once and forgets it: back to the menu and in again, the form starts empty.

This is presentation only. No endpoint changes, no rule changes, and the client enforces nothing: it fills in a form and the join route decides ([[§9.5]]). It is how Hearthstone's friend challenge works: an invitation never seats anyone, and the one it is sent to chooses what to bring.

Amended by [[R3730006]] (issue #3730): `/play` has no room ticket and no join form any more. The share is the private lobby's Copy link, `/lobby/CODE` ([[R3730000]]), which shares or copies as above. A `/play?room=` link still leaves the address bar at once and its code is still read as above, but it opens `/lobby/CODE` instead of filling a form, and `mode` is no longer read: a classic room still open under the code shows its join card in the room's own mode, with a pick for that mode and Join, so no hint is needed and no refusal ([[R264]]) has anything to switch, and a queue the player waits in no longer bears on it. It still never joins by itself. A signed-out visitor's link, a `/lobby/` path among them, waits through the sign-in as above, and a pending account's through the invite page, and it opens its lobby once, on the first screen the account reaches active.
