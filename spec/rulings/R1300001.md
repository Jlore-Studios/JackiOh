[[R481]]'s grant of a new catalog version's cards to every person's active account skips a dev
account ([[§14.10]]), so what it cleared ([[R1300000]]) stays cleared. The list of dev accounts
lives in the server's environment (`DEV_PROFILE_IDS`), and the grant is a trigger on the catalog
stamp, so `seed-catalog`, which writes the stamp, hands the list to its own transaction: it reads
`DEV_PROFILE_IDS` as the server's boot does (a malformed id refuses the seed), and before the stamp
sets `jackioh.dev_profile_ids`, the ids comma-separated, for that transaction only. Migration 0046's
`app.grant_launch_collection_all` passes over the profiles it names as it passes over a ladder bot
([[R1454]]), and grants everyone else as before. A stamp without the setting grants every person's
active account, a dev account included, as [[R481]] did. The activation grant ([[R111]]) is
unchanged: a dev account becoming active owns every card like anyone.

Rejected: a table of dev accounts the server syncs from its environment at boot, since the boot
writes nothing to the database and a stale row would outlive its removal from the list.

Superseded by the economy's going live (issue #1310, [[R1310001]]): migration 0050 drops the
stamp's grant, so a stamp grants nobody, a dev account or anyone else, and a dev account's clear
stays cleared with nothing to pass it over. `seed-catalog` no longer reads `DEV_PROFILE_IDS` nor
sets `jackioh.dev_profile_ids`. A dev account becoming active owns the starter cards like anyone
([[R1310000]]).
