[[R3792000]] made any private-lobby read that could not reach the server replace the screen at once. That discarded the mounted lobby's local deck pick, Start countdown and action refusal after a transient failure, and with a live social socket [[R3730000]]'s socketless poll made no later read to learn that the lobby changed or started.

**After a good read.** Any non-404 failure of a private-lobby re-read keeps the ready lobby mounted, without a new banner or notice. Its local pick, countdown and inline action refusal therefore stay. The failure schedules one more read after `LOBBY_POLL_MS` whether the social socket is live or down; another failed re-read moves that one-shot retry to the same delay from the newer failure. The regular interval remains socketless ([[R3214000]]), and a successful read replaces the shown lobby as before.

**Before a good read, and 404.** A non-404 failure before the screen has shown a lobby still shows [[R3792000]]'s failure card with Try again, and the socketless poll may recover it. A 404 on the first read or a re-read still closes the lobby ([[R3730004]]); it is an answered read, not a transient failure to hide.

Presentation only (CLAUDE.md rule 7): the client keeps rendering the last lobby the server answered and decides no lobby rule. Hearthstone semantics: a transient connection loss preserves the screen already in use while the client reconnects.

Rejected: replacing the shown lobby for every failed refresh, which loses its local interaction state; a banner for one transient failure, which adds noise while the scheduled read repairs it; polling continuously while the socket is live, which duplicates the push channel.
