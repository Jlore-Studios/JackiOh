A username is a base name and, when it needs one, a numeric tag: `Max`, `Max#1`, `Max#2`, and so on with no upper limit ([[R1434]]). The input is trimmed first, and input of more than `USERNAME_INPUT_MAX_CHARS` (64) characters is refused as too long without being read. After NFKC normalisation every character of the base is in the Basic Multilingual Plane (U+0000–U+FFFF) and is one of: a letter (general category `L*`), a decimal digit (`Nd`), `_`, or a combining mark (`M*`) that follows a letter, at most `USERNAME_MAX_MARKS` (3) in a row. Spaces, punctuation, symbols, emoji, anything outside the BMP, and invisible or direction-control characters (`Cf`: zero-width joiners, right-to-left overrides) are refused. So is every other character Unicode marks `Default_Ignorable_Code_Point`, whatever its category: the combining grapheme joiner and the variation selectors are marks and the Hangul fillers letters by category, yet each renders as nothing, so `Max` with one appended would stand beside `Max` as a second bare name, and a name of fillers would render blank. A name holds one script: digits (whichever script Unicode files them under), `_` and the marks that take their letter's script (`Inherited`) go with any script, and every other character shares one, judged by its `Script_Extensions` (so the kana length mark `ー` goes with either kana, the tatweel with Arabic, and an Arabic vowel sign with Arabic but not on a Latin letter), except the mixes a language needs: Han with Hiragana and Katakana (Japanese), and Han with Hangul (Korean). A letter Unicode files under no script, not even by extension (`Common`: modifier letters such as `ˈ` and `ː`), is a script of its own and joins no other; the cost is that Hawaiian's `ʻokina` does not join a Latin name, while the modifier apostrophe `ʼ`, which Unicode files under Latin and Cyrillic among others, does. So `Mаx` with a Cyrillic `а` is refused, while an all-Cyrillic `Мах` is allowed: a light filter does not chase look-alikes across whole scripts. The base is `USERNAME_MIN_LENGTH` (2) to `USERNAME_MAX_LENGTH` (16) user-perceived characters, counted as extended grapheme clusters, so a letter with its marks counts once; the tag never counts. The server stores the base in its NFKC form (fullwidth `ＭＡＸ` is saved as `MAX`), and the preview shows exactly that form ([[R1435]]). Each refusal is one plain sentence naming its kind: the characters, mixed scripts, too short or too long. The server judges the form and the client only proposes a name and renders the answer (CLAUDE.md rule 7, [[§9.1]]).
