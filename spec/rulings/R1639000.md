Two public facts the view already carries to both seats reach the screen. [[R43]]'s Heroic Power
says `usedThisTurn`, and [[R240]]'s fatigue count (`SideView.fatigueCount`) is the one both seats
read; until now the first only set a `data-used` attribute, so a used power looked like one its
owner could not afford (the viewer's) or like nothing (the opponent's), and the second showed only
while [[R318]]'s notice played, so an empty deck read 0 between draws.

**A used power.** A Heroic Power whose `usedThisTurn` is true wears a "Used" mark first in its
chip and is greyed and dimmed, and its `title` reads "{power}: used this turn" in place of the
button's "{power}: Activate, spend ({x})". On the viewer's button the accessible name then starts
with "Used". It holds on the viewer's buttons and the opponent's tags, the extra powers included.
The mark stands first in the chip, so the chip's clip never takes it, and it adds no chip: the hero
row is tight on a phone. Whether a button is live is still `legalActions`' and the mark only draws
the view (CLAUDE.md rule 7).

**Resting fatigue.** A seat whose `libraryCount` is 0 and whose `fatigueCount` is above 0 shows
"Fatigue {count}" on its Deck pile, in the pile's own row and under its own testid
`pile-fatigue-<side>`, and the pile's `title` reads "Deck, Fatigue {count}". The count is the one
taken so far: the client works out no next hit, since that would be a rule ([[R240]]'s count is all
it shows). While a pile notice is up ([[R318]]'s "Fatigue N" burst on the pile, or [[R373]]'s "Deck
full"), the resting badge stands down, so the pile holds one fatigue badge at most, and it returns
when the board shows the next view.

Hearthstone semantics: a used Hero Power turns over and reads as spent to both players, unlike one
its owner just cannot afford, and a player can see how deep into fatigue a deck is.

Rejected: putting "Used" last in the chip, where a long title such as "Terminus Tricks" clips it
away; a wider or separate chip, which the phone's hero row cannot take; floating the badge over the
field as [[R318]]'s notice does, which would cover the backrow all game; showing the next hit, which
would be a rule the client does not decide; and showing the badge under any notice, which would put
two at once on the pile.
