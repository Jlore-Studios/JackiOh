[[R1655000]] kept the picks a player makes for one card (its foil, finish and border and whether
its full art prints) on the device that made them, since only that device's own copy wore them. An
opponent now sees them ([[R1834002]], [[R1834004]]), so the server, which sends them, must hold
them: they move to the account. It amends [[R1655000]] (*Where the picks live*: per-card picks no
longer stay on the device that made them).

**The table.** Migration 0060's `public.card_cosmetic_picks` holds one row per account and card:
`profile_id`, `card_id`, `foil`, `finish`, `border`, `full_art` and `updated_at`, keyed on
`(profile_id, card_id)`, with at least one pick in a row; a card with none has no row. It is current
state with no ledger, since a pick is no holding ([[§14.11]]). An id is kept as it was written, one
the registry does not know among them, so the table has no foreign key to `public.cosmetics` or
`public.cards`, and ownership is judged where a pick is worn ([[R1834002]]). RLS lets an account
read its own rows, and no client role writes any: every write is the server's.

**The routes.** Three routes for an active account, each keyed on the verified token's profile and
never on a field of the request:

- `GET /api/card-picks` answers `{ cards }`: every card the account picked something for, by card
  id, each `{ cardId, foil?, finish?, border?, fullArt? }`, an id answered as it was written.
- `PUT /api/card-picks` changes one card's picks, `{ cardId, foil?, finish?, border?, fullArt? }`: a
  key left out keeps the card's pick, and `null` clears it, so the card wears the account's again.
  The card must be a non-token card of the catalog, and each pick passes [[R1834001]]'s check, or
  the request is 400 `bad_request` and writes nothing.
- `POST /api/card-picks/upload` is a device's one-time upload of the picks it held, `{ cards }` as
  `GET` answers them. A card the account already holds a row for is never touched, so a pick another
  device wrote stands. An id this build does not know is kept, as the device's store kept it
  ([[R1655000]]); one it knows under another kind, or that the account does not own on that card, is
  left out, since it could never be worn; a card not in the catalog is passed over.

Each answers the account's `{ cards }` after it.

**The client.** A device's own picks (`jackioh.cosmetics.cards.v1`) go up once: the first active
profile to sign in on a device whose store holds picks sends them up; any other time the device
reads the account's. Either answer replaces the device's copy, so the account's copy wins, but for a
write made on the device while the answer was on its way, which stands and is sent after it, and
lists the profile under `jackioh.cosmetics.cards.uploaded.v1`. From then on the store is an account's
cache and is never sent up again, by that profile or another: a pick cleared on one device never
comes back from another's cache, and one profile's copy never lands on a second profile that signs
in on the same device. Each write on the page is sent as the fields it changed (`PUT`, `null`
clearing one), one request at a time. A failed request raises nothing and changes nothing on the
device: a failed upload or read lists no profile, so the next sign-in tries again, and a failed send
leaves the pick worn on that device until a later read replaces it. Signed out, the store is the
device's alone, as [[R1655000]] had it, and practice and hotseat read it as before ([[R1310004]]).

**What stays.** The `cosmetics` settings group keeps exactly its six keys and its shape
([[R633]], [[R634]]), and no card's pick enters it, a settings request or the log. The fallback, the
rarity rules and the Collection as the one place a pick is made are [[R1655000]]'s.

Nothing here is a rule (CLAUDE.md rule 7): a pick never enters `PlayerView`, an action, the log, a
replay hash or a game record, and nothing the engine does reads one.

Hearthstone semantics: which owned version of a card a player plays is the account's, and follows
it to every device it signs in on.

Rejected: keeping the picks on the device and sending them with each queue or room request, which
would let a client claim any pick as a match begins and leave the server nothing to check it
against; a per-card settings group, which the settings limits hold to a handful of cards
([[R1655000]]); an upload that overwrites the account's rows, which would let an older device's
picks undo a newer one's; and sending the store up at each profile's first sign-in, which would send
an account's cached copy back up, bringing back a pick cleared on another device or giving one
profile's picks to another.
