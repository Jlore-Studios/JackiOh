[[R3728002]] put this tab's queue search in the shell's status row on every menu screen but `/play`, which drew
its own. With the Play hub's cards ([[R3729000]]) the panel that starts a search closes, so the search needs a
home that stays: this amends [[R3728002]] to show the banner on `/play` too.

**The banner.** "You're in the queue", the mode, the time the search has lasted as a clock that ticks every
second (`m:ss`, from the moment `net/liveGame.ts` kept when the search began, else from when the banner
mounted), the expected wait the server counted for that mode ([[R640002]], read again every
`QUEUE_POPULATION_POLL_SECONDS` while the banner shows), and Cancel, which asks the server to take the ticket out
(`DELETE /api/queue`) and forgets the queue, as Leave the queue does. A refusal keeps the search on screen with
Cancel pressable again. `/play` draws no search of its own inside the shell, so there is one display, and
Cancel pressed on the banner ends the wait `/play` was holding too: the screen says "Left the queue." Outside
the shell (a test, a board) `/play` draws its own beacon and Leave the queue as before.

**The reveal.** A match found ([[R765]]) is announced before the board opens, on `/play` and on any other screen
(`QueueFound`), with the opponent named, and the opponent's rank when the match is ranked
(`GET /api/matches/:id/ranks`): "You face NAME, RANK." The read never delays the move: while it is out, or when
it failed, or for a game with no match (a series, a co-op game), the line is the name alone, or absent.

Nothing here is a rule (CLAUDE.md rule 7): the mode and the moment are what this tab remembers, the wait and the
ranks what the server answered, and the server holds the ticket. The clock is the tab's, not the server's: a
reload keeps it (session storage), a second tab does not share it, as the queue itself is per tab ([[R765]]).

**Proof.** `MenuShell.test.tsx`: the banner on `/play` and elsewhere with its clock (advancing under fake
timers), its wait and a Cancel that sends `DELETE /api/queue`; `liveGame.test.tsx`: the start kept, read and
cleared; `GameBanner.test.tsx`: the reveal naming the opponent and rank and falling back; `play.test.tsx`: the wait
ending when the banner forgets the queue; spec 55 queues, follows the banner to Collection and cancels there.

Rejected: a second search display on `/play` beside the banner, which would say the same thing twice; and
holding the navigation until the ranks arrive, which would turn a courtesy into a delay.
