The server keeps one last board per profile and kind (`public.last_boards`, migration 0017; kinds `server` and `practice`, only `server` written) and replaces it in the same transaction as each finished server match's result, however the match ended: each seat's board is the engine's `lastBoardFor` of the final state from that seat's side, so a face-down card the seat did not control never reaches its row. A match the reaper ends ([[R112]]) has no state to read, so it writes no board and the last one stays. Each match row freezes both seats' boards as it starts (`matches.p1_last_board`, `p2_last_board`, `[]` for older rows), so a rebuilt actor folds the same game whatever the profiles' rows say later ([[§9.3]]). No client role reads or writes either: RLS on with no policy and no grant, as `matches`; the server is the only reader and writer, and a profile's boards are deleted with it
