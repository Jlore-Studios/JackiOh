Revising [[R643]] (MD-D29): while a card with `StaticFlags.hears_emotes` acts — the Radiant Meditative
#71 Pareto Optimality, which answers "whenever your opponent emotes" — an emote by that card's
opponent is also an engine action, `Emote`. It is legal for either seat, on its own turn or the
other's, while the other seat controls such a card, outside a prompt and the mulligan; a seat's own
hearing card never makes its emotes actions. It is logged and replayed, and its `Emoted` event names
no card, so both seats read it as it is. A seat's `PlayerView.emotesHeard` is `true` only then, and
only then does the client's emote layer send its emotes as actions. The server relays an emote first,
as before, then mints the `Emote` action for the sender's current seat; a rate-limited emote mints
nothing, and an emote no card hears is only relayed. The server never takes an `Emote` on the action
channel: it is the server's own action, so R643's rate gate cannot be bypassed. The random policy
never emotes, and the automatic turn end ignores the action.
