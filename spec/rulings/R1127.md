Revising [[R643]] (MD-D29): while a card with `StaticFlags.hears_emotes` acts — the Radiant Meditative
#71 Pareto Optimality — an emote is also an engine action, `Emote`, legal for either seat outside a
prompt and the mulligan, logged and replayed, and its `Emoted` event names no card, so both seats read
it as it is. `PlayerView.emotesHeard` is `true` only then, and only then does the client's emote layer
send emotes as actions. The server relays an emote first, as before, then mints the `Emote` action for
the sender's current seat; a rate-limited emote mints nothing, and an emote no card hears is only
relayed. The random policy never emotes, and the automatic turn end ignores the action.
