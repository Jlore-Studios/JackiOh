The sign-in screen offers an OAuth provider only when the build names it in the public `VITE_AUTH_OAUTH_PROVIDERS` (names only, from a fixed list: apple, azure, discord, facebook, github, gitlab, google, twitch), so nothing appears until a person has set the provider up in the Supabase dashboard. A provider is always reached with a PKCE challenge whose verifier this browser keeps, and returns to `/login` with a code that exchanges only here, as [[R664]]'s link does; a browser that cannot hash is not offered the implicit flow, whose tokens come back in a URL. A provider that sends the player back with an error says so in the client's own words. The account it signs into, new or matched by a verified address, starts `pending` and passes the invite gate like any other ([[§9.4]]): nothing about a provider makes an account active, and a new account's email counts as verified only if the provider says so
