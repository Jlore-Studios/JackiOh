`createGame` keeps each seat's last board as a list of `{ defId, radiant }` in board order and nothing else, and drops, as the match is created, every entry the match could not rebuild from its id alone: an id its catalog lacks, a digest fused id ([[R468]]), whose list only the process that minted it can read, and a fused id ([[R179]]) any ingredient of which, all the way down, the catalog lacks. A seat left with no entry has no board, and a match with none hashes as one created without the input. C+ #29 picks among the different cards of its caster's board — each definition once, where it first appears, on its Radiant face if any of its entries was Radiant, never C+ #29 itself ([[R387]]) — so two copies of one card are one option, and Discover offers them all when there are fewer than 3. A fused entry's definition is rebuilt from its id into the match the first time it is offered or made, as [[R179]] rebuilds its scripts: each ingredient as printed, priced as [[R65]] reads it out of play
