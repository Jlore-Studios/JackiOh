Presentation only (CLAUDE.md rule 7): no record, total, store row, endpoint or response changes, and nothing is collected that was not: [[R2089000]] already folds every Created card's figures, tokens among them.

The Cards tab of `/stats` has a Show tokens toggle, off by default, which the address carries as `tokens=1` while it is on. On, a Tokens section stands below the deck table and above the Created cards. It lists the rows of `GET /api/stats/cards`' `created` whose card is a catalog token (`CardDef.token`, [[§7]]), and no other Created card, under the same search box. Each row gives the token's games (the seats that made one, each once a game), its win rate (those seats' wins over their games, used or not: the Used and Not used wins, each its rate times its games rounded, as the Sets tab pools its cards' ([[R1966000]])), and Used, Not used and Used vs not used as the Created table shows them. A rate under `CARD_STATS_MIN_SAMPLE` games shows "—" ([[R654]]). The rows run from the highest win rate down, those under the floor last in the server's order, and with no token to show the section says so. Off, the page is what it was; on, the deck and Created tables are unchanged, so a token shows in both sections, and the section names no source ([[R661]]).

Rejected: tokens as rows of the deck table, which [[R2089000]] rejected for every Created card; taking the tokens out of the Created table while the toggle is on, which changes a table the toggle is not for; a new tally (the tokens a seat made in a game) or a win rate of the server's, which would change the collection rather than read it; and keeping the toggle on the device, when the address keeps every other choice of the page.
