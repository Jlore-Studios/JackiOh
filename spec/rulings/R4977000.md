The server counts a seat's plays in the transaction that records the result of every ladder, unranked and Conquest game ([[R3013000]]), but the page loaded its copy of the account's proficiency ([[R3013001]]) once, when the shared sync started, and again only after a refused pick. The sync outlives the move from the match to the Collection, so a level a game reached still read as before, and its stamp could not be picked (`writeOwnStamp` refuses a stamp above the level the page holds), until a reload.

A paid result on the match screen (`match.economy` set, once however many views carry it) calls `reloadOwnProficiency()`, beside `announceWallet()`. It queues a `GET /api/proficiency` on the shared sync, after any stamp pick already in flight, and the answer replaces the page's copy. With no sync running (no active account on a gated screen) it sends nothing.

One more read per counted game, the read the page already makes on its first gated screen. Practice, the co-op board and the news panel's claims announce the wallet without counting a play and load nothing.

The client decides no level and no unlock (CLAUDE.md rule 7): it shows what the account answers.

Hearthstone semantics: a reward earned in a game is usable when the game ends ([[R4780000]]).

Rejected: calling it from `announceWallet()`'s no-balance branch, as [[R4780000]] did, since practice, co-op and the news claims announce there and count no plays; a read on every route change; the result carrying the new levels (a wire change to save one read).
