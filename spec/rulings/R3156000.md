The owner asked on 2026-11-05 for the dev panel to be "a different button it appears when you have a dev account on the front screen", "scoped for a computer". The front screen's top bar (`routes/landing.tsx`'s corner) shows a Dev button, before Account, when `GET /api/auth/me` says `isDev` and the window is a computer's: `DEV_PANEL_QUERY`, at least `DEV_PANEL_MIN_WIDTH_PX` wide (the game's own desktop line, `HERO_DESKTOP_QUERY`) with a fine main pointer (a mouse or a trackpad). A phone, a tablet held either way, a narrower window, an account the server does not call a dev account, or no account at all shows no button. The query is followed live, so a window narrowed below the line drops the button and its dialog.

The button opens the Dev tools ([[R1300000]], `routes/DevTools.tsx`, the very panel `/account` mounted) in a modal dialog over the front screen, laid out for a wide screen: each row of tools side by side. Escape, Back ([[R2127000]]), the close button and a press on the scrim close it, and the focus goes back to the button. `/account` no longer carries the Dev tools toggle, for any account.

The server still decides (CLAUDE.md rule 7): the button is a door, `isDev` only shows it, and every tool's route checks `DEV_PROFILE_IDS` itself. Nothing on the server changes, and no tool needs the two-step code: only the dashboard's `/api/admin/*` routes do on a strict server ([[R3074000]]).

Rejected: keeping the toggle on `/account` beside the button, since the owner asked for the panel to move; and showing the button at every width, against "scoped for a computer".
