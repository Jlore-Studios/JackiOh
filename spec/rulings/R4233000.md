A row of the feed [[R4039000]] keeps counts as seen as soon as its owner opens or answers what it is about, not only when the inbox marks it read: reading a daily game's board (or sending an action there) marks that game's `dailyMove` and `dailyEnded` rows read, accepting or declining a daily challenge marks that challenge's `dailyChallenge` row, accepting or declining a friend request (taking it by asking back among them) marks that sender's `friendRequest` row, entering a lobby marks that lobby's `lobbyInvite` row, and a friend's read of a replay shared with them marks that match's `replayShared` row. The mark runs after the act's own commit and never fails it: a failure is logged and the act's answer stands. A mark that changed any row pushes the owner's social frame ([[R3214000]]), so every one of their tabs drops the dot. The rows stay in Recent as history ([[R4039001]]); they only stop counting as new.

The game-ending row told to the player whose own move or concession ended the game is written already read: it is listed, but no toast goes out for it and it never counts as unread. The other player's row stays unread until they open the board. A loss on time ([[R3727000]]) is the server's act, not the loser's, so both rows are written unread. A board read marks inside its own read transaction and only rows still unread, so the slow re-read ([[R3840000]]) writes nothing twice and pushes nothing.

A `lobbyInvite` whose lobby is gone, started or expired counts as unread nowhere, even before any page is read: the same test the page reads by. The unread count stays one statement and the social read keeps its fixed number of reads ([[R3210000]]).

Rejected: having each client screen mark rows read as it opens. Every screen would have to remember to do it, and an older open tab would not follow; the server already handles each of these acts.

Amends [[R4039000]], whose only write marking a row read was the inbox's own read.
