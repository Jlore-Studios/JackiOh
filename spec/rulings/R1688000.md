A practice claim that passes its check ([[R1303000]]) is paid in one transaction, after the one
that burned its seed ([[R1303001]]): the game's Jlore, held to the day's cap ([[R1483000]]), its
XP, the quests it moves ([[R1304001]]) and the board it leaves ([[R1303003]]) land together or not
at all. The spec did not say what a pay the store fails does. It is tried again, as a finished
match's result is ([[R1437]]): `PRACTICE_PAY_ATTEMPTS` (3) tries in all, waiting
`PRACTICE_PAY_BACKOFF_MS` (250 ms) before the second and twice as long before each one after. A
try that fails rolls back whole, so the try that lands pays once. The tries run in the claim's own
task, so they go on when the caller stops waiting. The check runs once, and a refusal is an
answer, not a failure: it is never tried again. When every try fails the claim answers an error
and pays nothing, and its seed stays burned, so a later claim of it answers `already_claimed`; the
retention loop's sweep pays it later, once ([[R2422000]]).

Hearthstone semantics: a game's reward is granted once, and a server that fails to grant it tries
again rather than letting the game go unrewarded.

Rejected: giving the seed back when the pay fails, which would let two claims race for one seed
and break R1303001's one pay; running the check again on each try, which re-runs every AI move
for an answer that cannot change; and a sweeper that later pays seeds claimed but never paid, which
needs a mark of a seed paid (a migration) and was left to a follow-up, [[R2422000]].
