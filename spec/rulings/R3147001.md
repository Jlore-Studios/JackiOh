§9.4 step 1 still asks for a verified address before an invite code is redeemed, whatever way the account signed in. A pending account with no address (a Roblox sign-up, [[R3147000]]) meets, where a confirmation would be asked for, a sentence saying it has none yet and a field to add one. The address is sent as [[R663]]'s email change (`PUT /auth/v1/user` with the new `email`, the session's token and `redirect_to` `<origin>/login`, under its own PKCE verifier), with R663's refusals; the form then says it emailed a link to that address and to press Check again, which reads the account as the confirmation's Check again does. No resend is offered, since there is no address to resend to. The link comes back to `/login` as R663's does, and the browser that holds the account's session is told it is signed in and may go to that account. Once the server reads the address as confirmed, the screen is the code screen of any pending account.
