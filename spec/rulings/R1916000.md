[[R711000]] kept the button beside the gear on every screen for good: in the top bar, the landing's corner and the board.

Now the device counts its boots in `localStorage["jackioh.locale.settledVisits"]`, read and written inside try/catch beside the language itself: one more at every boot, and back to 0 at every language change — from the button, from settings' Language row — and at settings' reset. From the boot that writes `LANGUAGE_SETTLED_VISITS` (3) or more the device counts as settled: the button then shows in no top bar, landing corner or board, and settings' Language row, there at every count, is the only control, and a change there brings the button back at once. Storage that cannot be read or written never settles, so the button is never lost. The row's hint mentions the top button only while it shows.

It is still presentation only ([[R711000]], CLAUDE.md rule 7): the count never leaves the device, and the client sees no IP or fingerprint.

Hearthstone semantics: Hearthstone keeps its language among its settings, with no control on its screens of play.

Rejected: an IP or server-side fingerprint (the client never sees one, and [[R711000]] keeps the language off the server); counting without comparing first, which would hide the button only from the fourth boot; re-reading storage at every render, which would let another tab's boots take the button away mid-visit; keeping the count at settings' reset, since the reset goes back to a first visit and a first visit shows the button; and gating at the button's three call sites, which a future top bar could miss.
