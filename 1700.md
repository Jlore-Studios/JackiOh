## Goal

The animated rarity sheen (the sweep on every Mythic face and every Radiant face, `data-foil="animated"`) stops drawing a dark triangle at a face's corner each time the band enters or leaves it, and keeps its cost on a full hand and field: one layer per face, moved by `transform` alone, with no extra work per frame. **What the planner found (headless Chrome 141, ANGLE/SwiftShader GL, a copy of the sweep's CSS in `/tmp`, not in the repo):**
- The triangle shows only when a face is **rotated**, as every card in the home screen's fan is (`apps/web/src/routes/landing.css`, `.landing-fan-slot`, `rotate(±11deg, ±22deg)`). It shows as a dark wedge past the rounded corner (top-left as the band comes in, bottom-right as it leaves, which is where the loop restarts) and a dark strip along the face's leading edge.
- It comes from `mix-blend-mode: overlay` on the moving layer. The same page with `mix-blend-mode: normal` draws nothing outside the clip and no dark strip. `screen` has the same wedges as `overlay`. Moving the sweep into `.cf-scale` behind a `clip-path` cut the band with hard straight lines.
- Cost: 40 animated faces at 1920×1080, frames drawn in 5 s (two runs each): no sweep 299/301; current overlay sweep 136/144; the same sweep with normal blending 172/180. Dropping the blend adds about 25% more frames, so the "< 5% degradation" acceptance holds with room to spare. (SwiftShader runs on the CPU, so these figures show the direction of the change, not a GPU's frame times.)

  it("composites the sweep with no blend mode, so a rotated face keeps its rounded corners (#1700)", () => {
    const animated = ruleBody(
      /:root:not\(\[data-reduce-motion="true"\]\) \.cf\[data-foil="animated"\]::after/,
    );
    expect(animated).toMatch(/mix-blend-mode:\s*normal;/);
    const gated = ruleBody(/@media \(prefers-reduced-motion: no-preference\)/);
    const blends = [...gated.matchAll(/mix-blend-mode:\s*([a-z-]+)/g)].map((match) => match[1]);
    expect(blends, "the motion gate blends nothing").toEqual(["normal"]);
  });

  it("keeps the still foil's overlay, which never moves (#1700)", () => {
    const still = ruleBody(/\.cf\[data-foil="static"\]::after,\s*\.cf\[data-foil="animated"\]::after/);
    expect(still).toMatch(/mix-blend-mode:\s*overlay/);
  });

  it("lights the swept band at SWEPT_ALPHA_SHARE of the still band's alpha, stop for stop (#1700)", () => {
    const still = gradients()
      .filter((gradient) => /\(\s*115deg,/.test(gradient))
      .map(alphas);
    const swept = gradients()
      .filter((gradient) => /\(\s*90deg,/.test(gradient))
      .map(alphas);
    expect(swept, "a swept band per still band").toHaveLength(still.length);
    for (const [band, stops] of still.entries()) {
      const sweptStops = swept[band] ?? [];
      expect(sweptStops, `band ${String(band)}'s stops`).toHaveLength(stops.length);
      for (const [at, alpha] of stops.entries()) {
        expect(sweptStops[at], `band ${String(band)} stop ${String(at)}`).toBeCloseTo(alpha * SWEPT_ALPHA_SHARE, 5);
      }
    }
  });

## Risks

- **Brightness drift.** Normal blending lifts a light backdrop less than overlay did, and a dark one about the same, so the band reads a touch softer on the gilded edge. Use the values given. Do not retune them by eye, and do not raise them past the still band's alpha (the third test holds the ratio).
- **Reduced motion.** Under `prefers-reduced-motion: reduce` or Reduce motion, an animated face wears the still rule, which keeps `overlay`. Do not move `mix-blend-mode: normal` out of the motion gate: the existing test "runs only with motion allowed…" requires the gate to hold every sweep rule.
- **Performance.** Do not add a second layer, a `clip-path`, a mask or a `filter` to fix anything else: each forces another render pass per face, which is the cost the acceptance guards. Leave `isolation: isolate` and `overflow: clip` on `.cf` as they are.
