# v0.4.0 Part 6: the whole card API in Luau

Notes for issue #448 (v0.4.0 part 6 of 29): every effect verb, every reader, every
hook type a ported card uses, and the typed module — what was decided.

## 1. What changed

- `crates/luau/src/api/` (one file per `effects/` module): one Luau function per
  effect verb, same name, argument fields as serde names them. All 176 verbs bind,
  including the two `luau surface` leaves unclassified (`replace_hand_with_perfect`,
  `roll_back`).
- `crates/luau/src/reads.rs`: the readers, on the scoped `ctx` userdata, plus
  `J.query` / `J.pool` / `J.cost` / `J.div` / `J.rem` / `J.sort_by` /
  `J.TRAP_TYPES`.
- `crates/luau/src/hooks.rs` + `script.rs`: an adapter per hook type (42 of 45;
  L14's `quests`, `records_play_as` and `start_of_game` stay in Rust and are
  refused at load) and declarations as data.
- `crates/cards/luau/jackioh.luau` + `crates/cards/src/scripts/.luaurc`: the
  typed module, generated by `crates/luau/tests/export_api.rs` (ts-rs through the
  engine's off-by-default `ts` feature, translated to Luau) and committed; the
  `@jackioh` alias for editors. `crates/cards/build.rs` skips dotfiles so the
  scan tolerates it.
- `crates/luau/tests/api.rs` + 18 fixtures: one test per hook family and
  Luau-vs-Rust parity per verb group (equal `hash_state` and events).
- `docs/v0.4.0/api-gaps.md`: surface minus bound, per name with cards and waits.
- Engine `#[cfg_attr(feature = "ts", derive(ts_rs::TS))]` on every argument and
  return type the API names; no behaviour change.

## 2. Decisions

- **Closure verbs resolve by name, and there is no registry.** The first
  `after_state_check` binding kept script callbacks in a thread-local
  `RefCell<HashMap>` behind an `AtomicU32` counter — alive across calls (against
  L8) and impure (against rule 4). The script now passes a hook name plus data
  (`J.after_state_check({ hook = "after_check", data = { ... } })`), and the
  closure captures only card, face, name, data and site, re-running the chunk to
  call `module[face][hook]` when the engine reaches it. `draw_while` and
  `for_each_card` use the same pattern (`draw_more`, `each_cards`/`each_card`),
  since they shared the registry; `J` is pure data again, with no per-verb
  special case. Rejected: a Lua-registry-backed id map (same L8 problem through
  another door) and silencing the lint.
- **Face functions need statically known names.** Same-face multiples are real
  (Classic #39 holds two `for_each_card`s in one cry), so names stay dynamic in
  the effect args — but part 4's loader contract (an unknown face key is a load
  error, proved by the `cri` test) must hold. `vm::SUB_HOOKS` allowlists the
  four roles, with a `_<n>` suffix for a second use (`each_cards_2`); anything
  else is still a load error, and a name that resolves to nothing fails the
  card's own test (verbs verify at build) naming card, face and function.
- **The host needs the bytecode to build effects.** Named sub-hooks resolve from
  the card's chunk, so `effect_of` and the nested builders (`during`, random
  entries, `each`) thread the `&'static` bytecode the hook adapters already
  capture. Rejected: a card-to-bytecode map (a growing static against rule 4)
  and a thread-local "current card" (an implicit parameter by another name).
- **`with_kill_credit` stays half-bound.** Its `pairs`/`then` close over live
  kills; the old `pairsCallbackId`/`thenCallbackId` fields were dead (nothing
  could ever set them) and are removed, the verb watches nothing, and
  Classic+ #19.2 stays in Rust (`api-gaps.md`).
- **`start_of_game` fails to load.** It sat in `HOOKS` with no adapter: a face
  declaring it loaded and never fired. It is L14's, so it is refused like the
  other unknown keys.
- **Fixtures annotate their contexts.** Unannotated hook parameters degrade what
  readers answer (`#` and field access fail); `ctx: J.EffectContext` (and the
  other flavours where the runtime registers them) plus hoisted annotated
  locals for union-typed verb args (`HealArgs`) are the convention, proved by
  strict-clean fixtures. The `ConditionContext`/`HookArgs`/`ReplacementContext`
  stubs declared fields where the runtime has methods; they now mirror
  `reads.rs`, and the stub-sync test covers all four flavours.
- **`card_def` stays a gap.** Fourteen cards read the catalog def by id;
  `J.cost`, `J.query` and `ctx:def_by_index` cover the known uses, but no bare
  form exists and each batch judges per card. No new bindings were added for
  gaps: the doc names the wait instead.
- **Strict runs use staged copies.** This `luau-analyze` resolves no `@` alias
  even with the `.luaurc` present, so local runs copy the module, fixtures and
  pilots to one directory with a relative require; the alias key follows Luau's
  format (no `@`) for editors.

## 3. Provenance

Built on `bot/issue-442` (#560's `luau surface` read all 447 catalog cards, 14
marked to stay Rust, 0 unreadable, 0 unclassified). `surface.json` output is
printed and never committed. `cargo test -p jackioh-luau --features ts`
(21 api + 1 generator + 27 host), `cargo clippy -p jackioh-luau --all-targets
-- -D warnings`, `cargo fmt --check`, and `luau-analyze --mode=strict` (Luau
0.740) clean over the module, the pilots and every card-shaped fixture; the
host-harness negative fixtures (`write_global`, `require_other`, …) are out of
scope for strict by construction.
