## Plan

_Written by Claude (Opus 5.5) for #306's planning session. Edit it here to change it._

### 1. Goal

Shorten CI (#306): per pull request only the essential checks, each job under five minutes; everything slow in one daily "super" run that opens or updates an issue when it fails and closes it when it passes (README §7). Electron runs are dropped. Built on `staging`; it reaches `main` with the cutover (part 38).

**Who builds it: a person**, or a Claude Code session a person runs and watches, because it changes `.github/`, `.harness/`, `.squishy/` or `bot/`, which no bot may change (CLAUDE.md, The night bot). It is not a fullsend part: build and test normally.

### 3. Steps

1. Do this on `staging` (its CI runs the new jobs; red until Wave 3, expected).
2. Write `ci.yml` per README §7: `rust` (fmt, clippy -D warnings, cargo test --workspace, catalog check, patches check, spec check, fuzz --seeds 200), `web` (build-wasm, typecheck, eslint apps/web e2e, vitest web without `src/audio/**`, `src/fx/**` and the asset tests, the ts-rs/config export diff), `e2e smoke` (Chrome: 01, 06, 10, 13, 19 against the Rust server), `db` (sql, db, deploy when server/migrations/Dockerfile/render.yaml changed; a skip passes), `bot selftest` unchanged. Keep `concurrency` and the `changes` job.
3. Write `super.yml` per README §7; the issue text names each failed job with its log link; dedupe on the exact title.
4. Change the actions, `ci-duration.yml`, `patches-ship.yml`, the two scope scripts and their tests.
5. Measure: every per-PR job under 5 minutes on a green Wave 3 head (shard `rust`'s test step by crate if not).

### 4. Tests

- `ci-scope.test.ts` and `vercel-ignore.test.ts` updated and green.
- A dispatched `super.yml` run on staging opens the issue while red and closes it once green (V25).

### 5. Done when

- [ ] Per-PR required checks are `rust`, `web`, `e2e smoke`, `db`, `bot selftest`; the names are recorded on #306 for part 38 (branch protection, `.harness/config.json`, `.squishy/config.json`).
- [ ] The slowest per-PR job is under 5 minutes on a green head (V24).

### 6. Risks

- The bots wait on `required_checks` by name; they must change in the same hour as branch protection (part 38's checklist).
