# Patch v0.2.0 rulings: the Classic+ #1–#39 workstream (R560–R579)

Rows in SPEC §11's format, for the docs workstream to port into §11. Each is proved by a test named
after it and indexed in `packages/engine/test/rulings.test.ts`.

| R572 | C+ #12.8 Frostspatula: a kill in its own last combat | "Every Unit this destroyed" counts a Unit whose death it caused in the same state-check pass as its own death (a mutual kill): its Death adds the Units this action's `destroyed` events name it the killer of (R42) to the ones it remembered, each once, so a 10/3 that trades with a 3/3 Rush Token still summons a fresh Rush Token for its controller | C+ #12.8; R42, R89, R409 |
| R578 | C+ #37 Wardrum: which play is the 3rd | Its controller's Spell, Field Spell and Trap plays of the turn (casts included, R70) are counted in the order they were played, a cast made inside a play's resolution coming after that play; Wardrum answers the resolution of the play whose place in that order is its threshold (3) and no other, so a 4th cast that resolves inside the 3rd's resolution does not set it off and the 3rd's own resolution does | C+ #37; R70, R464 |
| R564 | C+ #29 Portal to the Past: a last board as the match keeps it | `createGame` keeps each seat's last board as a list of `{ defId, radiant }` in board order and nothing else, and drops, as the match is created, every entry the match could not rebuild from its id alone: an id its catalog lacks, a digest fused id (R468), whose list only the process that minted it can read, and a fused id (R179) any ingredient of which, all the way down, the catalog lacks. A seat left with no entry has no board, and a match with none hashes as one created without the input. C+ #29 picks among the different cards of its caster's board — each definition once, where it first appears, on its Radiant face if any of its entries was Radiant, never C+ #29 itself (R387) — so two copies of one card are one option, and Discover offers them all when there are fewer than 3. A fused entry's definition is rebuilt from its id into the match the first time it is offered or made, as R179 rebuilds its scripts: each ingredient as printed, priced as R65 reads it out of play | C+ #29; §9.3, §10.1, R65, R179, R387, R417, R468 |
| R565 | C+ #29 Portal to the Past: last boards on the server | The server keeps one last board per profile and kind (`public.last_boards`, migration 0016; kinds `server` and `practice`, only `server` written) and replaces it in the same transaction as each finished server match's result, however the match ended: each seat's board is the engine's `lastBoardFor` of the final state from that seat's side, so a face-down card the seat did not control never reaches its row. A match the reaper ends (R112) has no state to read, so it writes no board and the last one stays. Each match row freezes both seats' boards as it starts (`matches.p1_last_board`, `p2_last_board`, `[]` for older rows), so a rebuilt actor folds the same game whatever the profiles' rows say later (§9.3). No client role reads or writes either: RLS on with no policy and no grant, as `matches`; the server is the only reader and writer, and a profile's boards are deleted with it | C+ #29; §9.3, §9.5, R112, R417 |
| R561 | C+ #31 Fusion Lab's Radiant ingredient (extends R77) | C+ #31's Radiant face fuses its random card in on that card's Radiant face, and that Radiant form is lent to both of the fusion's forms: the fused definition's base form and its Radiant form each join the ingredient's Radiant face to the kept hand card's matching face, so the rider shows whether or not the hand card is Radiant (a base hand card reads the ingredient's Radiant text), and the fused id marks that ingredient Radiant (R179). The kept card keeps its own radiant flag, its zone, its type and its cost (a costOverride of the cost it had, R65) | C+ #31; R77, R102, R179 |
