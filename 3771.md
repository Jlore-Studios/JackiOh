## Risks

- **Check rejecting.** If `retireOlderImage` ever rejected, `imageCheck` would never clear and every request would throw, which is the bug being fixed. Keep every `await` inside it within a `try`. The outer `.then` does not clear on rejection.
- **Concurrent requests.** Concurrent requests share the in-flight `imageCheck`, and a request inside the retry window skips the check without waiting.
- **Timeout in tests.** A native `AbortSignal.timeout` timer is not faked by vitest, so test 4 stubs `AbortSignal.timeout`. Restore it afterwards so other tests are not affected.
- **Rate limit on `/healthz`.** The check is rate-limited by `IMAGE_CHECK_RETRY_MS`, so a down old server is not asked on every request.
- **Conflict with #3618.** Keep edits to `index.ts` to the regions named above.

## Open questions

- The values `IMAGE_CHECK_RETRY_MS = 10_000` and `IMAGE_CHECK_TIMEOUT_MS = 5_000` are my picks, because the issue names the constants but not their values. 5 s is well under `START_WAIT_MS`, and 10 s keeps a retry from being hit on every request. A person can change them in review.
- Design decision: a failed `stop` or `destroy` also counts as "not checked", so it is retried later, rather than being treated as done. I rejected treating it as done because the old image would then keep serving, which is the problem the issue describes.
