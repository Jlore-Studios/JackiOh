# Plan (sonnet, medium)

**Goal.** Holding a fused card (one fusion or a fusion of fusions) opens the full-screen art view with the right picture, or doesn't open, and never shows a black screen. The cause is that `artPlaneUri` (`apps/web/src/cards/art/pictures.ts:113`) returns `""` for any id missing from the static `CATALOG`. A fusion id (`t-N:(a+b)`, R179) is never in it, so every plane becomes `url("")` and the portal draws a black screen. The hold still opens because a fusion's rarity is its rarest ingredient's (`fuse.rs` `rarest_of`), so a fusion holding a Mythic or full-art ingredient passes `canOpenFullScreen`. I did not confirm that a single fusion fails the same way, but the code path says it does. Desktop click-and-hold uses the same trigger (`game/Card.tsx` `onLongPress` → `openFullScreenArt`), so it fails the same way. The fix has two parts:
- Resolve a fusion id to the catalog card whose art it draws.
- Refuse the hold when no such card can be found.

No layout changes, so no phone-width e2e is needed. A web unit test covers the fusion of fusions.
