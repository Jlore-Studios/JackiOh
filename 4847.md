# Plan issue #4847: Reload Dungeon Run on Page Reopen

## Goal

Ensure the Dungeon client store (`apps/web/src/dungeon/store.ts`) reloads its state from `localStorage` whenever a Dungeon page is reopened and the first subscriber joins in `subscribe()`, while preserving an unsaved finished run if this tab is still displaying one. This prevents stale in-memory cached run state, progress (Embers, unlocks), and history records from overwriting updates committed by another tab (such as completing a run or purchasing deck levels) while the Dungeon page was unmounted. Proving unit tests in `apps/web/src/dungeon/store.test.ts` verify that cross-tab changes made while unmounted are preserved when the page is reopened and subsequently acted on or abandoned, and that completed runs displayed in this tab are preserved across page reopen until explicitly dismissed.

## Risks

- **Run Timer restart or double-counting (R3502000):** If `subscribe()` reloads core state while listeners exist, `sessionStart()` initializes `resumedAt` using the current timestamp. Because `setSession` is idempotent (`if (running === (live.resumedAt !== null)) return;`), subsequent `setSession(onScreen())` calls do not restart or double-bank elapsed session time.
- **Finished run disappearance (R4742000):** If a finished run was settled in this tab, its storage key was deleted from `localStorage`. If `reloadCore()` unconditionally discarded in-memory state in favor of `loadCore().live` (which is `null`), the run-over screen would prematurely vanish when reopening the page. The conditional `next.live === null && kept !== null && runFinished(kept.run)` guarantees the finished run remains visible until dismissed.
