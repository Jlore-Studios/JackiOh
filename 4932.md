# Plan (sonnet, medium)

## Goal

When the Duos AI decides whether to pass a card, its two scores read the teammate's best-valued cards, not the first cards in hand order. The scores are `pass_score` and `mate_baseline`. This holds at any hand size, because the hand cap is a setting (R1143, 0 to `HAND_CAP_MAX`) and nothing may assume 10. The engine-step bound stays at `DUOS_PASS_MAX_FOLLOWUPS` (8) per scoring site. A hand that fits the bound scores exactly as before.

What the code does today:
- `mate_baseline` takes the first 8 distinct hand cards. A winning ninth card never enters the baseline, so a card the teammate cannot use better is passed. This is the bug that changes decisions.
- `pass_score` cuts by plays, not cards. A Unit lists one play per open lane, so 8 plays reach one or two cards. Its cut cannot flip a decision on its own, because the passed card's own plays come first. It gets the same rule because the issue asks for it and R1127000 would otherwise keep an arbitrary cut.

Decisions the issue did not settle:
- **Bound stays 8, not the hand size.** The maintainer's "should read an arbitrary value" is read as: tests and code must not hard-code 10, and ordering works at any hand length. The rejected alternative is lifting the bound to the hand size (up to 14 steps per site). That adds unmeasured cost and contradicts "no new nodes".
- **`own_use_gain` and `pass_gain`'s `card_plays` are untouched.** They hold variants of one card, which tie on hand value, so ordering them changes nothing. The judge flagged the same tie.
- **Ranking applies only on overflow.** A hand within the bound keeps its order, so existing behaviour and tie-breaks do not move.
- **Pairing method for the paired screen (decided now):** two builds of the same duos gate on the same frozen deals. Size is `--games 40`. Keep bar is below.
- **A ruling is needed.** R1127000 and R1723000 state the cut order, so a new note amends them.

2. **`crates/ai/src/duos.rs`: add a helper** next to `best_step`:
   ```rust
   /// R4932000: the plays that get scored, at most `limit`. A list that fits is kept as it came, in
   /// `legal_actions` order, so a hand within the bound scores as it always has. A longer one is cut to
   /// the first play of each card it names, the `limit` cards worth most first (`hand_card_value` on
   /// `state`, the teammate's probe), ties in the order they came; a play of a card outside the hand
   /// (a graveyard play, R454) ranks last. The bound is unchanged: no engine step is added.
   fn best_valued_plays(state: &GameState, mate: PlayerId, plays: Vec<ActionBody>, limit: usize) -> Vec<ActionBody> {
       if plays.len() <= limit {
           return plays;
       }
       let worth = |action: &ActionBody| match action {
           ActionBody::Play { instance_id, .. } => state.players[mate]
               .hand
               .iter()
               .find(|card| card.id == *instance_id)
               .map_or(f64::NEG_INFINITY, |card| hand_card_value(state, card, &AI_EVAL)),
           _ => f64::NEG_INFINITY,
       };
       let mut seen: IndexSet<String> = IndexSet::new();
       let mut ranked: Vec<(f64, ActionBody)> = plays
           .into_iter()
           .filter(|action| matches!(action, ActionBody::Play { instance_id, .. } if seen.insert(instance_id.clone())))
           .map(|action| (worth(&action), action))
           .collect();
       ranked.sort_by(|a, b| b.0.partial_cmp(&a.0).unwrap_or(Ordering::Equal)); // stable
       ranked.into_iter().take(limit).map(|(_, action)| action).collect()
   }
   ```
   `Ordering`, `IndexSet`, `hand_card_value` and `AI_EVAL` are already imported in this file.
