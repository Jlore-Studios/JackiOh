## Risks

- **Resurrecting a settled run.** A pause that rewrote `DUNGEON_RUN_KEY` for a finished run would pay it again on reload. `setSession` returns early for finished runs, and a test covers it.
- **Stale snapshot.** The first render loads with no subscriber, so the clock starts only in `subscribe`; the store commits there. A timer frame at most can lag.
- **Unclean exit.** A crash with no `pagehide` loses the time since the last save. That undercounts and never overcounts; accepted.
- **Two tabs on one run.** Each tab banks its own session and the later write wins. It is rare and undercounts; not handled.
- **Storage.** No `DUNGEON_STORAGE_VERSION` bump, because a bump would drop every kept run. `elapsedMs` is optional on read.
- **Test reloads.** `reload()` calls `cleanup()`, which pauses and banks time up to the current clock. Tests that move the clock to model a closed page must dispatch `pagehide` first.
- **Purity.** No crate changes; the generated `wire/` has no diff.

**Decisions the issue left open**
- *Start screen:* counts while the Dungeon page is open, including the start screen's Continue wait. Rejected: pausing it until Continue, which would wire `DungeonPage`'s `entered` state into the store.
- *Leaving the page:* time stops when the Dungeon page unmounts, so the "Back to Play" link, the primary leave path, stops the clock. Rejected: only hide and `pagehide`, which would time a tab left open on another route.
- *`startedAt`:* kept in storage, removed from `Dungeon`. Rejected: reusing it as a "virtual start".
- *`pageshow`:* also resumes the clock, for a back-forward-cache restore.

## Risks

- **Resurrecting a settled run.** A pause that rewrote `DUNGEON_RUN_KEY` for a finished run would pay it again on reload. `setSession` returns early for finished runs, and a test covers it.
- **Stale snapshot.** The first render loads with no subscriber, so the clock starts only in `subscribe`; the store commits there. A timer frame at most can lag.
- **Unclean exit.** A crash with no `pagehide` loses the time since the last save. That undercounts and never overcounts; accepted.
- **Two tabs on one run.** Each tab banks its own session and the later write wins. It is rare and undercounts; not handled.
- **Storage.** No `DUNGEON_STORAGE_VERSION` bump, because a bump would drop every kept run. `elapsedMs` is optional on read.
- **Test reloads.** `reload()` calls `cleanup()`, which pauses and banks time up to the current clock. Tests that move the clock to model a closed page must dispatch `pagehide` first.
- **Purity.** No crate changes; the generated `wire/` has no diff.

**Decisions the issue left open**
- *Start screen:* counts while the Dungeon page is open, including the start screen's Continue wait. Rejected: pausing it until Continue, which would wire `DungeonPage`'s `entered` state into the store.

- *`startedAt`:* kept in storage, removed from `Dungeon`. Rejected: reusing it as a "virtual start".
- *`pageshow`:* also resumes the clock, for a back-forward-cache restore.
