## 6. Risks

- **Animation timing divergence between FxLayer and Result**: `FxLayer` plays the lethal lead and Victory/Defeat cues only on the condition `previousResult === null && view.result !== null`. If `GameResult` used a different condition or waited on initial mount, the panel would either appear over a running animation or stay invisible with nothing playing. By coupling `arrived` strictly to whether the board mounted on an in-progress game (`shown.result === null`), `GameResult` waits if and only if `FxLayer` triggers its cues.
- **Layout shift**: Hiding the End turn button upon game over was rejected because it would shift the rail layout right when the result arrives. Keeping the button visible in its `"over"` state with the same physical dimensions and sunken styling prevents layout jumping.

     title: "A finished game's board stops reading Enemy turn, and a board opened on a finished game shows its result at once (issue #4734)"

     **Why.** Once a game was over, two presentation issues degraded the board's clarity (issue #4734):
     1. The End turn button read "Enemy turn" after every game, even a game the player won on their own turn. The turn plate beside it read "Game over", but on portrait viewports on mobile devices, End turn is the only turn wording visible.
     2. When a board mounted on a game already finished (for instance, returning to the match route after watching a replay, or reloading a page on a finished match), the Victory or Defeat panel stayed transparent and ignored pointers for 3.8 seconds (`resultRevealMs()`, 600 ms lethal lead + 3200 ms result sequence). The effects layer (`apps/web/src/fx/FxLayer.tsx`) only plays lethal and Victory/Defeat cues when a result arrives while mounted (`previousResult === null && view.result !== null`), so the panel was waiting out an animation that never played, preventing players from clicking Rematch immediately.

     **What holds now.**
     - When a game has a result (`view.result !== null`), End turn carries `data-turn-state="over"`, displays the label `t("Game over")`, and remains disabled (`disabled` and `aria-disabled="true"`). This holds regardless of whether the game was won, lost, or drawn, and whether it ended on the viewer's turn or the opponent's. The button shares the sunken, desaturated styling of the `enemy` state in `apps/web/src/game/board.css`.
     - The opponent's live turn (`view.result === null && view.active !== view.viewer`) continues to display "Enemy turn" with `data-turn-state="enemy"`.
     - `Game` tracks whether the board mounted on an in-progress game (`shown.result === null`). Only when the result arrived on the mounted board (transition from `result === null` to `result !== null`) does `GameResult` wait out `resultRevealMs()`; if the board mounted on an already-finished game, the reveal delay is 0, displaying the result panel with `data-revealed="true"` immediately. Reduced motion and disabled effects continue to reveal with 0 delay ([[R200]], [[§10.10]]).

     **Rejected.**
     - Hiding the End turn button once the game is over: this would shift the layout of the rail right when the result lands.
     - Retaining the 3.8-second delay when mounting on an already finished game: nothing plays in the effects layer on that mount, so the delay served only to block player input (such as Rematch).

## 6. Risks

- **Animation timing divergence between FxLayer and Result**: `FxLayer` plays the lethal lead and Victory/Defeat cues only on the condition `previousResult === null && view.result !== null`. If `GameResult` used a different condition or waited on initial mount, the panel would either appear over a running animation or stay invisible with nothing playing. By coupling `arrived` strictly to whether the board mounted on an in-progress game (`shown.result === null`), `GameResult` waits if and only if `FxLayer` triggers its cues.
- **Layout shift**: Hiding the End turn button upon game over was rejected because it would shift the rail layout right when the result arrives. Keeping the button visible in its `"over"` state with the same physical dimensions and sunken styling prevents layout jumping.
- **Rule 7 (Presentation purity)**: Neither End turn wording nor result reveal timing affects game state or sends illegal intents; legality remains governed by engine views.
