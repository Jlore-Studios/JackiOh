# Plan (opus, strong)

## Goal

A match socket closed with 4401 ("sign in first") becomes final only for the token that got it. A different token opens exactly one more socket: in 1v1 that is the next `setToken`; in co-op it is the gate's token, which now reaches `useDuosMatch` through `DuosRoute`. The refused token opens nothing. A 4401 on the new socket is final for that socket's token, and 4403 and 4404 stay final, so nothing loops. The rule is ruling R1115000 (the first number of issue #1115's block), proven by tests named after it. The existing "does not retry a refusal" tests stay untouched.
