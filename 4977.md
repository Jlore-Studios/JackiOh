# Plan: Issue #4977 — Counted game's result reloads card proficiency

## Goal

When an online counted game finishes, its paid result (`match.economy`) triggers `reloadOwnProficiency()`, which queues a reload on the active account's shared proficiency sync handle through `requestQueue`. The updated card level and play count appear immediately in the Collection without requiring a page reload, and newly unlocked stamps can be equipped right away. With no active account, the call is a no-op, and reloads requested while a stamp pick is in flight are ordered to resolve after the pick.

## Risks

- **Race between in-flight stamp pick and game result reload**: Mitigated by reusing `requestQueue()` in `startProficiencyAccountSync`. The existing `enqueue` mechanism ensures requests run in serial sequence without clobbering each other, so the reload runs after the pick and receives the latest account state.
- **Excessive network requests from other game modes**: Calling `reloadOwnProficiency()` directly in `match.tsx`'s `paid` effect ensures only server-recorded matches that count plays trigger the read. Solitary AI practice games, co-op games, and news claims do not call this reload.
- **Client deciding rules or unlocks (CLAUDE.md rule 7)**: The client does not calculate proficiency gains or unlock status locally; it merely requests a fresh snapshot from `GET /api/proficiency` and presents the server's truth.

## 6. Risks

- **Race between in-flight stamp pick and game result reload**: Mitigated by reusing `requestQueue()` in `startProficiencyAccountSync`. The existing `enqueue` mechanism ensures requests run in serial sequence without clobbering each other, so the reload runs after the pick and receives the latest account state.
- **Excessive network requests from other game modes**: Calling `reloadOwnProficiency()` directly in `match.tsx`'s `paid` effect ensures only server-recorded matches that count plays trigger the read. Solitary AI practice games, co-op games, and news claims do not call this reload.
- **Client deciding rules or unlocks (CLAUDE.md rule 7)**: The client does not calculate proficiency gains or unlock status locally; it merely requests a fresh snapshot from `GET /api/proficiency` and presents the server's truth.
