## Goal

The Supabase provider in `crates/server/src/auth.rs` makes one provider call per key at a time. Concurrent R194 session checks for one session of one user share one `GET /auth/v1/user` call and its answer, and concurrent admin lookups for one user id share one `GET /admin/users/{id}`. ## Risks

- **A stale flight.** An entry left after its call lands would serve an old answer forever. `LeaveFlight` removes it in the same poll as `set_value`. Keep step 3 verbatim.
- **Locks.** No `std::sync::MutexGuard` may live across an `.await`. Clippy's `await_holding_lock` catches it. Keep the lock order key_set then inflight, as today.
- **Security.** Keys include `sub`, an ended answer is never memoed, and the const assert caps the outage memo. Worst case, an ended session is refused 15 s after the provider recovers, inside R194's 30 s.
- **The paused clock with real sockets** (`SupabaseAuthInput.now`'s doc). Only test 5 pauses, and only after its warm-up.
- **The client.** The new constants are not exported, and the client's B25 still reads `AUTH_PROVIDER_TIMEOUT_SECONDS`, whose value stays the same.
