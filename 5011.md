# Plan (sonnet, medium)

## Goal

When the Assault page is opened again after it was left, the store re-reads the attempt, held report and records from the device instead of serving its in-memory `core`. This is the same as `apps/web/src/dungeon/store.ts` after #4914 (commit `1769dbf58b`). The criteria:

- **Stale cache:** a write made while nothing was subscribed is picked up on the next mount.
- **Start and retry:** starting or retrying from the reopened page builds on the other tab's attempts, checkpoints and held report.
- **Finished attempt:** a finished attempt this tab still shows (`terminal(state)`) is kept across the reload.
- **Tests:** the assault store tests pass and the dungeon store tests pass unchanged.

No spec note, ruling or patch fragment is needed. #4914 touched none, and this is a web-only fix.
