# Plan (sonnet, medium)

## Goal

A crash in a player's browser reaches the owners. The client sends one small report to a new `POST /api/client-errors` for each of the three triggers: an error `RouteErrorBoundary` catches, an uncaught `error` event and an `unhandledrejection`. At most 3 reports go out per page load. Lazy-chunk load failures and errors with no file of ours in the stack send nothing. The report holds the message, a trimmed stack, the route as a pattern and the catalog version. It never holds a hand, a board, a query string, a token, an address or an email.

The server size-caps the body, rate-limits it per address and per account, and raises `log_alert("client.error", …)`. `alerts.rs` already files the public issue (event, site, build, time) and sends the email with the details, under `ALERT_WINDOW_MS` and `ALERT_EMAILS_PER_DAY`.

No ruling is needed. Like `alerts.rs` and `bug_reports.rs`, this is operational, "not in SPEC, no R-row".
