# Plan (opus, strong)

## Goal

`SwingReader::step` (`crates/ai/src/swing_turns.rs`) holds a started turn's row back while the step's `after` state is still inside that turn's start, and writes it at the first later step that leaves the start, so the row reads the state after the draw and the start-of-turn triggers (R4552000). The rest stays as it is: a turn that begins and ends inside one step is read off the state that step left (R345, R1183002), and a turn that begins on a finished game gets no row. A game that ends while the start is still under way also gets no row for that turn. The issue's reproduction passes in full: the Spikey Pillow is in `acting` with `maker: Some("core-065")`, and `eval` is the evaluation of the resolved state.

A second cause, found by running the reproduction: the answer step emits no `HookResolving` (`crates/engine/src/prompts.rs:1056`, a continued run is not marked), and the Pillow's `Summoned` has `source_id: None`, so with the hold alone the maker is `None`. An answer step must start `resolving` from the prompt it answers (`before.pending.resume.def_id`, `"core-065"` for the Mask). A scratch copy with both changes passed all four tests below.
