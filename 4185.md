# Plan (muse-spark-1.3-contributor, medium)

## Goal

When a screen-reader user moves a sound volume slider, it announces the value as a percentage (e.g. `80%`), and while `Mute all sound` is on, all five volume sliders are disabled and visibly dimmed so it is clear they do nothing until sound returns. This touches only `AudioControls` presentation: no engine, card, audio-playback, or settings-store behavior changes.

## Files to touch

| Path | New / change | What changes |
|---|---|---|
| `apps/web/src/audio/AudioControls.tsx` | change | In the `VOLUMES.map` range `<input>`, add `aria-valuetext` and `disabled`; nothing else |
| `apps/web/src/audio/audio.css` | change | Add disabled styling for volume rows and range inputs at the end, near `.audio-controls__row input[type="range"]` |
| `apps/web/src/audio/AudioControls.test.tsx` | change | Add tests for `aria-valuetext` percentages and mute/unmute disabled state |

Do not touch: `.github/`, `.harness/`, `.squishy/`, `bot/`, `crates/engine`, `crates/cards`, `crates/ai`, `crates/server`, the audio engine/playback (`engine.ts`, `director.ts`, `cues.ts`), the settings store (`settings.ts`), or any other web file. Governing spec: SPEC §10.11 ("Settings", `spec/10-engine-guide.md` "Settings" paragraph: volumes, mute, voice on/off) and `docs/polish/2-sound.md` B30, B54. No new ruling note: percentage announcements and disabling sliders while muted are pure UI feedback, not an undecided rules question, so no `spec/rulings/R*.md`, no `spec/pending/` paragraph, and no `r<n>`/`R<n>` test name is required.

## Steps

1. `apps/web/src/audio/AudioControls.tsx`, in `AudioControls`'s `VOLUMES.map` volume `<input type="range">` (the block starting `<input id={inputId} type="range"`): add exactly two props, copying the `SpeedSlider` pattern in `apps/web/src/settings/controls.tsx` (which sets `aria-valuetext={speedLabel(props.speed)}`):
   - `aria-valuetext={\`${value}%\`}` (`` value `` is the already-computed `percent(settings, key)` in scope, so the default master slider exposes `'80%'`).
   - `disabled={settings.muted}` (reads the same `settings` object the mute checkbox already reads; no new state, no new import).
   - Leave the adjacent `<output ... aria-hidden="true">{value}%</output>` exactly as is; it stays the sighted readout while `aria-valuetext` becomes the announced value.
2. `apps/web/src/audio/audio.css`, immediately after the existing `.audio-controls__row input[type="range"]` rule: add exactly:
   ```css
   .audio-controls__row input[type="range"]:disabled {
     opacity: 0.5;
     cursor: not-allowed;
   }
   .audio-controls__row:has(input[type="range"]:disabled) {
     opacity: 0.5;
   }
   ```
   - Do not rename or restyle any existing rule; do not add a modifier class in the `.tsx` (the `:has` selector dims the whole row, label and readout included, from the `disabled` attribute alone).
3. `apps/web/src/audio/AudioControls.test.tsx`, append one new `describe` block (after the `B54` block, before the `R631` block), following the file's existing `screen.getByTestId` style:
   - `it("announces each volume slider as a percentage")`: render `<AudioControls />` with default settings, then for each of `audio-master`, `audio-sfx`, `audio-crowd`, `audio-voice`, `audio-music`, assert `slider.getAttribute("aria-valuetext")` equals `` `${slider.value}%` `` (e.g. master `'80%'`); then `writeAudioSettings({ master: 0.25 })` (or `fireEvent.change` on `audio-master` to `"25"`) and assert that slider's `aria-valuetext` is `'25%'`.
   - `it("disables all five volume sliders while muted, and re-enables on unmute")`: render `<AudioControls />`, assert all five sliders have `disabled === false`; set mute via `fireEvent.click(screen.getByTestId("audio-mute"))` and assert all five have `disabled === true`; click the mute checkbox again and assert all five have `disabled === false`. Prefer clicking the real checkbox over calling `writeAudioSettings` directly so the test proves the UI path.

## Tests

- `apps/web/src/audio/AudioControls.test.tsx`:
  - `announces each volume slider as a percentage` — asserts each of the five `data-testid` sliders exposes `aria-valuetext` equal to its displayed percent, and that changing a value updates it (fails without Step 1's `aria-valuetext`).
  - `disables all five volume sliders while muted, and re-enables on unmute` — asserts `disabled` is false by default, true for all five after muting, false again after unmuting (fails without Step 1's `disabled`).
- Commands:
  - `pnpm --dir apps/web test src/audio/AudioControls.test.tsx`
  - `pnpm --dir apps/web typecheck`

## Done when

- [ ] Each volume range input (`audio-master`, `audio-sfx`, `audio-crowd`, `audio-voice`, `audio-music`) exposes `aria-valuetext` of `${value}%`.
- [ ] With `settings.muted` true, all five sliders have `disabled === true`; with false, all five have `disabled === false`.
- [ ] Disabled sliders and their rows render dimmed/inactive via `audio.css` (`opacity: 0.5; cursor: not-allowed;` or equivalent).
