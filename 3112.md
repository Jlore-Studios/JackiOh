## Goal

The learned evaluation's features gain sparse keys for **what a card is**:
- its running face's type, keywords, and printed attack and health;
- its printed cost and its tags;
- whether it is Radiant.

These keys sit beside the id keys and exist only for cards the seat can name in `redact(state, seat)` (R185). This layout is `FEATURES_VERSION` 3. A test shows that a card with no id row still moves a network through these keys.
