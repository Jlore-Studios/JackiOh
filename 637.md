# Plan (opus, strong)

## Goal

Online matches leave play telemetry for the ladder bots (#636). Three new server-only tables hold it: `action_timings`, `emote_events` and `match_signals`, keyed by match id and seat, with no profile id and no client grant. The match actor records think times, emotes and end-of-game signals in memory. It writes them in one batch right after the result commits, and a failed write is logged and never costs the result.

Four more pieces come with it:

- `jackioh-server timing-backfill` folds the `match_actions` logs still held into the same `action_timings` rows the live path writes.
- `jackioh-server timing-fit` prints log-normal parameters per bucket, leaving out `pilot = 'ai'` rows.
- The rows are covered by the retention purge and by account deletion.
- Ruling R1442 records the decisions, and the privacy policy names the telemetry.

## Risks

- **A rebuilt actor now replays its log a second time.** The replay must use the same `dealt` as the fold, and skip a refused row exactly as `fold` does, or its rows describe another game. The cost is CPU on rebuilds only.
- **Tier read at Arm.** The new store read at Arm, and `evaluate` on fixture cards, could disturb existing actor tests. Log at warn only, and run the whole suite.
- **Who reads the state.** `legal_actions` and `evaluate` read the true state on the server only. Nothing new reaches a socket (rule 7).
- **Timestamps differ.** Postgres stamps `match_actions.at` with its own clock (pg.rs "KNOWN DIVERGENCES"), so backfilled think times run commit to commit. Say so in R1442.
- **Old purge signature.** Grep `purge_expired_rows` across `crates/server`, so that no call with two arguments survives.
- **`timing-fit` loads every timing row into memory.** That is fine at today's scale. Say so in the module doc.

## Open questions

1. Retention is 365 days, to leave room for fits. The alternative was 90 days, like the log. A person may prefer 90 or 180.
2. Backfilled rows leave `clock_left_ms` and `rank_bucket` null. The rejected alternatives were replaying the clock on paused tokio time, and using players' current tiers.
3. Emotes sent after the result ("GG") are not recorded, because the rows are written with the result.
4. Account deletion deletes the player's seats' rows. The rejected alternative was keeping them unlinked, as `game_records` are kept.
5. `rank_bucket` is the ladder tier at match start, unranked rooms included. Unranked matches get no "unranked" bucket.
