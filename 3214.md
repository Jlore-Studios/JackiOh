# Plan (opus, strong)

## Goal

Each signed-in tab holds one WebSocket at `/ws/social`. The server pushes three kinds of frame over it:
- `social`: the caller's challenges and unread counts, exactly the body `GET /api/social` returns.
- `chat`: a nudge when a chat message is sent.
- `friends`: a nudge when the caller's friends list changes.

While the socket is up, the tab sends no social poll and no chat poll. The polls start again when the socket drops, and older clients keep polling.

The socket signs in the way `/ws/match` does: R1379000, R2478000 and §9.4's gate. Its session is checked again every R194 window. It is capped per account, and it has a per-address count of its own. The work is done when there are server tests, client tests, ruling R3214000, and the route listed in the server README.
