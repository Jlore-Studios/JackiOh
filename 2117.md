# Plan (opus, strong)

## Goal

Every move from one menu screen to another runs inside `document.startViewTransition`, using the browser's default root cross-fade. Inside the callback, `flushSync` renders the new screen at once so the browser captures it. That covers `navigate()` and the browser's Back/Forward (`popstate`), and each move starts exactly one transition. These start no transition and happen as they do today:
- a move into or out of a board's route;
- a move off a board on screen (a replay playing in place);
- any move under Reduce motion (the system's, the settings panel's or the effects setting's);
- any move in a browser without the API.

A move that R1754000's leave guard holds starts nothing until it is let go. SPEC §10 does not decide any of this, so it becomes ruling R2117000, proven by a vitest file with a stubbed `startViewTransition`.
