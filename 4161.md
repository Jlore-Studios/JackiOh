# Plan (sonnet, medium)

## Goal

When a pull request changes a deckable card, `play_changed_cards` plays a second, bounded rotation after the existing changed-cards wave. In it every game is a run-start game: each changed card is forced into both decks and its forced indices are pinned Radiant through `deckMarks`. The rotation goes through the same checks as the gate, the summary and `--json` name it, and a failing seed prints a `reproduce:` line that replays the identical game. With no deckable changed card there are no extra games and a line says so. `--from`, `--handicap`, `--cards`, `--json` and `--regress` runs behave as before.

## Risks

- **Determinism and replay.** Marks are overlaid after `run_start_inputs`, so no existing stream moves. `GameSetup` carries the pin, so `fold_args` and the checkpoint rebuild identical options. The new `radiant` field is 0 everywhere else, so non-Radiant games are unchanged.
- **Marked indices.** They are valid only because forced cards are placed first and `run_deck_size` keeps decks ≥ the forced count. `force_into` dedups, and `Forcing::from_changed` and `resolve_force` already dedupe the card list. `FORCED_SET_CARDS_PER_SEED` is 10 and equals `RUN_STARTER_SIZE`, so the minimum run deck fits.
- **Radiant is not guaranteed to resolve.** The random policy may never play a given card, so "never resolved Radiant" is only reported and never fails the gate. Making it fail would be flaky, so I rejected that.
- **CI time.** At most 30 extra seeds, about 7 seconds; run-start decks can be up to `RUN_DECK_MAX` cards, so check the printed seconds once.
- **Rejected alternative.** Forcing Radiant through a separate corpus or a new engine option, because the existing `deckMarks` path is enough and keeps the change in one tool module.

None. One judgement call: the replay flag is a new `fuzz --radiant`, which requires `--cards`. A `reproduce:` line can only replay a game from CLI arguments, and a Radiant-rotation game is a forced `Run` start that `--from N --cards …` cannot draw on its own.
