# Plan (opus, strong)

## Goal

When the restart drain (`Registry::stop_all`, which runs on every deploy) stops a live 1v1 match, the actor stores one checkpoint for it. The write is guarded: it lands only while the match is live and its log holds the row the checkpoint follows. The checkpoint holds:
- that row's seq and nonce;
- the catalog version, the build's rules fingerprint and a checkpoint version;
- a body: the engine state, the R1442 telemetry recorder and the R639000 bot turns;
- an FNV integrity hash.

`Registry::rebuild` starts all three of its folds from a checkpoint that passes every check, and folds only the rows after it. If any check fails, it folds the whole log as today and logs only the reason. Finishing a match deletes its checkpoint. The log stays whole, and replays (`api/replays.rs`, R768) never read a checkpoint.

**Departures, made for the owner's "savings should far outweigh the cost":**
1. **Written at the drain, not every N actions.** Measured on a release build over 40 real-card games:
   - a fold costs 0.39 ms per action;
   - the telemetry replay costs 0.50 ms per action;
   - a checkpoint is about 75 KB, ~0.3 ms to serialize and hash, plus one write.

   At a 1% rebuild rate, a write every 32 actions costs about 4× what it saves. A drain write is read by the very next boot.
2. **Unlike muse's plan:**
   - all three folds resume, not just the state's;
   - finishing deletes the row, so there is one row per live match and the purge is unchanged.

## Risks

- **Rules drift.** `RULES_FINGERPRINT` refuses a checkpoint after any engine or card change. A server change to what a fold gives needs a `MATCH_CHECKPOINT_VERSION` bump.
- **Hidden information.** The table is server-only (RLS on, no grant, listed in both SQL arrays). Sockets still get only `view_for`, and a refusal logs only its reason.
- **Nonces, sequence and clocks.** These still come from the full log and the match row, and the equality test covers them.
- **Drain bound.** The writes run concurrently inside `SHUTDOWN_DRAIN_SECONDS`. A failed write is only logged.
- **The prefix is not re-folded.** A determinism break inside it is not filed again. A rules change refuses the checkpoint anyway.
- **Telemetry.** Up to the checkpoint it is the live recorder's (real clocks and push times), which is better than a replay's.
- **Docker.** cargo-chef recompiles the workspace crates, so `build.rs` runs for every image.
