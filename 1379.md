# Plan (opus, strong)

**Goal.** The 1v1 (`/ws/match`), co-op (`/ws/duos`) and watch (`/ws/watch`) sockets carry the bearer token as an offered WebSocket subprotocol, so no client URL holds it. Each client offers `["jackioh.v1", "jackioh.bearer.<base64url, no padding, of the token's UTF-8>"]`, and the server answers with `jackioh.v1` alone. Missing, malformed and refused credentials keep today's refusal (R148's `forbidden` frame, close 4401, "sign in first"), and a renewed token reconnects (R194, R1115000). Server and client tests cover success, refusal and reconnect for all three socket types, under a new ruling R1379000.

Decisions the issue left open:
- **The subprotocol, not an HTTPS ticket.** Rejected: the ticket, since there is no proxy in the way (`vercel.json`'s CSP sends the sockets straight to Render).
- **The token is always base64url-encoded.** Rejected: the raw token, which a token format with a character outside an HTTP token would break.
- **The server still reads `?token=` when an upgrade offers no `jackioh.bearer.` entry.** `docs/deploy-cloudflare.md` §7 requires the server to keep working with the previous day's client. Rejected: dropping it now, which strands every open production tab. A malformed credential never falls back to the query.
