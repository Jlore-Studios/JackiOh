# Plan (opus, strong)

## Goal

When a held backrow zone is being kept for an animated "Animated on your turn" card, its icon's tooltip names that card: "Held for {name} to return". The card is a unit on the same side whose `UnitView.animated.home` is this lane, and the name is the one its card face shows. Any other held zone keeps "Held for a Reborn unit". The new string gets a `zh-CN.json` entry, a new `Zone` unit test covers both wordings, and `i18n.test.ts`, typecheck and eslint pass.

## Files to touch

| Path | Kind | What changes |
|---|---|---|
| `apps/web/src/game/Zone.tsx` | change | new module function `heldFor`; `Zone` reads `CatalogContext` and uses `heldFor` for the held icon's `title` |
| `apps/web/src/i18n/zh-CN.json` | change | one entry, `"Held for {name} to return"` |
| `apps/web/src/game/Zone.test.tsx` | new | the held icon's title, both wordings, both seats |

Do not touch: anything in `crates/` (no engine, view or wire change), `spec/`, `apps/web/src/wire/`, any other web component, CSS, `e2e/`, any `package.json` or config. This is governed by B3.1 rule 6 and R383 (`spec/rulings/R0383.md`: an animated "on your turn" card's backrow zone is held for its return) and R64 (`spec/rulings/R0064.md`: the Reborn hold). There is no new ruling and no spec change.

What the code does, checked:
- `UnitView.animated.home` is the engine's 1-based backrow lane, the same numbering as `Zone`'s `lane` prop. The R383 test in `apps/web/src/cards/cardState.test.tsx` pairs `home: 2` with `reserved.backrow[1]`.
- Homes are only ever backrow zones (`crates/engine/src/zones.rs`, `reserve_home`). Reborn holds are unit zones (`state_check.rs:793`).

2. **`Zone.tsx`, the new function.** Add it after `zoneLabel` and before `export default function Zone`, exactly:

   ```tsx
   /**
    * What a held zone's icon says it waits for. B3.1 rule 6, R383: a backrow zone is held for the
    * animated "Animated on your turn" card on its side that goes back to it (`UnitView.animated.home`),
    * named as its face names it; any other hold is R64's, for a Reborn unit. The card stands on the
    * field, so its name is public (CLAUDE.md rule 7).
    */
   function heldFor(lookup: CardLookup | null, view: PlayerView, side: Side, row: Row, lane: number): string {
     const returning = row === "backrow" ? (sideView(view, side).units.find((unit) => unit?.animated?.home === lane) ?? null) : null;
     const face = returning === null ? null : listedFace(lookup, view, returning);
     return face === null ? t("Held for a Reborn unit") : t("Held for {name} to return", { name: face.name });
   }
   ```

   Both `t(...)` calls must keep a literal first argument, because `i18n.test.ts` reads those literals.

## Risks

- **Hidden information (CLAUDE.md rule 7):** the name comes only from a `UnitView` already on the field, through `listedFace`. `listedFace` returns null for the hidden sentinel, and the tooltip then falls back to the Reborn wording, so nothing hidden can show. Do not look at backrow entries, hands or piles.
- **Rules of hooks:** `useContext` must stay unconditional at the top of `Zone`, never inside the `reserved &&` branch.
- **i18n guard:** a `t()` call whose first argument is not a string literal escapes `i18n.test.ts`'s check. Keep both literals as written in step 2.
- **Rendering cost:** `heldFor` runs only for held zones, because it sits inside the `&&` branch.
- There is no engine, wire, replay or determinism impact, because nothing outside `apps/web` changes.

## Open questions

Decisions I made that the issue left open:
- **The name the tooltip uses.** It is `listedFace(...).name`, the name the card's face shows. That covers Chinese faces (R1301), Glitch and match-made definitions. I rejected `useCardInfo(defId).name`, because it misses the Chinese flag on a card.
- **A card whose control has changed.** If an animated card is stolen, its home stays held on its old side until cleanup (`crates/engine/src/animated.rs`, `return_home`). `animated.home` doesn't say which side the home is on, so the old side's held zone keeps the Reborn wording, as the issue proposes. I rejected matching units on the other seat, because the view can't tell that case apart from a home on that seat's own side. Test 3(c) pins this. If people want different wording there, it needs a side added to `AnimatedView` in the engine, which would be a separate issue.
- **The zone's `aria-label`.** It stays "Reserved zone". The issue changes only the `title`.
