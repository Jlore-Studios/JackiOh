## Risks

- **Hook order.** The effect must sit above the early `return` for `expired`, or React fails with "rendered fewer hooks".
- **Test isolation.** The wallet event is a `window` event, so every test must remove its listener (`onTestFinished`, as in `watchWallet`). The proficiency sync is a module singleton, so `resetProficiencySyncForTests` must run after each test. `afterEach` does not do it, so `watchProficiency` registers it.
- **`announceWallet()` with no token.** It tolerates a missing session (`readSession()?.accessToken`), and the tests are signed in anyway.
- **No sync running.** `reloadOwnProficiency()` sends nothing when no sync runs, so in the real app it is safe on any screen. The tests assert a reload only where `watchProficiency` mounted a sync.
- **`over` versus `view.result`.** The server sets `over` with the result. If a test fixture sets `view.result` but not `over: true`, the effect will not fire, so the `finished()` helper sets both.
- **Stub reads.** A request the stub does not answer (`/api/wallet`, `/api/proficiency`) is unanswered by `serve`, so the announce's wallet read fails quietly (`failed()` in `wallet.ts`). Tests count the event, not the read. If `stubServer` throws on an unknown path, answer `/api/wallet` with `{ status: 200, body: { jlore: 0 } }` in `serve`'s `answer` hook.
