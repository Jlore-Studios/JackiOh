4. Append a step `the floor` after `the scores`, reading `$RUNNER_TEMP/scores.md`. It is a separate step because `the scores` pipes into `tee`, so the floor's exit code must not be lost. Use `shell: bash` or POSIX `sh`; the following is pure awk:
   ```
   - name: the floor
     run: |
       fail=0
       while read -r area floor; do
         case "$area" in "" | "#"*) continue ;; esac
         row=$(grep "^| $area |" "$RUNNER_TEMP/scores.md" || true)
         [ -n "$row" ] || { echo "::warning::$area: no score this run"; continue; }
         score=$(echo "$row" | awk -F'|' '{gsub(/[ %]/, "", $9); print $9}')

       exit $fail
   ```

## Risks

- **Noisy floors.** One shard of each area runs per week, so scores swing with the shard. Set each floor under the lowest shard seen, not under the average, or the weekly run goes red by chance.
- **Row format.** The step parses the markdown table that `scripts/mutants.sh score` prints (`| area | shard | killed | survived | timed out | unviable | left out | score |`). A column change there breaks the awk field number (9).
- **PR runs.** On a pull request, `size=20` samples only 20 mutants of `run` and `cards`. Their scores are not comparable with the weekly floors, so a PR run could fail the floor. If it does, gate only when `github.event_name != 'pull_request'`, by adding `if: github.event_name != 'pull_request'` to the floor step. Step 8's PR-run proof then needs the dispatch route instead.
- **Cancelled runs.** The `report` job runs `if: always()`, so a cancelled run could fail the floor on partial data. The warning path above covers missing areas.
