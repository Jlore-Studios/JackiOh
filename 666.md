# Plan (opus, strong)

## Goal

The match reaper gets a second sweep. Every 30 s it deletes each `public.matches` row with `status = 'open'` whose `ceiling_at` is more than `OPEN_MATCH_REAP_GRACE_SECONDS` (300 s) in the past. That covers three kinds of row: a room nobody joined before it expired, a claimed room whose match never started, and a queue pairing's skeleton whose start failed and whose cleanup failed too. Deleting the row frees the room code, sets both profiles' `current_match_id` and the tickets' `match_id` to null, and so lets both players queue again. An open row younger than the grace is kept, and a live or finished match is never touched. The Postgres store and the fake store behave the same way, which the store contract (both stores) and one API test prove. There is no migration and no constant outside `crates/server/src/config.rs`. The behaviour is recorded as ruling R1450.

## Risks

- **Deleting a row mid-start.** The cutoff is the server clock less 300 s. A claim needs `ceiling_at` to be after the claim time, and a pair is started milliseconds after its claim. A series' game 1 starts or is abandoned within 180 s. Do not shorten the grace below `SERIES_PICK_SECONDS + SERIES_START_GIVE_UP_SECONDS`.
- **Fake and Postgres drift.** The contract runs on both stores. Return the same count (one per room, one per reservation). Never count a reservation that `discard_open` removed. The fake must keep a claimed room whose match exists.
- **`to_timestamp` range.** Never pass `i64::MAX` as `before`; use `now + 86_400_000`.
- **Hidden information and replay.** Unaffected: an open row has no seed, log or actor.
- **Ruling clash.** If another branch lands R1450 first, renumber as `docs/issues-and-patches.md` "Ruling numbers" says.

## Open questions

None block the build. These are the decisions taken, each with the alternative rejected:

- **Inline delete in `pg.rs`, not a new `app.reap_open_matches` SQL function.** The SQL function would need a migration; `matches_discard_open` is the precedent for the inline delete.
- **The 30 s reaper tick, not the hourly purge.** On the reaper tick a locked-out player is freed within about 5.5 minutes rather than up to 65.
- **A count, not the ids.** The fake has no id for an unclaimed room.
- **Rows a series still names are not excluded.** The grace already outlasts the series' timings, as the first risk explains.
- **A ruling, not "no R-row" like the retention purge.** The sweep changes when players are released under §9.5, as R263 and R108 do. A person may drop R1450 and the spec edits if they disagree.
