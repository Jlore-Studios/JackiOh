# Plan (opus, strong)

## Goal

The match reaper gets a second sweep. Every 30 s it deletes each `public.matches` row with `status = 'open'` whose `ceiling_at` is more than `OPEN_MATCH_REAP_GRACE_SECONDS` (300 s) in the past. That covers three kinds of row: a room nobody joined before it expired, a claimed room whose match never started, and a queue pairing's skeleton whose start failed and whose cleanup failed too. Deleting the row frees the room code, sets both profiles' `current_match_id` and the tickets' `match_id` to null, and so lets both players queue again. An open row younger than the grace is kept, and a live or finished match is never touched. The Postgres store and the fake store behave the same way, which the store contract (both stores) and one API test prove. There is no migration and no constant outside `crates/server/src/config.rs`. The behaviour is recorded as ruling R1450.
