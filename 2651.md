## Risks

- **Serialized self-play.** Step 5's two `start_selfplay` calls must both happen before either wait. Otherwise local runs take twice as long.
- **The cross-job contract.** The legs and `rust (classify)` must agree on the layout: `<dir>/head/` and `<dir>/base/` holding `selfplay_file`'s name. Both legs run the head's binary, which also drives the base's `selfplay`, so `SELFPLAY_GAMES` and `SELFPLAY_SEED` always match. A missing file is an error, never "the same".
- **Determinism.** The games, their seeds and the compared fields are unchanged (selfplay's lines are byte-identical whatever the thread count, R1006001), so the labels match today's.
- **Spawning the test binary.** Tests must never take the played path; see the warning under Tests.
- **A remaining slow case, not fixed here.** Forced games cost about 23 s per changed script, so a refactor of about 10 scripts plus engine code can still pass 5 minutes in `rust (classify)`. Say so in the report as a follow-up.
