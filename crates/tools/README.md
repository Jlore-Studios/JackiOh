# `jackioh-tools`

The `jackioh` binary: every development and CI tool that is not the server. Run it as
`cargo jackioh <command>` (`.cargo/config.toml`'s alias for `cargo run --release -p jackioh-tools --`),
or build it once with `cargo build --release -p jackioh-tools` and run `target/release/jackioh`, as
CI does. It reads and writes files under the repository it was built from (`--root` on `spec`
overrides that).

Exit status: 0 on success, 1 on a failed check, 2 on bad usage. Output goes to stdout; nothing is
interactive. Tooling may read the clock and the disk; the crates it drives stay pure (CLAUDE.md
rule 4), and it hands them the clock as a callback where they need one.

| `fuzz [--from N] [--seeds N] [--handicap]`, `fuzz --duos [--from N] [--seeds N]` | `fuzz.rs`, `duos_fuzz.rs` | random-policy games (spec §10.7) from every non-token card of every set, the I1–I4 invariants checked each step and every game folded back to its live hash; seeds 1–1,000 by default, `--handicap` rotates one seat through Medium and Hard. CI plays `--seeds 200`, the daily run 10,000 of each. `--duos`: random-policy Duos co-op games (§13, #936 B25), the 1v1 games' I1–I7 monitor run over each duel's events each step (I6 every `I6_GATE_STRIDE`-th state and the last, #1074), with `duos_view_for`'s seat redaction and each team's pool bound (§13.4, §13.6), each game ended inside its bound and `duos_fold`ed back to its live `duos_hash`; 200 seeds by default |
| `replay` | `replay.rs` | reads `{seed, decks, log, handicaps?, dealt?, lastBoards?, glitchBoards?}` on stdin and prints `{"hash", "errors"}`: e2e specs 01 and 13 check the browser's hash with it |
| `trace [matchup] [n] [full]` | `trace.rs` | one AI gate game, turn by turn |

Nothing the seat cannot see is printed (R185). The decision is from the stream a gate match starts the seat's AI on, so it repeats exactly; a tier is the handicaps the input carries, so there is no `--tier` |
| `catalog check` | `catalog.rs` | `crates/cards/catalog.json`'s shape and census, set by set (spec §5, §6.1, §7, §8): 370 cards and 80 tokens, the rarity counts, the tag counts, the patch v0.2.0 fields |
| `catalog loc <script path>` | `catalog.rs` | a new card script's `loc` (its non-blank, non-comment, non-`use` lines above `#[cfg(test)]`); prints, writes nothing |

| `patches check`, `patches ship` | `patches.rs` | every catalog change claimed by exactly one fragment, every fragment and shipped patch holding a player note players can read (R724001), and every older shipped version carried for replays, its snapshot's cards in order, each with a script (R767000); after a merge, promote the fragments in ship order with their notes and bump the catalog version |

| `sweep [ids…] [--json] [--pass2 files] [--report files]` | `sweep.rs` | R186's two-pass shadow-ban sweep; a decision its clock finds slower than `AI_SWEEP.decision_ms` is timed again with `gate.rs`'s yardstick and decision timer and counts as a timeout only if still slow, each row showing both counts (R977000); prints the `SHADOW_BAN` and `SHADOW_WATCH` rows to copy into `crates/ai/src/shadow_ban.rs` |
| `stats [--games N] [--from N] [--patch v] [--series s] [--out file]` | `stats.rs` | R378's development run for the card statistics |
| `stats report <file>… [--source live\|dev\|all] [--mode m] [--patch v] [--pilot p] [--card id] [--json]` | `stats.rs` | R377's card win rates over record files (one `GameRecord` per line: `stats --out`, `jackioh-server stats-export`, the training lanes' `~/training-out/<lane>/*.jsonl`) with no database; `stats-cards`' flags and defaults (live games unless `--source` says otherwise, their human seats unless `--pilot` says otherwise, R1451), its table or its `--json`; a line that is not a record is an error naming its file and line. The figures `analysis/` computes over the same files are held to these |
| `stats fit-dealt <file>…` | `dealt_fit.rs` | `DEALT_Q`'s refit over arena record files (`~/training-out/unban/*.jsonl`); only `self-vs-bin-…` games count (the candidate at full skill against a parent build, its seat read off the record id), each id once. `DEALT_Q_PRIOR` is the candidate's share of games won; each card's q is `(w + 60 × prior) / (n + 60)` over the candidate's decks that held it. It prints the prior line and the rows by id, to paste into `crates/ai/src/shadow_ban.rs` unchanged, plus an advisory `UNBANNED_PREFER` table (its entries, and the cards without a row whose refit beats the prior). | `golden check`, `golden bless` | `golden.rs` | replay `crates/engine/tests/golden/games.jsonl` (the traces recorded from the TypeScript engine) and the hotseat fixture; `bless` rewrites them, only after an intended rules change |
| `golden record --seeds A..B [--force ids] --out <path>` | `golden.rs` | the golden seeds A..=B (each within 1–240) played with `bless`'s recorder into a file of its own, `games.jsonl` untouched; each `--force` card goes into both decks (a deck keeps its size), a token through the smallest-id deck card whose `refs` name it (R279); a token no card names, a card of a set that has not shipped (R1420) and an unknown id are refused. | `luau surface [--json] [--card <id>]…` | `luau/surface.rs` | v0.4.0 groundwork (#560): the engine API every card script calls, card by card. For each script (above its `#[cfg(test)]`), per face, the `Script` hooks it sets, whether Radiant reuses base (`whole`, `spread`, `no`), the effect verbs, the read helpers and the `query.rs` pools it calls, and the names it cannot classify, with #442's L14 cards (`STAY_IN_RUST`) marked; then each distinct hook, verb, reader and pool with how many cards use it and which, L14 counted apart. Markdown tables, or `--json`; `--card` (repeatable) narrows it. It reads source text, not Rust, and writes nothing: a card it cannot read is listed with its reason, never dropped |
| `spec check`, `spec index` | `spec.rs` | the spec graph's structural checks (CLAUDE.md rule 3), and `spec/INDEX.md` rewritten from the ruling notes |
| `arena --a … --b … (--games N --seed s [--paired] \| --set improve-dev [--games N]) [--out dir] [--a-skill s --b-skill s]` | `arena.rs` | two agents (`self`, `random`, `bin:<path>`) play N games; one game record per line. R850000: `--paired` plays each deal twice with the seats swapped and adds the paired edge and its 95% interval to the tally (`deals`, `edge`, `edgeLow`, `edgeHigh`); `--set improve-dev` is the improve lane's fixed dev set, paired, 400 games or more (400 by default), and a base naming a gate's seeds (`improve`, `unban`, or either followed by `:`) is refused (R850001). How the skill-to-Elo curve is measured with it: `crates/server/README.md`, "Skill to Elo" |
| `selfplay --games N [--from K] --seed <base> --out <dir>` | `selfplay.rs` | #1006: the learned evaluation's game logs. This build's AI plays itself at `AI_GATE_BUDGET` on games `K..K+N−1` (seed `<base>:<n>`) of a development run's deals (R258), through the arena's play path, on rayon's threads; one JSON line per game in game order (seed, decks, log, final hash, result, turns, catalog version, commit) to `<dir>/selfplay-<base>-<K>-<last>.jsonl`, byte-identical whatever the thread count (R1006001). A base naming a training gate's hold-out deals or the dev set (`improve-dev`) is refused (R1006002) |
| `positions <logs>… --out <file> [--every turn\|decision\|reply]` | `positions.rs` | #1006: `selfplay` files folded into training rows. Each game is folded under the catalog it was played on and dropped, and counted, when it no longer reaches its hash, has no result or names a catalog this build does not carry (R1006003); then one row per seat per turn (its turn's first main-phase decision, the default) or per decision, or (`reply`) after each turn's end the opponent's reply as the search simulates it (R1006006): the seat's features (`features_of`), `FEATURES_VERSION`, the hand eval with the reply's swing rule and the outcome for the seat (R1006004). A header line names the dense features. Prints the counts |

| `promote --lane improve\|unban --parent-bin <path> [--dry-run] [--verify]` | `promote.rs` | a training lane's promotion gate (`training/README.md`): improve's 220 of 400 games on 200 hold-out deals, each played twice with the seats swapped, which only the committed AI reads (R850000, R850001); unban's 60 of 100 and strictly fewer shadow bans (R732001) |

```
cargo jackioh --help
cargo jackioh catalog check && cargo jackioh patches check && cargo jackioh spec check
cargo jackioh fuzz --seeds 200
cargo jackioh fuzz --from 700 --seeds 1        # replay the one seed a failure names
cargo jackioh fuzz --duos --seeds 200          # Duos co-op games (#936 B25)
cargo jackioh golden check
cargo test -p jackioh-tools                    # the tools' own tests
```

`spec check` holds six rules: every ruling note's `id` matches its file name and is unique; every
`proven_in` path exists and holds a proof (a Rust `fn` or `mod` whose name has the `_`-delimited token
`r<n>`, a TypeScript `it(`, `test(` or `describe(` whose title has `R<n>` as a word, or an SQL
script's `\echo '### R<n>: … ###'` heading); every `r<n>` test token and every `R<n>` cited in
`crates/`, `apps/web/src/` and `e2e/` has a note; every `[[…]]` link in `spec/` resolves; every note's
`title` and `cards` are filled in; `spec/INDEX.md` is what `spec index` writes from the notes. It reads
ids, file names and test names, never wording.
