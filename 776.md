# Plan (opus, strong)

## Goal

When the log write of a clock's server action fails (a turn, prompt or mulligan `timeout`, `disconnectExpired`, `ceilingReached`), the clock runs out again `MATCH_SERVER_ACTION_RETRY_MS` later. This repeats until the row lands, the match ends or the actor stops, and one expiry is never logged twice. When the store finds that a row already holds the seq the actor is about to write, it raises a new `StoreError::SeqClash`. The actor then lets go as R1437's `let_go_unrecorded` does, so the next socket rebuilds it from the log. The fake store answers a repeated (nonce, seq) the way Postgres does, a contract case proves both stores agree, and ruling R776000 records all of it.

## Risks

- **Retry loops.** At 0 ms a retry would spin in a tight loop; 1 s matches `BOT_WRITE_RETRY_MS`. Each failure logs `match.append.failed` once.
- **A second copy of an expiry.** This is guarded by the clock's one timer per countdown and by the guards in step 3. Do not add an actor-side timer.
- **Replay.** Nothing changes for rows that land. The nonce is still `srv-<kind>-<next_seq>`, so a retried write that had committed is answered by the store and folds the same.
- **A pre-existing race.** If a player reattaches between the grace timer firing and its `Expire` task running, the first try already forfeits them. A retry does the same, and an `Attach` after the failure cancels the retry.
- **Registry.** `forget` removes whatever actor is mapped, hence the `stopped` guard in `let_go_diverged`.

## Open questions

None block the build. Decisions taken, each with the alternative I rejected:
1. The retry lives in the clock. I rejected an actor timer that re-enqueues the expiry: it would forfeit a player who had come back, and it could double a turn expiry the clock re-fires itself.
2. Only clock actions are retried. An emote's `srv-emote-` action and a client's action are not; the client already gets `internal` with "try again".
3. A retried expiry derives its action again from the current state instead of replaying the old body, so a stale timeout is never logged.
4. The fake does not copy Postgres's refusal of a seq gap. That is out of scope, and some tests may write gapped rows.
