## Risks

- **Import cycle.** `marks.ts` imports `cardState.ts`, so `cardState.ts` must never import `marks.ts`. The disc colours live in `CardStates.tsx`.
- **Palette ratchet.** `palette.test.ts` compares each stylesheet's colour-literal count exactly. Any literal in `cardstate.css`, `black` included, fails it.
- **Hidden information (rule 7).** The count comes only from the face's keywords, which are the view's. The opponent's hand of backs (`card === null`) carries nothing.
- **Printed versus view count.** Don't read `card.keywords` alone: the view omits it when the keywords equal the printed ones, which would miss a printed Temporary that has never counted down (Fortify Mind).
- **Revealed hands.** The opponent's hand revealed at game end (R434) is face up with `inHandOf` set, so it wears the aura and badge too. Its view may list no keywords, and then shows the printed count, which is the view's statement.
- **Small faces.** A small hand face shows two badges before folding; placing Temporary right after Brittle keeps it visible.
- **Other faces.** The drag ghost (`DragLayer`), hand hints and prompts build faces without `inHand`, so they show no badge. That is intended: the issue scopes this to `Card.tsx` with `inHandOf` set.
- **Spec check.** No new test title holds an R-id, so `spec check` expects nothing new.

## Open questions

None needs a person. Decisions made here:

- **Count source:** `face.keywords` rather than `card.keywords`, for the reason in Risks.
- **Hand flag:** "in a hand" travels as `LiveFacts.inHand` → `InPlay.inHand`, so the face model carries the count only there, as the issue asks. I rejected computing the badge in `Card.tsx`, because the badge must come from the face model.
- **Disc colour:** inline variables from the palette constants. I rejected bare hex in `cardstate.css` (it breaks the palette ratchet) and importing `marks.ts` into `cardState.ts` (the cycle).
- **Glyph:** `\u231B\uFE0E`, so it takes the badge's colour like `DORMANT_GLYPH`. It reads as ⌛1, but the text holds U+FE0E, so tests compare against `${TEMPORARY_GLYPH}1`. I rejected a bare `⌛`, which draws as a colour emoji.

## Risks

- **Import cycle.** `marks.ts` imports `cardState.ts`, so `cardState.ts` must never import `marks.ts`. The disc colours live in `CardStates.tsx`.
- **Palette ratchet.** `palette.test.ts` compares each stylesheet's colour-literal count exactly. Any literal in `cardstate.css`, `black` included, fails it.
- **Hidden information (rule 7).** The count comes only from the face's keywords, which are the view's. The opponent's hand of backs (`card === null`) carries nothing.
- **Printed versus view count.** Don't read `card.keywords` alone: the view omits it when the keywords equal the printed ones, which would miss a printed Temporary that has never counted down (Fortify Mind).
- **Revealed hands.** The opponent's hand revealed at game end (R434) is face up with `inHandOf` set, so it wears the aura and badge too. Its view may list no keywords, and then shows the printed count, which is the view's statement.
- **Small faces.** A small hand face shows two badges before folding; placing Temporary right after Brittle keeps it visible.
- **Other faces.** The drag ghost (`DragLayer`), hand hints and prompts build faces without `inHand`, so they show no badge. That is intended: the issue scopes this to `Card.tsx` with `inHandOf` set.
- **Spec check.** No new test title holds an R-id, so `spec check` expects nothing new.

## Open questions

None needs a person. Decisions made here:

- **Count source:** `face.keywords` rather than `card.keywords`, for the reason in Risks.
- **Hand flag:** "in a hand" travels as `LiveFacts.inHand` → `InPlay.inHand`, so the face model carries the count only there, as the issue asks. I rejected computing the badge in `Card.tsx`, because the badge must come from the face model.
- **Disc colour:** inline variables from the palette constants. I rejected bare hex in `cardstate.css` (it breaks the palette ratchet) and importing `marks.ts` into `cardState.ts` (the cycle).
