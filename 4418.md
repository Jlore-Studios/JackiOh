- No hermetic test can fail without this fix: the fake serializes whole transactions, so the race is unobservable under `cargo test` (the issue says the same). The contract test pins the wiring on both stores (it fails if the method is missing or reads the wrong profile); the race itself is closed by the `FOR UPDATE` text, verified by inspection and by CI's Postgres halves.
- Reject the migration alternative (applying the keep inside `app.merge_player_settings`): a new migration file would make this a migration-class change and churn checksum-pinned files for no behavioral gain; the API-layer lock is sufficient because the merge already serializes writers on the profile lock.
- Reject adding `FOR UPDATE` to the existing `player_settings_get`: it would put a write lock on the read-only `GET` route and on `loadout.rs`' seat picks. The separate method keeps the lock exactly where the filter needs it and keeps `round_trips.rs` counts unchanged.

None. Both findings have a settled fix above; the one honest limit (no hermetic race reproduction) is disclosed, not decided.
