## Risks

- Double counting from the live-vs-sweep race: guarded by counting only when the settle UPDATE changes the row; `Already` counts nothing.
- Fake/PG day divergence: both go through `claim_count_day`; the contract test runs on both.
- Day-boundary skew: buckets key on settle/count time (UTC), documented in README; TTL analysis joins on day, not exact time.
- Privacy: counts table and export hold no account, seed, or log data; the log line holds seed + reason only, like `practice.claim.verified`.
- Retention: the `practice_seeds` prune must not touch the counts table; counts accumulate at ~9 rows/day.
