# Plan (muse-spark-1.3-contributor, medium)

## Goal

Give `notify_one` in `crates/server/src/daily/notify.rs` one per-profile async exclusion, shared by the after-move `NotifyQueue` task and the hourly `sweep`, held across decide, send and mark-sent. The second caller for an account waits, re-reads fresh `last_email_at`/`last_push_at`, and decides nothing is due, so a colliding move and sweep send exactly one email and one push per device. `after_move` stays enqueue-and-return. No spec, ruling, migration, or config change.

Never hold the map mutex across `.await`.

Update `notify_one`'s doc comment to state the exclusion and that the waiter re-reads fresh state. Both callers (`start()`'s task and `sweep()`'s holder loop) stay sequential and unchanged.

Build the app with a `held_service(StatusCode::OK)` mail endpoint (gate closed) plus an immediate `fake_service` push endpoint; one push device each for Ada and Bo (added directly via `tx.push_subs_add`, copying `push_answered`'s endpoint shape). Wrap the `daily_game` accept in `answers_at_once` (proves enqueue-and-return). The queue task takes the acceptor and stalls in the mail send; `eventually` wait for 1 mail request, then `tokio::spawn` `sweep`. Sleep ~1s (lets the sweep reach the guard; mail timeout is 10s, so no timeout risk), then assert exactly 2 mail requests total (queue's acceptor mail plus sweep's challenger mail — the sweep did not double-send for the acceptor). Open the gate (`add_permits(1)`), join the sweep, `notifier_idle`, then assert each `to` address appears exactly once, each push endpoint got exactly one request, both `last_*` are set for both profiles, and `swept == {emailed: 1, pushed: 1}`. Pre-fix this fails (3 mails while gated, 2 per acceptor after).

Game 1 (Bo vs Dan, created first) played past the mulligan until Bo holds; `notifier_idle`. Subscribe Ada's device at a `held_service(StatusCode::CREATED)` push URL and Bo's at an immediate `fake_service` one (Dan/Cy: none). Accept game 2 (Cy challenges, Ada accepts) inside `answers_at_once`; the queue takes Ada and stalls in her push send (`eventually` held==1). Spawn `sweep`; sleep ~1s; assert Bo's endpoint has exactly 1 request while Ada's still has exactly 1 and the sweep is still pending. Open the gate, join, `notifier_idle`; assert Ada's endpoint has exactly 1 total, `swept.pushed == 1`, and Bo's `last_push_at` is set. Creation order (`daily_games_running` orders by `created_at, match_id` in both fake and pg stores) puts Bo first, so a sequential sweep reaches him without touching Ada's lock.
