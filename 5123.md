````markdown
   /// R4607000: which deals a rerun plays next, decided as the uncut run decides them. Walks the
   /// batches from `initial_deals`, then `next_batch`'s, and at each boundary counts only the live
   /// forks of the deals up to it, never those of a cut batch past it. `Some(target)` is the
   /// boundary of the first batch the save leaves incomplete (play every deal up to `target` the
   /// save lacks); `None` is a finished save, whose boundary the screen stops at.
   fn save_plan(map: &BTreeMap<i32, DealLine>, extend: bool, initial_deals: i32) -> Option<i32> {
       let mut target = initial_deals;
       loop {
           if !(1..=target).all(|deal| map.contains_key(&deal)) {
               return Some(target);
           }
           let live: usize = map.range(..=target).map(|(_, line)| live_forks(line)).sum();
           let (_, len) = next_batch(target, live, extend, initial_deals)?;
           target += len;
       }
   }
   ```
````

````markdown
## Risks

- **Byte-for-byte tally:** the final tally still reads `map.values()`, and every deal the rerun plays lies in the batch the uncut run plays. - **Decision for the builder to record:** the tally is not trimmed to the deals up to the stop. A save with deals past a stop cannot come from a real run (the batch before it would have stopped the screen), so `tally_from_lines` still reads every saved deal. The alternative is `map.range(..=stop)`; I rejected it as needing a second plan value for a case the file cannot hold.
- **Determinism and purity:** `crates/tools` may read the disk. `save_plan` is pure and reads only the map and `next_batch`. The cost is at most about 20 walk steps over at most 2,000 deals, which is small next to the games.
- **`--save` absent:** `run` never calls `resume_save`, so those screens are untouched.
````
