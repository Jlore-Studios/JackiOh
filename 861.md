## Risks

- **The SIGTERM test signals the whole test process.** This is safe only because `shutdown_signal()` installs tokio's handler synchronously, before `kill` runs, so keep that order. Afterwards tokio keeps the handler, so the test binary ignores SIGTERM for the rest of its run and a CI cancel needs SIGKILL.
- **Grace and replay.** Never close an actor's sockets directly. A plain close counts as a disconnect: it stores each seat's grace, which then runs out during the restart. `MatchActor::stop` sets `stopped` first, so nothing is stored and R744 applies as it does after a crash. The log is untouched, so replay is unaffected.
- **A hung database at shutdown.** `pg::close` waits for checked-out connections, which is why it sits inside the `drain` timeout. Do not move it out.
- **Flapping.** A slow store fails one `/readyz` check (the 2 s bound), and a restart loses no match.
- **Timing in the in-flight test.** The 100 ms settle and the 2 s probe bound leave wide margins. Release the lock as soon as `server.draining` is logged.
- **`rehearse.sh`** runs only in CI's db job. Keep the edits to the lines above and check them with `sh -n`.
