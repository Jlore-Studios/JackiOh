## Risks

- **Flaky socket timing.** Every wait is a retried DOM assertion, or a `cy.window().should` over recorded frames bounded by a named constant. Do not use `cy.wait(ms)`: `support/e2e.ts` throws on it. The aim relay coalesces to one per 100 ms, so each step waits on the DOM before sending the next aim.
- **Emote rate gate (1.5 s).** Step 10's wait for the bubble to vanish (≥ 2 s) is what spaces the two emotes. Step 12's frame check proves the second emote was relayed, so the "no bubble" assertion is not trivially true. Emotes must come from seat two's dealt hand (R1342), or the server refuses them silently.
- **Never send a malformed aim** (a hand *target*). It earns an `error` frame and counts toward the socket's malformed budget. Step 8 uses a hand *source* in the receiver's hand, which parses and is then dropped at relay.

- **Hidden information.** The spec reads only frames the browser's own socket received and `wsPlayer`'s own view. It never asserts through `window.__jackioh` (CLAUDE.md rule 7).
- **A real bug.** If a step fails because the app or server misbehaves (for example, the badge never clears or the stripped fields survive), do not weaken the assertion and do not change production code under this plan. Report the failing step with its output.
