# Plan (sonnet, medium)

## Goal

Two kinds of repeated failure raise an alert, as a stuck 1v1 match already does.

1. **Routes.** A route, or a socket upgrade, that answers an internal error to every request raises `api.route.failing`, with the pattern in the line's data. Its first good answer logs `api.route.recovered`. Any other answer resets the run, a 4xx refusal included.

   - The co-op sweeper counts a pass in which any match would not end as failed, so one wedged match raises `duos.sweeper.failing` once.

## Risks

- **Noise.**
  - The counts and the existing one-notice-an-hour window hold it. All routes share one event, so a database outage that fails every authenticated route is one notice.
  - Any success on the same `(method, pattern)` resets the run.
  - A rarely called route that fails every time it is called does alert, even if the calls are days apart. A reset after a quiet gap was rejected as extra state.
- **Privacy.** `message` is a store error's text and goes only to the email (`alerts.rs` hands the issue no fields). Never put the concrete path, a profile id or an address into the alert's data.
- **Hot path.** `answered` takes one mutex and does one `swap_remove` miss per request, like the limiter. Do not log while holding the lock.

## Risks

- **Noise.**
  - The counts and the existing one-notice-an-hour window hold it. All routes share one event, so a database outage that fails every authenticated route is one notice.
  - Any success on the same `(method, pattern)` resets the run.
  - A rarely called route that fails every time it is called does alert, even if the calls are days apart. A reset after a quiet gap was rejected as extra state.
- **Privacy.** `message` is a store error's text and goes only to the email (`alerts.rs` hands the issue no fields). Never put the concrete path, a profile id or an address into the alert's data.
- **Hot path.** `answered` takes one mutex and does one `swap_remove` miss per request, like the limiter. Do not log while holding the lock.
- **Test seeding.** `pay_coop` and the fold may need richer seeded profiles or options than the bare ones. Copy from `tests/api/duos_again.rs` and `tests/api/duos_rooms.rs`. The unreadable log row must make `registry.actor_for` fail.
- **Signature changes.** `refuse_for`, `sweep` and `end_abandoned` change; grep for every caller before finishing.
